## 1. 评估结论

**方向可取，尚不适合作为“照着做不会错”的全站实施规范。** 原案在材质分层、令牌统一、保留 Jinja 与 React islands、限制玻璃面积、尊重原有配色、保留阅读正文方面有很好的基础。问题集中在三个方面：

1. **规则之间尚未闭合。** 禁止玻璃叠玻璃，却要求玻璃容器里的按钮、chip、输入框再次模糊；限制三个模糊层，却把被透明遮罩覆盖的层排除；要求全部三入口 DOM 相等，却保留 Radix Portal 和 sonner。
2. **视觉方案越过了业务边界。** 批改页的“发布成绩”、逐题手动评分、去 iframe、统一提交状态等，并非更换组件就能成立。现有服务的权限、版本冲突、保存确认、成绩可见性、后台任务和导出状态必须成为设计输入。
3. **覆盖范围与执行顺序不够可靠。** 作业编写没有独立规格；实际 LessonDoc 编辑器、最终材料、简历导出等被过度简化。全站改壳、替换弹层与删除 CSS 早于领域验证，风险集中；Tailwind 4 又与旧浏览器承诺冲突。

建议保留原案的视觉目标，将实施方式调整为：**共同令牌与基础组件 → 一条完整业务链试点 → 按领域迁移 → 依据引用关系退出旧代码**。不要将“类名统一、文件变短、截图相似”当作业务完成。

### 2.1 对 Apple 参考的定位

本项目目标是**符合该美学的 Web 设计系统**。Apple 的材质自适应来自原生平台，CSS模糊并不自动获得同样的亮度分析、折射、可读性与交互能力。本文保留“控制层玻璃、内容层清晰”的方向；登录表单默认使用 Regular/高遮盖表面，Clear 仅在合适媒体背景与对比度实测通过时启用，不因为存在背景图就启用。[Apple 官方讲解](https://developer.apple.com/videos/play/wwdc2025/219/)

“每视图恰好一个主按钮”“四个汉字”“列表超过12项一律扁平”等属于项目取舍，应改成可说明理由的设计规则，不能标成 Apple 强制要求。

## 3. 统一视觉规范的补充

### 3.1 令牌、主题与定制

按三层组织：基础色阶/间距 → 语义令牌 → 组件槽位。基础层负责数值，语义层负责用途，页面只选择变体。`lq-*` 是组件样式唯一真源；`tw-*` 负责布局工具，不另维护一套同义玻璃组件实现。

主题解析分开两个概念：`appearancePreference=light|dark|auto` 与实际 `resolvedAppearance=light|dark`。显式light/dark直接生效，auto跟随系统，偏好缺失才使用产品默认（建议auto）；角色默认主要决定配色，不拦截auto。局部星图/监控可以有独立内容主题，须登记作用域；系统强制色和可访问性约束优先。用户关闭透明与减少动效始终生效，不能被局部主题或弹层覆盖。

- 深色从首个组件开始实现，偏好接入在基础阶段完成，最后阶段只做全站校准。
- 每套配色分别定义亮/暗的 `primary + on-primary + primary-soft + on-primary-soft`；同样补全 success/warning/danger/info 的前景色对。不能把亮色 primary 继承到深色，再配深色前景字。
- 教师青绿是默认值，是否允许教师自选配色由偏好权限契约决定；课程身份色、监考色、试卷状态、笔迹颜色与用户主色解耦。
- 明确 `surface-0/1/2` 与旧 `background/card/popover` 的别名方向，禁止循环引用。`off` 必须将实际所有模糊声明置为 `none`，不能只改一个未被引用的 blur 变量。
- 顶层Portal、原生dialog、iframe子文档各有明确主题传播方式，不能依赖某个body内的偶然继承。
- 定制仅允许配色、密度、材质强度和经过登记的领域变体；页面不私造按钮、圆角、状态语义或局部主题机制。
- 打印/导出另用不透明浅底、清楚边框、正常排版；隐藏工具条和动效。简历、试卷、材料产物不继承网页背景玻璃。

### 3.2 材质与性能的统一决定

普通工作页建议最多两个持续模糊宿主（顶栏加侧栏/工具条）；弹层开启后总量目标仍不超过三个，按**真实渲染状态**计数。若超限，先去掉scrim与子控件模糊，再降低背景壳材质。这个数字是初始项目预算，不是GPU安全保证。

默认内容卡完全或接近完全不透明，不创建模糊。侧栏、工作台和表格允许分隔线，不为“高级感”删除必要边界。禁止一屏多个漂浮色团与常驻大面积动画；考试、编辑器、监控和白板默认静态背景。

通用玻璃类不设置 `contain:paint`、`will-change` 或所有直接子元素定位；局部高光伪元素自行定位且不拦截指针。`contain:paint` 会建立定位包含块和堆叠上下文，不能作为无副作用优化。[MDN contain](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/contain)

嵌套滤镜、opacity和mask可能改变可采样背景边界，不能靠“类名不嵌套”保证正确。[MDN backdrop-filter](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter) 背景采样仅针对已知可访问图片，处理CORS失败并缓存结果；不循环截屏采样整个DOM，不逐帧做canvas读回。

## 4. 组件库必须达到的规格深度

### 4.1 每个控件都要有可审查登记

原案描述了基础按钮，但还没有规定“每个业务按钮”。实施新增 `docs/lq-action-registry.md`（或对应结构化数据），按**路由＋角色＋状态＋动作ID**登记，不能只列“页面换成lq-btn”。每条包含：

`actionId / 所属路由与组件 / 可见角色和资源权限 / 前置业务状态 / 准确文案和可访问名称 / 原生button或link及type / 视觉等级与tone / 字体字号 / 尺寸与形状 / 桌面和移动位置 / 图标 / 默认-hover-focus-active-disabled-loading状态 / 确认内容 / API与版本字段 / 重复点击策略 / 成功和失败反馈 / 完成后焦点及导航 / 测试编号`。

### 4.2 按钮与交互补充规格

| 维度 | 统一要求 |
|---|---|
| 基础 | 普通40px高、14px/600、横向16px、图标18px、间距6px、胶囊；紧凑32px/13px/600，仅精确指针；大按钮48px/16px/600 |

| 颜色 | primary背景配on-primary；soft配on-primary-soft；ghost配ink-2；危险动作配danger色对。所有态引用色对，不统一opacity压低可读性 |
| 位置 | 页级主操作在页头尾端；表单提交与当前表单关联；长工作台可固定底部但保留内容避让；危险动作与常用动作有间距或菜单分组 |
| focus | 清楚实色轮廓，focus-within显示附加操作；对玻璃的明暗背景均可识别，不能被clip裁掉 |
| loading | 保留可访问名称和按钮占位，spinner作为辅助；有“保存中/提交中”文本或关联状态。不要用visibility:hidden让按钮失去名称 |

| 危险确认 | 写明对象、数量、后果和可恢复性；初始焦点优先安全动作；结果由服务端确认，不能动画结束就显示成功 |

### 4.4 弹层与通知的闭环

统一的是协议和体验，不要求把所有弹层重写成同一个DOM。LayerCoordinator至少登记 `owner/root/trigger/modality/parentLayer/returnFocus/closeReason/beforeClose`：

1. 打开时选正确初始焦点；关闭后恢复触发器或合理后继位置。modal使背景不可交互，popover/menu不全局锁背景。
2. 外点、Escape、关闭按钮、浏览器返回、父组件销毁分别是关闭原因。脏表单必须先处理未保存内容；只关当前最上层。
3. 允许有明确父子关系的日期面板、选择器、帮助、附件灯箱和确认层；禁止的是无管理的多层叠加，不是一刀切禁止必要子层。
4. 原生dialog的后代浮层进入正确的top-layer/内部宿主；body Portal不能通过更大z-index穿过原生模态层。所有控制器共用焦点和滚动锁所有权。
5. 不以`aria-hidden + tabindex`当作完整inert替代；降级须同时处理焦点、指针、动态子树与恢复。优先采用已有经过测试的基础设施。
6. `close()`/`destroy()`幂等，移除监听、observer、定时器，取消待完成异步结果回写；关闭动画有超时兜底，不能只等可能不触发的transitionend。

模态对话框的焦点进入、圈闭和返回应依照可访问交互模式验收。[W3C Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

toast只保留一个服务和一个播报出口。React调用同一服务或适配器，不再同时创建独立sonner消息队列。表单错误常驻就地显示；后台任务进度进入JobStatus；重要失败可有持久通知，常规成功短提示并去重。静态状态chip不全部加`role=status`，计时器不每秒触发live region。

同步`confirm()`改为Promise时，事件必须先`preventDefault()`，再等待确认；防止链接或表单提前执行。检查调用者是否`await`、重复点击是否被锁、取消是否清理。`beforeunload`保留浏览器允许的原生机制；剪贴板、下载和新窗口操作需要验证异步确认后用户激活是否仍有效。

## 5. 所有业务页面共享的状态和权限协议

### 5.1 保存、提交和冲突不能混成一个spinner

| 状态 | 可见反馈 | 允许的下一步 |
|---|---|---|
| dirty | 未保存 | 继续编辑/保存；离开有保护 |
| local_saved | 已存本机 | 继续编辑，等待或主动同步；不得称“已同步” |
| syncing | 正在同步 | 合并后续修改，避免同时发多个覆盖请求 |
| synced | 已同步，必要时显示时间 | 以服务器确认的版本为准 |
| offline | 离线，修改仅保存在本机（仅确已存成功时） | 保留内容；恢复后按版本协议重试 |
| error | 保存失败＋可执行原因 | 保留输入和附件；明确重试范围 |
| conflict | 内容已在其他位置更新 | 保留本地版本，重新核对；不能自动覆盖或作为断网错误无限重试 |
| submitting | 正在提交 | 锁定同一提交命令，等待附件和草稿队列；不得提前清空 |
| submitted | 已提交/已交卷 | 使用返回的版本和业务状态更新页面 |

`SaveStatus`只呈现状态，业务controller拥有状态机和请求队列。视觉组件不能自行再增加一条保存请求。相同语义组件可共享，考试、作业、简历、LessonDoc的版本字段与恢复规则仍由各自适配器处理。

服务端响应不明的写操作应核查结果后再重试；断开HTTP不代表服务器取消。只有后端已经支持幂等标识的操作才可宣称安全重放，不能用前端按钮禁用替代并发保护。

### 5.2 权限与错误

每动作定义 `visible/enabled/pending/disabledReason`，服务器仍是授权真源。页面角色包括学生、任课教师、非所属教师、组织管理员、超管；还要检查资源归属、共享范围、当前提交轮次、任务状态和代理身份。教师/学生两张截图不足以覆盖权限。

| 情况 | 统一呈现原则 |
|---|---|
| 登录过期 | 明确需要重新登录；可恢复草稿按既有安全策略保留，不能把登录HTML当成功JSON/片段 |
| 403/404 | 使用对应权限/不存在状态；不泄露不可访问资源标题或内容；不自动反复请求 |
| 409 | 冲突区常显、保留编辑、提供核对/刷新；区分材料版本冲突与业务状态已改变 |
| 400/422 | 对应字段或文档约束显示，错误摘要可定位；不只toast |
| 429 | 显示冷却与重试条件，输入保留；不另启高频轮询 |
| 网络/5xx | 保留本地工作，提供有限重试；不能显示“暂无数据” |

通知通道策略保持现有业务层决定：UI toast不新增邮件，不把每次轮询状态变化播报为新消息。`classroom_app/services/email_notification_service.py:350`、`:384`、`:407`、`:1530` 已区分事件、成绩可见性、小组公布与发送时重新判断，不能因统一视觉而改成“danger都发邮件”。

## 6. 教学核心业务链补充计划

### 6.1 作业/试卷编写：必须新增独立章节

原案对用户特别关注的“作业编写”缺少完整设计。`exam_editor.html`并不只是通用文本编辑器：它管理题型、分值、评分标准、附件要求、试卷配置、组织共享、AI/导入和课堂布置。

建议模块：`AssignmentComposer`协调文档状态；`QuestionOutline`负责目录与排序；`QuestionEditor`按题型渲染；`RubricEditor`负责评分要求；`AttachmentRequirements`负责文件约束；`ImportDiagnostics`负责导入错误定位；`PaperPreview`只读预览；`ScopeSelector`呈现共享范围；`AssignmentPublisher`负责选择课堂及布置条件。保存、生成、导入和布置不由这些呈现组件分别复制实现。

布局：顶栏放试卷名称、保存状态、预览与当前主操作；桌面左题目目录、中间正文、右评分/属性；中等宽度右栏变按需面板；手机主编辑区单列，目录和属性通过有名称的入口打开。正文不能因三个固定面板被挤到不可编辑。

必须区分：草稿、评分标准未完整、可布置、已布置但无人作答、已有草稿或提交、只读共享、无管理权限。已有作答时后端会拒绝原地修改题目，UI应事先解释并提供已有能力允许的路径，不能一直显示可保存然后用toast报错。

**已有证据：** `templates/exam_editor.html:2395`开始的保存流程包含配置与共享；`:2440`的原生confirm存在“确定完善评分、取消只存草稿”的有效双分支。`classroom_app/routers/homework_parts/exam_papers.py:326`返回`is_owned/can_manage/scope_level`，`:339`起限制已发生作答的题目修改。

**需要单列的能力补齐：**当前编辑器PUT未携带客户端预期版本，相关路由也没有该校验。若承诺多窗口安全编辑，应设计预期修订号/ETag及409交互后再实施，不能在文档中写成“沿用现有CAS”。这属于业务一致性改进票，需独立审查API、数据库更新条件与旧客户端兼容。

确认改为明确三结果：“完善评分”“仅存草稿”“返回编辑”。关闭、Escape、遮罩只映射返回，不再让“取消”隐含保存副作用。AI结果先预览/应用，未采用不得覆盖当前内容；导入失败保留原试卷。

**验收：**各题型与空题、题目排序/删除撤销、分值和评分标准校验、导入部分错误、共享只读、已布置修改限制、未保存离开、AI迟到结果、两窗口冲突；保存草稿和布置课堂的结果分别可核实。

### 6.2 学生作答：保留单一提交执行器

当前React岛屿不是第二套提交业务：`frontend/src/islands/assignment-submit-sync.tsx:43`起观察DOM和事件，展示提交状态；实际请求由页面脚本负责。它依赖`.answer-textarea`、`.answer-form-container`、`#submit-btn`及模板`:982`起发布的自定义事件。因此“旧类名全部删除”会切断观察链。

模块边界：`AnswerStore`、`DraftSync`、`AttachmentQueue`、`SubmissionController`拥有数据/请求；`AnswerField`、`QuestionNavigator`、`SaveStatus`、`SubmissionActions`负责显示。不要为每文件400行拆碎共享闭包；以可独立测试的职责为界。

### 6.3 考试：计时与草稿不得依赖视觉壳

`templates/exam_take.html:2106`保存打开页面时的固定`SUBMISSION_VERSION`，后续冲突停止写入。迁移必须保留这个版本边界，不能从最新响应悄悄刷新版本后覆盖新轮次草稿。

- 计时依据既有服务器截止规则；后台标签页恢复、时钟偏差与可提交状态按现逻辑校准，不依赖CSS动画或每秒定时器精度。当前到期只更新可提交状态，并无自动交卷（模板`:1912`、`static/js/assignment_time.js:83`）。

- 题目导航的已答/当前/错误/待上传用文字、形状或图标共同表达；可触控目标足够大。
- 软键盘出现时，导航Dock可收起，但不能让唯一提交入口永久消失；保留表单上下文内的可达提交路径。

### 6.5 最终材料、签名与正式导出

4. SSR输出已保存的偏好与身份上下文；auto通过首屏媒体查询或最早同步脚本解析，不能假定服务器知道客户端系统深浅色。auto监听系统变化但不每次变化发写请求；弹层主题同步。
5. 采用向后兼容、可空/有默认值的增量迁移，验证SQLite和PostgreSQL路径；旧服务可忽略新列，回退不需要删除偏好数据。
6. 复用已有偏好加载，避免每组件查询或每页新增N+1数据库读；全局监听只注册一份，保存操作合并而不高频写库。

### 8.4 迁移台账与删除条件

扩展已有`tools/frontend_migration_inventory.py`，形成路由级台账（建议`docs/lq-migration-registry.json`），不是只有模板名的数组。每项至少记录：

`routePattern / template或fragment / roles与资源scope / layout / assets与islands / controller与DOM钩子 / APIs与版本字段 / 关键状态 / 组件依赖 / before基线 / tests与配置 / migrationFlag / sharedCssConsumers / exceptions / rollbackUnit / status`。

状态分为未盘点、已盘点、组件就绪、迁移中、业务验收通过、视觉验收通过、待发布、已发布、旧代码可删除。135个模板逐一归属到路由/宏/片段，不能每个文件都算一个完成页面。

删除CSS须检查模板、JS字符串、React、iframe、导出/打印及未授权/空/错误分支。`Source:`注释是定位线索，不是删除证明；一个页面完成后，共享规则仍有消费者就保留。内联style并非无法使用令牌，抽离是为职责和维护，不是必须先抽完才能应用变量。

lint分三级：可确定错误阻断（无可访问名称、未许可色值、非法变体）；疑似问题提示（动态模板、共享钩子）；运行时验证（实际层数、焦点、权限、溢出）。例外登记`reason/owner/scope/reviewAt`，允许用户内容色、画布坐标、必要尺寸测量和第三方内部样式；禁止用普遍豁免掩盖一次性UI。

### 8.5 资源缓存、发布和回退

`asset_url()`适合模板引用，但仅替换入口的`?v=`不保证ESM传递依赖更新。建立同一发布的资源图：模板、CSS、原生模块与Vite manifest一致；优先内容哈希资源，对仍用mtime的依赖明确版本传播。关闭页面后再打开、缓存命中、跨发布回退都应验证。

回退单位是“对应HTML＋CSS＋JS＋向后兼容schema”，可按页面/领域开关启用；不能只保留旧模板而删掉它的CSS/脚本。长时间打开的考试/编辑页不在后台自动热切主题系统或强制刷新，应保持当前会话资源可用。

每个实现PR完成本地构建与相应回归，**部署仍按项目现有发布门禁和用户实际授权执行**。原案“每阶段必部署”改为“每阶段具备独立发布条件”；文档审查、界面开发不自动授予生产部署权限。也不把“更新记忆”作为自动实现步骤。

### 10.3 视觉与可访问性

组件级覆盖完整状态矩阵；页面级按风险做组合覆盖，避免机械生成几千张没人审的截图。核心作答/评分/签名链必须覆盖亮色、深色和关闭玻璃；配色完整组合优先在组件层和实际Portal/壳验证，再抽查领域页面。

- 视口：320、375/390、768、1024、1440；加各实际布局断点±1px；200%缩放和适当的重排检查。平板触摸不能按鼠标小按钮处理。
- 数据：长中文、英文长串、无头像、图片失败、0/1/多项、长表格、错误提示、权限禁用、后台处理中。
- 操作：全键盘、focus-visible、触控、输入法；拖拽有替代动作；reduced-motion、reduced-transparency、contrast、forced-colors均验证。媒体特性无法仿真时记录手工验证方式，不能跳过后标通过。
- 读屏：有名称/角色/值；错误与帮助关联；tab的控制关系、radio的选中、列表/表格语义正确；自动刷新不反复播报整屏。
- 对比：对文本、选中/未选中、边界/焦点分别检查。玻璃采样先固定背景图、时间、动效和内容；最亮/最暗纯背景并不足以代表复杂照片/文字背景。
- 截图验收同时看视觉重心、留白、对齐、层级、颜色语义和真实可读性；对动态区域有受控掩码，结构性遮挡/溢出/文字缺失不能用像素容差放行。

### 10.4 浏览器与性能

基础功能支持范围、材质能力与动效能力分开记录，取消“A档必有所有特性”的推断。用户代理和CPU核数只能作辅助提示；未知设备先使用保守默认值，用户可关闭增强，不能自动降级后持久改写账户偏好。

跨文档View Transition需要两端同源页面共同启用，与`document.startViewTransition`的同文档能力不等价；当前官方资料仍标注跨文档规则为有限可用，作为增强即可。[MDN @view-transition](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@view-transition)

Tailwind4官方最低目标为Safari16.4、Chrome111、Firefox128，不兼容原案承诺的一部分旧浏览器，因此本次保留3.4。[Tailwind升级指南](https://tailwindcss.com/docs/upgrade-guide)

| 指标 | 修订后的测量与初始门槛 |
|---|---|
| 可用性 | 支持浏览器首先能登录、导航、保存、提交、读取结果；无玻璃仍全部可用。能力关闭仿真与真实旧内核测试分别记录 |
| 玻璃成本 | 普通页持续宿主建议≤2，弹层组合目标≤3；核查伪元素、::backdrop及被透明遮挡元素，另记录覆盖面积、DPR、背景动画与实际帧耗时 |
| 交互 | 固定机器/浏览器/数据/操作，记录前端交互到下一次呈现的p50/p95，核心路径实验室目标p95≤200ms。使用Event Timing/trace等明确测量方法，不能把rAF回调当成已呈现。请求、上传、生成等业务完成时延另记并设场景预算；真实用户INP p75另采集，不能混报 |
| 长任务 | 捕获交互期间>50ms任务并定位；玻璃改造不得新增可归因的长任务，已有业务长任务列票处理，不以全页面绝对零为假门禁 |
| 布局 | 固定场景CLS目标≤0.05；加载/按钮busy/字号/顶部收缩不得造成关键操作漂移 |
| 资源 | 记录构建体积与路由传输量。过渡允许经批准的有期限增量；原案400KB min CSS、18KB gzip核心JS作为待验证目标，不能靠漏打包/不计懒加载达标 |
| 生命周期 | 连续开关/切页20次后无重复请求/监听/订阅；内存测量固定浏览器和回收条件，不要求噪声下字节完全相同 |
| 服务端 | 同一操作请求数、并发保存数、轮询频率不增；偏好查询/更新有界；不因React与原生同时订阅而重复拉取 |
| 实机 | 至少旧Windows教学设备、iOS Safari、常用安卓/微信路径；未取得设备的项目标“未测”，不得用新版Chromium模拟结果代填 |

首屏关键图片不统一lazy；首屏背景与LCP候选应按实际加载策略验证。关闭增强应停止其observer/rAF等运行时成本，不能只把装饰隐藏。

## 11. 文档与组件库的完成定义

本补充稿解决的是实施规则和风险，**全平台逐按钮清单、可运行组件预览、全部主题色对与实机记录仍是实施产物**。完成条件应写成以下证据，而不是“已经统一成lq类名”：

- 每个路由/片段/独立文档有台账，每个可操作元素有标准组件或解释充分的领域变体；没有遗漏的深链、角色与错误状态。
- 每个基础组件有规范、实例、状态表、键盘/触控行为、主题与降级；只有实际需要的入口实现，公共契约一致。
- 作业编写到成绩、最终材料到导出等关键链有完整通过记录，数据版本、权限和副作用保持正确。
- 3D课表、白板、编辑器和阅读壳保留领域能力，用户内容与产物视觉不被主题重解释。
- 旧代码删除由消费者清单支持；共享壳、资源图、数据库兼容和页面开关可回退。
- 自动检查、人工视觉判断和实机测量分别有记录，未测项明确保留，不能用“axe通过”或“截图差异小”替代业务验收。

建议维护四份相互链接的实施资料：`lq-components.md`（组件规格）、`lq-action-registry.md`（业务按钮）、`lq-migration-registry.json`（路由与迁移）、`lq-acceptance.md`（测试与实机证据）。任何例外只登记一次并被对应页面引用，避免再形成第二套不断漂移的“真源”。

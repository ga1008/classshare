# 平台文件导入到 DSH 工作区的阶段验收

状态：源码已实现并完成分层验证；尚未纳入最终冻结源码的真实 DSH 任务验收，尚未切换生产应用。

`platform_download` / `POST /api/agent-bridge/download` 支持材料、作业附件、小组文件、课程共享文件四种平台编号，以及当前任务或同一主体合法延续的终态父任务文件。沿用普通下载权限，返回当前任务 `inputs/` 相对路径、文件名、大小、SHA256 和原业务入口；不向模型返回原始二进制、base64、宿主路径或存储字段。SHA256 可作为调用者的预期版本。导入文件不冒充本次新生成产物。

单文件上限 32MiB，托管输入目录上限 64MiB / 128 项，进程同时导入上限 2。达到目录上限应在新任务中处理更多文件。需要编辑时将输入复制为新的输出文件。Linux 原生安全写入不可用时返回 503；不采用弱化的 Windows 写路径替代生产约束。

## 授权与文件披露

最初实现存在实质性缺陷：先把文件公开到工作区，再进行最后一次授权复核；撤权时虽返回错误，却留下执行器可读文件。当前实现将数据复制、大小/哈希校验与 `fsync` 放在数据库锁外；副本由可信服务持有，权限为 0600。`inputs` 是托管目录，服务收回其目录所有权，避免执行器预建目录后在校验与清理之间替换文件名。

最后阶段依次获取任务、主体、持续授权（若有）、任务委托、源登录会话锁，重新核对实际委托、权限和源文件归属，并检查最终路径仍指向本次 inode。通过后对仍持有的文件描述符执行 `fchmod(0444)`，才允许执行器读取。取消任务、改密和账号撤权共享相关身份锁；普通退出登录及显式持续授权撤销也与对应数据库行锁排序。

资源访问使用最终读取时的原业务权限判定；这不意味着所有领域资源修改都被身份锁串行化。已经授权披露的内容无法因之后撤权而收回，与普通浏览器下载一致。发布后不再用一次撤权检查错误地声称本次下载未发生。授权或路径验证失败时按本次 inode 清理新建目录项，保留此前合法导入的重放文件。采用 no-follow/openat、非阻塞文件检查与不覆盖的链接发布，拒绝路径穿越、符号链接、FIFO 以及变化中的源文件。

## 验证

1. `python -m unittest tests.test_agent_platform_download -q`：11 项实际 HTTP / SQLite / 文件字节测试。仅 Linux 发布系统调用层用跨平台替身；身份解析、普通下载策略、源数据快照、实时撤权、续接和 MCP 分派均实际执行。覆盖同编号教师/学生身份隔离、跨班/跨组拒绝、版本冲突、大小限制、最终授权前退出登录、拒绝重放保留既有文件，以及输入不计为生成产物。
2. `tests.test_agent_download_authority_postgres`：在显式指定的 55439 回环隔离集群创建随机合成数据库，5 项全部通过，结束后删除该合成数据库。通过真实 `pg_locks` 证明先退出/先撤权/先取消的操作阻止下载，下载先取得最终授权锁时退出或持续撤权等待其释放；持续授权与委托的锁序不存在本测试覆盖的循环等待。没有读取生产数据库或运行应用后台工作器。
3. 服务器 Linux 精确源码探测：21 项通过，证据见 `agent-platform-download-linux-poc-2026-09-10.json`。除源/目标软链、FIFO、替换 inode、目录重命名、配额与重复导入，还实际以 UID/GID 10001 读取文件，证明授权前不可读、授权后可读、执行器不能替换托管目录内本次输入。测试使用合成文件和较小限额触发边界；没有付费模型请求。JSON 保存被验证服务源码和 multipart 文件的 SHA256。

这三层验证不能代替同一冻结版本的 DSH ACP/MCP + Linux + PostgreSQL 端到端任务。最终发布仍需复跑教师/学生/管理员的真实任务，特别检查读取原始 Word/Excel/PDF 后生成并下载新产物、取消与重试、工作区容量限制，以及发布源码与迁移报告的一致性。

# 散修声线与持续学习改造

## 实施前调查与方案

基线 `63dbdccb644c98e3f71c6aed815d48e3dc6f1761`，沿用已上线的私聊持久队列、并发上限、AI 日预算、身份与权限。

截图中的模板感有具体来源：种子的人格正文与每轮说话提醒两次强调固定口头禅；博客回复用随机 multi 要求多说几条；低境界提示要求偶尔犯错。现有反 AI 规则偏重去除 Markdown，没有约束复述、刻意追问、宣告记忆或纠错后继续追打。会话只有摘要和近期记录，普通交流没有可验证、可纠正的结构化学习。博客发送失败后仍把全部预期 parts 记为已说，也是虚假记忆来源。

设计分成两个独立层次：

- 表达层：研究公开可访问讨论，记录来源与可访问性，归纳表达机制；制作 12 种可组合声线与多场景原创案例，不复制真人整套人设。每轮只检索少量匹配案例，保留个人背景与情绪；旧散修运行时接入，不重置管理员设定，新散修在已有 speech_style JSON 中存声线 ID。避免强制口头禅、每句表情、假装线下行动或机械拆条。
- 学习层：在原有生成调用中返回私有 learning 元数据，不为每句话新增模型调用。服务端提供实际发生的消息证据，按个体与会话作用域保存知识线索、交流偏好与自我反思；下一轮可以使用、纠正和替代。自己说过的话不自动成为事实依据，公开说法也保持待核实。权限失效、撤回或编辑的证据不能继续被引用。失败恢复、重复处理与并发不造成重复学习或覆盖新纠正。

原始网页只作研究数据，不能修改系统指令。存储归纳、来源链接与原创案例，不将搜索摘要冒充完整评论，不保存真人账号身份。无法访问的平台明确记录，数据量以实际取得和清洗后的产物统计。风格案例不是本人的真实经历。

## 验收与发布计划

验证旧角色不被重置、新生显式/自动匹配、12 种声线与情境覆盖、提示长度与稳定变化；验证截图里的纠错、收束、情绪承接场景。学习覆盖真实证据、私聊不串线、来源失效、幂等、替代冲突、模型失败、发送失败、重启恢复与后台审计权限。模型使用替身，不以固定输出证明生产模型已经像真人。

运行隔离后端回归与原生 PostgreSQL 并发/迁移演练，检查正式构建与相关旧功能。冻结后沿用 DryRun、停止写入备份、正式部署、只读上线核验、Git 远端一致性流程，保护业务库和 `/lanshare/data`。

## 实现与语料

[完整讲话指南与 240 条原创案例](wanderer-speaking-guide-2026-10-28.md)由程序资源生成；[研究记录](wanderer-voice-research-2026-10-28.md)保留来源链接、实际访问范围与清洗方法。实际登记 33 条可用网页/索引观察、3 条不可访问记录（full=2、partial=31、unavailable=3），不将其称为 240 条采集评论。知乎、小红书、公众号未取得可用正文，抖音仅索引片段，没有假称取得视频截图或完整评论。

运行时按场景和表达意图选择最多 3 条案例，单次声线指南不超过 3000 字符；语料单次加载缓存。20 位默认散修有明确映射，自定义角色可据气质匹配，天道新生在已有 speech_style JSON 中保存有效声线与版本。旧人格不写回，只在运行时识别并替换精确匹配的旧自动风格句，管理员的其他设定保留。取消博客/群聊随机要求多说几条，低境界不再要求故意犯错；普通“记不清了”等语义不会被文本正则误删。

[个体学习实现记录](wanderer-learning-memory-2026-10-28.md)说明来源、作用域、纠错、持久性与容量。新增一张经验表、范围索引和失败重试索引；学习复用当前生成请求，不追加每轮模型调用，不加修为、不增公开活动与天道活动计数。等待学习锁后再次检查权限，避免解除好友期间继续落库；维持原有锁序。学习失败与审计失败都有 savepoint 隔离，回复仍可提交，后续行为能恢复有限重试包。

## 1. 旧数据保护的实际证据

不是只按代码推断兼容性：从线上 PostgreSQL 16 导出一致性备份，传输前后校验 SHA-256，在本机只监听回环地址的独立 PostgreSQL 16.14 集群恢复，并验证增量迁移两次、完整应用数据库初始化两次（独立 Python 进程）。未启动应用、AI 或后台 worker 连接这个真实数据副本。

| 检查 | 结果 |
| --- | --- |
| 原有表与行 | 220 张表，469,672 行；旧字段、主键、关联关系、原结构与序列均无差异 |
| 关键旧记录 | 98 个任务、4,294 份提交、13,342 条提交文件登记、86 条成绩版本、36 条材料导入记录保留 |
| 历史任务新分类 | 全部保持 NULL、版本 0；无自动写入分类审计，无自动重批 |

| 原始备份 | 32,120,139 字节；SHA-256 `cc48110a53b63cecf998530c5131ba256f8db9216af3767b2fb40ba3b4d29e36`，演练后未改变 |
| 线上状态 | 只读查询及一致性备份；没有修改生产表、配置或运行服务 |

首次完整数据库初始化演练发现一个已有的签名功能种子初始化会反复更新时间戳并推进序列。修复为只更新变化项、只插入缺失项；重新从原始备份恢复后复验通过，没有将差异加入白名单。保留 [首次报告](assessment-postgres-rehearsal-2026-09-07.json) 和 [修复后通过报告](assessment-postgres-rehearsal-fixed-2026-09-07.json)，便于审计。

验证能说明这份真实备份及当前迁移代码没有改坏旧数据，不能承诺未来任何数据状态和部署操作都零风险。因此上线继续实行备份、源码指纹核验与迁移门禁。演练方法见 [操作说明](assessment-migration-rehearsal.md)。原始备份、数据库副本留在同步目录之外，报告只含汇总与哈希，不含学生作答或个人名单。此次证据覆盖数据库记录和文件路径映射；附件、历史材料的文件本体没有做全量备份与逐件可打开性验证，仍是上线前门禁。

## 2. 实施后的业务规则

| 业务 | 分类与执行 |
| --- | --- |
| 平时作业 | `homework`；需要视觉证据时豆包 Pro low |
| 期中测验 | `midterm`；需要视觉证据时豆包 Pro high |
| 期末测验 | `final`；需要视觉证据时豆包 Pro high |
| 旧任务未确认分类 | 显示待确认；需要视觉证据时保守使用 Pro high，教师显式确认才改类 |
| 即时对话、公开助教、私信、博客识图 | 当前授权图片进入 Lite low；不自动遍历旧消息图片 |
| 结构化教学文档解析 | 必要视觉用 Pro low |
| 纯文字处理 | 继续 DeepSeek；普通文字不因拥堵自动转豆包 |

任务分类独立于有没有在线试卷。教师发布、试卷分配、修改及批量确认有统一校验和版本比较；网页 SSR、React、历史列表、小程序、首页、通知、搜索和成绩页面同步使用正式分类。分类修改保留旧分和历史材料，同时使旧任务回调失效，避免旧结果覆盖新作答或新量表。

不新增模型选择器。教师看到任务类别、处理状态和复核提示；具体 provider、实际思考参数、输出额度、尝试次数及费用集中记录。已有其他平台凭据继续保留，不作为这套默认评分链的隐式回退。

## 3. 成绩与材料闭环

- 使用共享有效成绩投影：真实 0、教师缺交 0、未评分 NULL、有旧分重批和无分待复核分开表达。重批或回调失败保留上次有效分；迟交和小组综合成绩保持一致。
- 小组未揭晓前，各学生页面、接口、通知及复习导出遵守同一可见性；缺交 0 可以查看，但不能导出不存在的答卷。学生接口不选取内部评分证据和执行元数据。
- 统计只读必要字段，避免为全班汇总加载大段答卷与反馈；个人阶段任务不进入正式课堂分母与成绩来源。
- 新平时成绩材料明确选 3 份平时作业和 1 份期中测验；期末来源为期末测验。拒绝跨课堂、跨学期、个人阶段任务及重复槽；历史材料仍可查看，更新时才按新规则预检。
- 保留原公式：平时成绩 = 出勤 × 40% + 三份作业均分 × 30% + 期中 × 30%；总评 = 平时 × 40% + 期末 × 60%。原卷 40/50 与任务百分制 80 只换算一次。
- 保底、重修和人工调整不写回任务原始成绩。重修名单改变后改为预览并显式更新材料，不在访问页面时重算覆盖旧人工调整。
- 生成、更新成绩材料先核对来源、缺分与分制；警告逐项确认且携带来源哈希，来源变化返回冲突并重新预览，不自动重试写入。
- 教师从正式成绩材料预览整班，再显式公布独立的逐学生快照。学生只读本人公布成绩。材料后来更新或删除不会重写公布分数；教师可从课堂“成绩公布”入口独立查看历史或填写原因撤回，无需原材料仍存在。课堂存在当前公布版本时不能直接删除。

固定基准验证（关闭最低分保护，无重修或人工调整）：出勤 90、作业 80/90/100、期中 70，平时为 84；期末 80，总评为 81.6。真实本地师生界面已跑通公布、本人查看、禁止学生读取整班预览、撤回后隐藏，以及 390px 窄屏布局。

## 4. AI 执行与成本约束

执行计划按服务器提供的业务、分类版本与实际附件模态冻结，不接受学生文字或图片中的切档指令。Chat、流式与 Responses 适配器都发送实际 `thinking=enabled` 与 low/high，固定 SDK 隐式重试为 0，避免声明参数与请求不同。

持久任务在发送前以租约和 revision CAS 保存尝试账本；已存结果仅重试回调，不能重新调用模型。每个逻辑任务最多两次可能产生费用的生成、总共三次 HTTP 尝试。明确 429 与发送结果不明分别记账。旧任务缺少可靠账本且已经尝试过时停止复核，不重置预算继续付费。

普通低档评分出现明确证据风险时，可在有额度的情况下升 high 一次；全站每日 10 次、每课程每日 3 次，数据库预约，重复恢复不再占额。格式错误与证据风险同时出现时合并为一次 high 修复。high 主评分不再自动进行同档二次“仲裁”。不合格结果、截断、断流和不完整证据不能作为完整成绩落分。

结构化输出按可信试卷题数或服务端出题数量选择上限，具体阈值与修复流程见 [结构化输出规则](ai-structured-output-and-repair-2026-09-07.md)。超大出题在创建试卷和入队前拒绝并提示拆分；不会为扩大输出额度自动追加付费调用。

继续保留总并发 6、DS 4、豆包 2及 high 子限制。本轮不扩容。费用按物理 attempt 去重，分主调用、复核及实际档位统计；未知 usage 显示待核对，有已知费用时明确是小计，不当作免费。

## 5. 附件完整性与合理限制

本轮聊天、出题与批改的文件输入统一构造有序文本和图片清单，修复“文本在图片前面导致图片与名称错位”的问题。PDF 中扫描页与必要图形页、DOCX/PPTX/XLSX 内嵌图片进入视觉输入；文件丢失、坏图、过大图片、图像截断、无法表示的图表/矢量/SmartArt、缺失或外链图片给出明确提示，不静默丢弃后交给文字模型。其他材料导入与工具消费者尚未统一把 extractor issues 作为阻断条件，不将本轮改进表述为所有文件用途的完整性保证。

聊天限制 8 个文件、8 张图、单文件 10MB、图片解码前 3,600 万像素上限；文档解压限制 2,048 项及 64MB，PDF 50 页上限，超出可处理视觉页数即要求拆分。解析有并发限制并在线程执行，避免阻塞事件循环。原图完整性检查先于压缩和调用。

旧二进制 DOC/XLS 的解析器不能确认全部视觉信息时，AI 流程提示另存 DOCX/XLSX/PDF；原文件和非 AI 的文本提取用途保留。不能把“读取到了几个单元格”当作已读完整张截图。具体限制是本次明确拒绝残缺证据的边界，不是格式迁移或删除用户文件。

## 7. 生产切换与回退要求

1. 正式发布时重新检查数据库引擎、待处理/运行 AI 任务和配置，取得新的一致性数据库备份，并备份附件与材料文件、抽验历史文件可打开性；对实际发布源码与该备份重复迁移门禁。本文备份是本次演练证据，不应长期替代新备份。
2. 停止旧 worker 认领并排空或明确取消旧协议运行任务，再整体切换兼容的 app、AI 和 worker。只运行一个共享容量与预算的 AI 进程，不混用新旧 worker。
3. 同步明确的 Pro/Lite 型号、候选范围、思考参数、输出额度、关闭文字 spillover 的配置。通过容器内部 health 核对实际有效策略，不能只凭示例 env 判断线上已生效。
4. 先验证两类关键测验 high 路径、两端分类与查分、历史材料可读，再扩大普通作业和边缘图片入口。优先观察教师自然触发的少量调用，不自动发起一轮付费批量重测。
5. 回退先停止新任务入口、处理带新快照的任务，再恢复兼容代码与配置。保留新增 schema、分类审计、成绩版本和公布快照；不删除新字段，不清空任务表，不用旧数据库覆盖上线后新提交的数据。

本轮完成的是代码和发布前验证；线上启用、自然业务验收及小程序正式上传仍是单独发布步骤。原有成绩、作答、附件、材料和人工调整的兼容约束在整个切换过程中继续生效。

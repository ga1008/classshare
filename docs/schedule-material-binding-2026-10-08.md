# 教务课次排序、Git 学习材料与 3D 调课指向

## 数据合同

课次 ID 是真实上课安排的身份，继续承载教务关联、作业、出勤、提交及其他业务引用。最新正式安排中的日期、节次决定教学序号，不能通过交换不同课次的日期维持旧序号。历史日期也参与排序；同一日期按明确节次及稳定身份排序，日期已知但节次缺失的普通手工课次仍参与编号。取消、未排期记录保留身份和材料，排在有效课次之后，不占有效课次的连续编号。

例如原第 3 次课调到最后：它的 ID、教务申请关联和实际日期仍属于该课次，序号变为最后一次；原第 4 次成为新第 3 次。学习材料是教学序号的内容：主材料、多材料列表、显示顺序及简介整体按旧有效序列到新有效序列置换，原第 3 次的教材因此出现在新第 3 次。作业、成绩、出勤和人工课次标题不随教材置换。严格识别的教务自动标题只在显示槽位改用当前序号，原始标题和正文保留。

重排在课程、课堂和课次锁下执行，以暂存序号避开立即唯一约束；序号、材料和持久课表投影在同一保存点内提交或回滚。教务正式发布、旧同步入口、手工修复和 Git 教材同步共用这一实现。重复同步不再交换日期。旧版本交换日期产生的记录，仅在原始历史、当前基线和正式快照足以唯一证明时恢复；人工改动或歧义保留并报告。

## Git 投影

成功的 Git 更新在材料树入库事务内扫描完整可见树，而不只读取本次变化的 README；无新提交也会补齐绑定。明确的 `lesson_N`、`L01`、数字课次目录及 README/HTML 入口按序号绑定，根入口属于课程首页。重复编号、相互矛盾的路径和无法判断的入口保留为待核对候选，不调用 AI 猜测作为默认同步步骤。

自动规则记录课堂、仓库、教学序号、当前材料及课次、投影所有权和手工解绑标志。删除、重命名和重新编号只清理可证明由该规则管理的链接；非规范手工主材料及补充材料保留。取消课次的历史材料不因有效序列压缩被清除。显式解绑会阻止后续 Git 更新复活该自动绑定。显式 AI 匹配在返回后重新锁定并验证课次序号/材料状态，发生并发编辑时返回冲突。

仓库仅作用于已经分配且教师有管理权的课堂，不按课程名称猜测其他课堂。Git 网络等待在数据库锁外，提交时重新读取最新排序。失败拉取、冲突和鉴权失败不发布部分材料树或绑定。

## 3D 课表

已批准调课关系独立于待审批预测，只有正式新位置能唯一对应、原位置已退出正式安排时才显示原→新指向。只换教室、停课、缺失端点或有歧义的审批不伪造时间箭头。共享视图投影生成“原安排”位置，历史位置不计正式课次、课时或预测总数；它可以与同一课次后续待审批调课同时显示。

教师与学生仅收到授权课堂的关系；三个课表宿主复用同一投影和箭头实现。跨周标签支持鼠标、键盘和触屏跳转，保留 3D 当前周按需内容与 LQ 焦点/弹层所有权。材料绑定结果继续使用共享表面与按钮，领域样式只调整长文字和窄屏布局。

## 验证与发布

测试均在隔离合成 SQLite、独立本地 Git remote 和隔离原生 PostgreSQL 中进行，不连接真实业务库运行测试。源码审计与运行验收分别记录，不把扫描中的 pending/unknown 宣称为完成。

发布前运行 `tools/repair_schedule_learning_bindings.py --dry-run` 评估已保存数据；该命令默认全事务回滚，不发起教务、Git 或 AI 网络请求。审阅结果后才执行 `--apply`。既有部署流程先备份数据库、停写迁移并保护 `/lanshare/data`，随后独立核对服务器版本、不可变资产图与远端 Git。

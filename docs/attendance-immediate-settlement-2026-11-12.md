# 自动点名：立即结算（本地待审查）

本次承接同一工作区尚未提交的单人改签功能，增加立即结算及确认中断重算。没有提交、推送 Git 或部署，也没有连接真实业务库或修改真实学校考勤。

## 教师操作

- 自动点名主操作区提供“立即结算”。未开始记录、尚未到上课时间的预约、历史或作废轮次不能执行；后端再次核验，不依赖浏览器时钟。
- 首次点击会停止本轮继续记录，按已收到的证据立即启动后台结算，不再等待原补报宽限期。学生原记录在新结果完整发布前保留。
- 进度显示真实的读取证据、核算、保存及完成阶段。未知进度不虚构百分比；后台很快完成时允许直接显示完成，不为展示动画人为延迟。
- 正在等待补报或执行结算时仍可点击“立即结算”，弹窗提示将中断当前结算并重新开始。取消则继续原任务；确认后旧任务失去发布权限，新任务重新读取证据。
- 关闭浮窗不停止任务，再次打开可恢复进度。失败时保留原结果、人工更正和失败说明，可明确重试；网络响应丢失时复用原请求查询处理结果，不重复发起一轮结算。
- 已完成的有效轮次可在原有 7 天证据回放期内重新结算。重算不延长原课次记录窗口；补报数据没有被删除，后续重算可纳入原窗口内的新证据。

“重新核算”旧按钮收敛为上述入口；原结束本地点名、历史查看、作废、人工改签、申诉及旧 API 保持原有用途。结算完成后刷新学生卡片与统计，保留未保存的批量或学生改签草稿、焦点和详情浮窗。

## 数据与并发保护

结算请求、任务代次、停止记录和后台任务在同一事务受理，保留幂等收据。计算期间不持有课堂和点名轮次的写锁；每次进度更新及最终发布均验证任务代次、执行标识和调度认领。重算以协作式取消使旧工作失效，不强杀 SQL 或工作线程。旧任务迟到、旧异常、重复认领均不能覆盖新任务。

原考勤算法拆为共享读取、计算和发布步骤，普通自动扫描与立即结算使用同一规则。发布时重新读取教师决定，保留最新手工状态、理由、决定审计和时间戳；已有正向出勤事实不降级，证据不足、补报待处理或隔离数据不会自动转成缺课。新结果、证据归档及完成状态原子发布，结算失败不会被普通扫描绕过后悄悄发布。

新任务使用既有调度系统的 deadline 通道和本地点名的 90 秒失联回收策略，避免排在外部学校网络任务后。执行标识与调度认领共同防止重新接管后旧工作继续落库。停止采集、课次变更、授课归属、教师停用及作废均在受理和发布时重新检查。

结算开始前检查学校请求：单人推送正在处理或学校提交结果未知时，先完成原请求回读；尚未发送的旧整班授权可原子停止，未发送的旧操作不再继续。新结算未发布时禁止新的学校推送，但教师仍可保存本地改签。结算完成后需明确点击同步与推送，新结果不会继承旧授权自动外发。

删除课堂会撤销未完成结算并取消排队任务，原签到决定和结算收据保留。合班保留已完成任务的原始课次范围；未完成结算须先处理或作废，不能把旧工作移到新课堂继续执行。

通过原有入口重新开始记录时，前一轮未完成结算会在同一事务中失效，历史轮次、结算收据和人工更正保留，旧执行者不能覆盖新一轮。

## 实现与审查入口

- `login_attendance_settlement_service.py`：持久任务、幂等、门禁、重启与最终发布。
- `login_attendance_settlement_guard.py`：结算与学校推送之间的互斥及旧授权撤销。
- `login_attendance_service.py`：复用的读取、计算和发布算法；普通扫描防止旧时间戳回退。
- `login_attendance_settlement.js`：按钮、确认、真实进度、恢复及独立状态轮询；复用 LQ Button、Dialog、Progress。
- 数据库仅增加 `login_attendance_rounds.settlement_generation` 和 `login_attendance_settlement_runs` 表及索引，没有重建或清空旧业务表。

本次验收使用隔离合成数据，覆盖并发重算、人工改签竞态、未知学校请求、归档、调度重启恢复，以及正式构建的界面状态和响应式布局。详细结果、来源哈希及本地证据索引见配套 JSON。全平台源码清点会保留未完成运行验收的条目，不作为全平台容量或线上核验结论。

# 全局文件引用与延迟回收协议

全局文件按 SHA-256 去重，由课程材料、课程文件、头像、班群二维码、讨论/私信附件及其派生图、表情、博客、反馈、协作、LessonDoc、Git 材料和简历共同使用。删除某条业务记录不等于可以删除对应文件。

## 本轮行为

- `save_file_globally` 复用 `store_file_object_globally`：先写同目录临时文件，最后原子发布，不把正在写入的文件暴露为完整文件。
- 文件路径函数仅接受 64 位十六进制 SHA-256；异常路径不能用于定位、写入或绑定其他文件。
- `lock_global_file_references` 是事务协议，PostgreSQL 使用按 hash 排序的事务 advisory lock；SQLite 使用写事务。绑定前再次检查文件存在，文件已丢失则拒绝保存。HTTP 写入口使用 `bind_global_file_references` 返回 409 和重新上传提示。
- 批量写入必须在第一次引用写入之前一次性提交完整 hash 集合，包括原图、缩略图和预览图；不能在循环中逐个获取不同顺序的锁。先取得业务行锁，再取得文件锁，最后提交同一个数据库事务。
- `count_global_file_references` 从当前数据库 schema 发现所有 `file_hash` 和 `*_file_hash` 列，并计算简历不可变快照中的引用。这包含现有课程、头像、消息、博客、反馈等结构化引用，不能据此认定富文本和历史快照中没有其他引用。
- `delete_global_file` 当前保留共享字节并返回 `False`。现有业务记录照常删除，`removed_file_count` 不会虚报物理删除数。该函数不提交调用者事务，也不在可能回滚的事务内执行不可逆 unlink。

## 已接入绑定事务的入口

课程文件复用、小文件直传、分块合并、旧管理台上传；师生头像、班群二维码；讨论附件及派生图补建；私信批量附件及派生图补建；自定义表情；此前已接入的简历来源、头像、附件和历史恢复。

## 启用未来回收器前必须完成

1. 对博客/协作、材料批量导入、Git/生成材料、LessonDoc 媒体和所有富文本/JSON/历史快照建立完整可审计引用清单，补齐全部写入口的锁协议。当前不宣称这些旧入口已全部完成改造。
2. 回收单独运行，不能借用尚未提交的业务连接。先提交业务解绑，再经过明确宽限期；上传未绑定、正在生成、回滚或旧版本仍使用的文件必须保留。
3. 回收器对候选 hash 获取同一事务锁，重新检查所有活跃、历史和嵌入引用；有未知引用形式、数据库错误或检查不完整时保留。仅凭文件年龄或一次计数为零不得删除。
4. 支持 dry-run 清单、可审阅理由、隔离/恢复期和受控最终清理；先验证“绑定先完成”“回收先完成”“解绑后回滚”“相反顺序批量绑定”及跨进程并发。

本轮没有后台删除队列、自动清理开关或绕过保护的环境变量。保留文件是当前明确的数据保护行为，不代表磁盘已完成回收。

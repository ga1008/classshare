# 用户管理卡片与账号生命周期

本次延续职工号与任教归属改进，将用户管理页整理为紧凑账号概览、教师卡片、新增用户浮窗和教师详情浮窗。原右侧常驻表单与等高概览布局移除；统计不再被表单撑高。搜索覆盖姓名、邮箱、工号、联系方式与多校归属，启用、停用、注销分开筛选。

## 界面与交互合同

- 页面模板：`templates/manage/system/users.html`；唯一业务控制器：`static/js/manage_users.js`。
- 卡片使用原生 Button 的共享 Choice surface 变体，可用 Enter/Space 打开；没有嵌套操作按钮。概要、归属使用 LQ Surface，状态使用 Status，错误使用 Alert。
- 新增、详情、归属编辑、重置密码四个浮窗均由 `createDomainModal` 接入 LQ 层栈。共享 Dialog 负责模糊边界、滚动锁、背景 inert、键盘、出入场与焦点归还。页面 CSS 只提供布局、尺寸、排版，不定义私有白色面板、按钮材质或模糊。
- 详情打开时重新读取最新服务端资料。保存原地更新卡片、统计和关联结果，无整页重载。新增成功后直接进入新账号详情。
- 表单采用原生字段与 `form` 属性关联页脚提交按钮；保留原生 required、密码长度、邮箱格式、IME 及推荐 datalist。学校变化会清空原学校工号，防止跨校误用。
- 请求中禁止重复提交和关闭，并暂时锁定字段；失败、409 冲突保留草稿并显示错误。未保存关闭先否决，再通过共享确认浮窗处理，不受异步关闭的超时上限影响。详情中有未保存基础资料时，先保存或重新载入，再进行独立账号操作。

## 状态、数据与权限

`teachers.is_active` 表示登录是否启用；新增 nullable `cancelled_at`、`cancelled_by_teacher_id` 标识注销。迁移仅追加字段。没有物理删除教师或教学记录。

| 操作 | 登录与授权 | 归属、工号及教学记录 |
|---|---|---|
| 创建 | 超管创建，邮箱与工号校验 | 创建默认归属，立即扫描已同步课表 |
| 修改工号或邮箱 | 旧登录会话及相关 Agent 授权失效 | 原弱关联即时失效，按新学校、工号重新匹配 |
| 停用 | 撤销会话和超管权限 | 保留当时的归属启停配置和历史，关联暂时失效 |
| 启用 | 恢复登录；超管权限需另行授予 | 恢复有效身份匹配；不重新开启此前手动停用的归属 |
| 注销 | 撤销登录、权限及关联，禁止普通恢复 | 保留课程、班级、材料、历史及邮箱/工号占用 |
| 重置密码 | 撤销旧登录会话和相关授权 | 历史及归属不变 |

当前登录账号不能被自己停用或注销，至少保留一名启用超管。已注销详情只读；停用账号先启用再编辑。新建操作不能静默恢复或覆盖停用账号，返回明确的原卡片启用提示。既有经过独立确认的 Agent 恢复流程改为显式启用、更新资料、重置密码与可选授超管，同一事务完成，注销账号仍禁止恢复。

旧版本停用时曾一并关闭所有归属。兼容恢复仅匹配该次账号停用的准确时间，不恢复更早手动关闭的归属。SQLite 启动归属回填只处理启用教师，避免重新激活注销账号的归属。

所有管理修改要求 `expected_revision`。版本摘要覆盖账号身份、状态及归属；在同一账号管理锁下检查最新超管权限和版本，再写入。陈旧或缺失版本返回 409。会话撤销、授权失效和资料写入属于同一事务，后续关联计算失败也整体回滚。

## 课表弱关联

复用原正向身份解析器，不建立独立持久绑定表。反向摘要 `load_teacher_timetable_link_summaries` 批量读取有效身份、教师目录与已缓存课表学期，不读取整份课表、不访问外部教务系统。相同学校与规范工号唯一匹配才显示“已关联”；无目录显示“未匹配”，冲突显示“关联冲突”，不按姓名猜测。

账号停用、注销、归属停用和改工号都会即时影响下一次读取。明确工号仍优先于已验证教务账号的兼容回退。弱关联不转移课表、不改变所有权，也不授予查看权限。无该学校权限时仅显示匹配状态，不暴露课表教师资料与跳转 URL。

有权查看且存在缓存时，“查看教师课表”在新窗口精确定位已有教师及学期，自动打开原有 LQ 完整课表浮窗。深链仅调用本地详情 GET；缺缓存、无权限或参数错误时不会回退远程抓取。原正常查询入口保留。工号含 `/` 时路由使用 path 参数，继续执行原学校及资源权限检查。

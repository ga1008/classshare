## 2. 轻量 API 查询与耗时

方法：独立内存数据库，分别构造 1、6、30 个授权课堂；每个课堂增加 6 项任务和 1 个课次，再加入 145 项个人待办。学生、教师各场景连续请求 10 轮，页大小 100，固定投影时间，禁用身份缓存。每轮使用真实 FastAPI TestClient 请求并记录 SQL trace。整个场景前后比较数据库 dump 的 SHA-256；六组均一致，全部请求只出现 SELECT/WITH。

| 角色 | 课堂数 | 完整事项数 | 每轮 SQL 数 | 首次请求 ms | 后 9 轮中位 ms | 10 轮最小–最大 ms | 返回 JSON 字节 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 学生 | 1 | 158 | 11 | 18.636 | 11.854 | 11.341–18.636 | 117453 |
| 学生 | 6 | 193 | 11 | 15.838 | 13.912 | 13.583–15.838 | 117088 |
| 学生 | 30 | 361 | 11 | 26.964 | 25.681 | 24.854–27.570 | 119716 |
| 教师 | 1 | 159 | 10 | 11.816 | 11.279 | 10.956–12.495 | 116985 |
| 教师 | 6 | 194 | 10 | 13.868 | 12.700 | 12.363–13.868 | 117160 |
| 教师 | 30 | 362 | 10 | 21.845 | 19.586 | 19.222–21.845 | 118176 |

这些是当前工作区、本机、内存 SQLite 的小样本请求耗时，包含验证、查询和 JSON 序列化；首次请求不是生产磁盘冷缓存实验，也不是线上 p75。没有并发压测、实际网络传输、真实 PostgreSQL 计划或生产冷/脏修为缓存实验。

查询次数不随课堂数增加，未发现按课堂产生的 N+1。轻量端点不调用 `build_dashboard_context`，不重建修为/计划或执行其既有副作用；测试直接令该调用抛错以防误用。统计来自授权事实，而不是旧 agenda 的筛选或前 100 条。

**规模限制仍需如实理解：**准确的动态计数仍会扫描当前账号的授权源；`fetchmany(100)` 限制 Python 读取批次，不表示 SQL 总扫描只有 100 行，也不表示 PostgreSQL 使用服务端游标。新 keyset 每页只保留至多 100 个完整候选对象，但去重集合仍保存 O(N) 个来源键；兼容 offset 路径保留 O(offset + limit) 个候选并限制 offset≤10000。新前端使用 keyset，因此没有由该兼容上限导致的末页不可达。100 项响应约 117–120 KB 是未压缩 JSON 小样结果，不能由此推断线上带宽或并发容量。

本地逐轮数据和前后哈希已归档到 `artifacts/home-classroom-redesign-2026-09-05/backend-api-performance.json`；其 `scripts/backend_api_probe.py` 可基于重新建立的隔离测试 fixture 重跑。运行副本按主任务清理约定处理，以上表格保留本次结果。

## 3. MP 与数据库覆盖边界

- `build_dashboard_context` 的 `include_workspace` 默认关闭；仅 Web 首页主动开启。MP 首页保持 `success/data/error` 外层及 `role/user/stats/focus/agenda` 字段，保留学生任务桶对“待完成/已提交”的覆盖和 agenda 前 40 条契约。两角色的固定旧输出内容已经逐字段断言，新 workspace 不混入 MP 响应。
- 旧课堂统计、旧 agenda 与旧续读默认选择没有被替换成 Web 新字段。唯一有意修正的旧 cockpit 提示为 D14：仅有昨天连续记录时不再声称今天已有活动；它不属于 MP 首页投影。Web 的“份数/人数”差异由新的结构计数消除，不修改 MP 所用旧统计。
- **SQLite：**以上生命周期、权限、分页、SQL只读与小样本耗时实际执行通过。
- **PostgreSQL mock：**沿用 `test_dashboard_service_postgres.py` 对 dict 行读取和 PostgreSQL 日期 SQL 分支等辅助逻辑的测试；该测试文件名本身不代表真实 PostgreSQL 执行。后续真实执行证据单列于第 6 节。
- **真实 PostgreSQL / 生产：**已补本地 PostgreSQL 16.14 的已建表读取与 10/30/60 并发小样验证，详见第 6 节；未执行真实生产验收或 EXPLAIN，也未完成 PostgreSQL 全量历史初始化迁移验收。

## 4. 课堂交叉检查

`classroom_page_service.build_assignment_workspace_items` 使用路由已授权、已处理组内结果可见性的 assignment 列表，仅输出任务标题、生命周期、提交状态和必要教师计数，不输出分数/评语/答案。检查中发现该新投影最初原样输出 naive 时间，已向课堂实现负责人提出带学校时区的修正，避免异地浏览器错误判断补交/重交结束；最终课堂状态与界面回归由课堂负责人和主任务记录。

首页不能证明“本人正在作答”时，不从公开考试时间或提交时才写入的 `started_at` 推断该状态。教务考试/监考的可靠起止时间可以判定安排进行中，二者不是同一业务事实。

## 5. Web 学期日历口径修复

浏览器核验发现旧日历将可补交任务显示为原截止日期，并将过去课次当作未完成的午夜截止事项。Web 首页现以同一次 workspace 授权源迭代附加完整日历；不从 `all_items` 的前 100 条构造，不重复查询每个课堂的旧待办概览。只读 `/api/dashboard/calendar` 使用相同投影与真实身份链，不调用完整首页构造器。`include_workspace=False` 的原日历分支和 MP 默认契约保留。

新 6 项隔离 HTTP 测试验证：

- 9 月 4 日原截止、9 月 7 日补交截止的真实 assignment 源，在 workspace 和 calendar 的状态、可行动、完成及有效截止四字段一致；日历标注“补交截止 9月7日 23:59”。
- 过去课次保持 `is_completed=false`、`is_actionable=false`，显示“已结束”和真实节次，所有截止显示字段为空。日期型课次不输出虚构的具体起止时刻。
- 146 条本人待办全部进入日历，来源键不重复；SQL trace 显示个人待办只读取一次，全部语句只读。本人试炼、投票 custom 受众和其他课堂私有事项沿用原授权源。
- 合班学生可以得到授权课堂对应学期；撤销合班关系后学期与事项均不可见。教师无课堂关联的私人待办仍可完成，非本人教师不可见；未登录、停用、非法角色返回明确错误。
- 既有 published/countdown 业务当前按 `due_at` 判断接收，并未以未来 `starts_at` 阻挡提交。首页投影因此尊重业务的 `is_accepting_submissions`，不另外发明开放条件；测试确认日历和首页一致。
- 教务考试的 UTC 起止转换为上海 `09:00–10:00`，精确到 10:00 边界显示“已结束”，不标作个人已完成；真实地点保留，时间位置字段携带 `+08:00`。

日历是完整学期载荷，保存全部轻量事项及所跨周的位置，内存与响应大小仍随事项数及跨周数增长；这与分页事项 API 的有界候选保留不同。第 2 节性能表测量的是 `/api/dashboard/workspace`，不能当作日历端点性能。新适配只在 Web 日历分支启用；真实 PostgreSQL 两端点混合读取结果见下节。

## 6. 真实 PostgreSQL 读取与并发验证

环境是任务专属的本机 PostgreSQL 16.14（Windows，64 位），端口 6543、独立 `lanshare_qa` 数据库；应用 8135 使用当前工作区代码，连接池 `min=1 / max=8`。由 `baseline-runtime` 合成 SQLite 数据导入的完整 schema 共 203 张表、345 行，父任务已验证导入 schema、数据、外键及计数。应用停止后台 workers，访问限定回环地址，无生产访问。

**初始化边界：**本次 QA lifespan 明确跳过 `init_database()`，因为既有 signature workflow 迁移遇到 text / `CURRENT_TIMESTAMP` 类型不匹配。读取使用已导入完整 schema；没有修改该历史迁移，也不将读取成功解释为“全新 PostgreSQL 初始化通过”。

`postgres-verification/probe.py` 在内存中完成四个合成身份登录，随后才采集数据库基线，凭据及 cookie 未写入证据。真实路由与 SQL 验证包括：

- 学生 workspace / calendar 各 46 项，教师各 47 项；两端点成功执行 PostgreSQL 查询、占位符适配和懒建表 `information_schema` 检查。
- 两个主账号和两个其他班/非任课账号仅显示各自授权课堂；选择外部课堂的 workspace 得到空交集。每条可操作个人待办的 owner 与登录身份一致。未登录读取两端点均返回 401。
- 该 PostgreSQL fixture 的权限覆盖限于已有主班、其他班、任课与非任课教师、本人待办；并未在 PostgreSQL 中新增合班撤销、custom 投票受众或超过 100 条事项场景。这些更细负例和超大集合末页由前述真实 SQLite 路由测试覆盖，不混称为 PostgreSQL 数据覆盖。

随后对学生/教师、workspace/calendar 交替混合发起并发读取，每档 3 轮；下表将该档全部请求合并计算样本分位数：

| 同时发起数 | 轮数 / 请求总数 | HTTP 结果 | 本机样本 p50 ms | 本机样本 p95 ms | 最大 ms |
|---:|---:|---|---:|---:|---:|
| 10 | 3 / 30 | 全部 200 | 177.053 | 234.579 | 235.347 |
| 30 | 3 / 90 | 全部 200 | 408.404 | 627.414 | 632.560 |
| 60 | 3 / 180 | 全部 200 | 606.077 | 916.766 | 948.868 |

300 次并发读取没有 HTTP 错误、客户端超时或连接池等待超时。`pg_stat_activity` 每 20 ms 采样，最多观察到 8 条应用连接；每轮结束的 health pool 均 `available == size`、`waiting == 0`，PG 应用连接全部为 `idle`。请求执行期间采到过 SQL 间隙的 `idle in transaction`，但每轮结束均归零，没有观察到事务或连接遗留。池由首次 5 条逐步达到 8 条并复用，这是连接归还而非物理连接关闭。

四个登录完成后的基线为 203 张表、349 行。全部读取完成后逐表比较行数及按完整行内容排序计算的 SHA-256，**203 张表全部一致**；登录导致的 session/日志写入已排除在读取前后区间之外。

这是同机回环网络、小型合成数据、单 QA 应用进程的短时读取实验；不能推断生产 p75、长期吞吐、多进程部署、跨网络延迟或生产容量。真实 PG 300 请求的小样结果与 SQLite 58 项单元/隔离 HTTP 测试是不同层次的证据。本轮没有为测试新增业务代码修复。

证据已归档到 `artifacts/home-classroom-redesign-2026-09-05/postgres-verification/`：`report.json` 保存各角色状态、逐请求耗时、每轮 pool 状态；`before.json` / `after.json` 保存逐表计数和内容哈希；`probe.py` 保存可复现脚本。临时 PostgreSQL 和 8135 已关闭，归档不含运行数据库、登录口令或会话；运行副本删除被自动审批审查拒绝，保留状态见验收附录14.5及归档`cleanup.json`。

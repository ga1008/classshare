# 私聊资料侧栏整理（2026-10-28）

本次将私聊右栏对齐群聊的卡片结构：基础资料与设置入口在首卡，修为、公开兴趣和能力雷达按可见数据展示。移除最新动态和无数据占位文案；备注、提醒、拍一拍、历史入口与好友关系操作移到二层设置浮窗。保持已有发送、会话草稿、未读、免打扰和群聊合同。

## 数据与布局

- 基础资料沿用社交资料接口；学习数据消费公开个人卡和现有雷达组件。教师、隐藏修为和无数据不显示对应卡片。
- 散修兴趣只复用其公开主页已有的兴趣字段；真实学生和教师的后台推断兴趣不公开。本次不新增兴趣编辑、画像推断或数据库结构。
- 卡片采用共享 embedded Surface；按钮、表单、子层、确认与状态消息复用 LQ。领域 CSS 只负责布局，不增加实时模糊、私有材质和动效。
- 侧栏由有界容器滚动，雷达紧凑展示，长姓名、组织、兴趣换行；手机和短屏不突破聊天窗口边界。二层设置需要避开全局 AI 浮动入口。

## 状态与业务闭环

- 资料异步加载保留代次保护；切换会话或关闭父窗后，迟到响应不能重建旧资料或孤立子层。
- 备注和免打扰保留真实服务器提交与失败草稿；有修改时关闭需共享确认，取消返回原输入和触发器。
- 删除、拉黑继续二次确认，取消不修改关系；提交期间防重入，成功同步会话和好友状态，失败保留可重试界面。教师不可拉黑仍以服务端规则为准。
- 子层由聊天侧栏 owner 持有并在切换/销毁时清理；保留原生输入、键盘焦点和 LQ 层栈。

实现中额外修复了三个并发状态问题：迟到的操作资料不能恢复已解除的好友权限；提交开始时固定真实修改字段，备注保存期间的免打扰推送不会引发反向写入；个人卡读取期间收到的新提醒设置必须用于初始化子层。尚未完成读取时，旧的已丢弃输入不参与脏稿判断。

真实浏览器还复现了共享层栈的焦点缺陷：`beforeClose` 打开自有确认子层后，全局 opening sequence 改变，导致成功关闭的父层跳过焦点返回。修复在 pending close 中按父子归属推进序号；无关新层一旦打断，后续自有子层也不能恢复旧焦点请求。保留新窗口防抢焦点、取消、原生 modal 和外部 owner 合同，不在私聊局部手写 focus 或添加延时。

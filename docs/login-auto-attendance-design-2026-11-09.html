2. 签到规则与两轮群体统计

2.1 判定目标与不可混淆的状态

系统回答“是否有足够的到课证据”，不把持续操作电脑当成到课条件。只要本人账号在课堂网络中出现可靠的登录或已认证接入记录，发生在本次课的合理时间范围内，并与班级主要接入规律相符，就可以认定签到成功。操作和在线记录用于补充时间线，不设置最低有效学习时长、最低点击次数或必须连续在线的门槛。

维度保存与展示决策用途
正式考勤状态出勤、病假、事假、迟到、早退、缺课；未裁决使用“待确认”系统可以自动给出“出勤”；其他正式状态由教师确认或明确外部来源给出。
证据质量充分、部分、采集异常、无法观察、网络未确认、数据冲突与考勤状态并列。采集失败不能变成缺课；出勤也可以同时显示“参与时长未知”。
规则建议已符合群体规律、偏离需复核、无可用群体基准辅助教师，不产生“代签”“协助逃课”自动定性。
人工覆盖当前状态、操作者、原因、版本与时间始终高于后续自动重算；允许审计和撤销至上一版本。

2.2 时间范围与“偏离小于 20 分钟”的准确含义

设课程起止为 S、E，建议宽容窗口 W=[S−10 分钟, E+10 分钟)，采用左闭右开边界。10 分钟是本设计建议的可配置值，不是假定学校规定。窗口只影响证据接纳，不延长实际教学时间，不代表教师晚点开始后再计满 90 分钟。

相似度按同一种时间事件比较：首次课堂网络接入对比首次接入，首次平台操作对比同一教学阶段操作，末次可靠活动对比末次活动。使用中位数而非平均数，以服务端时间毫秒精度比较 |t−m| < 1,200,000 毫秒；19 分 59.999 秒符合，20 分整进入复核，不能先四舍五入到分钟。在线秒数只显示差异，不参与硬性否决。

没有操作时间、没有结束事件、没有有效学习秒数时，该维度记为未知并跳过，不补成 0，也不要求把三个维度全部凑齐。登录已有可靠正向证据后，后续切后台、只听讲、提前关闭网页等不自动撤销出勤。

2.3 两轮计算，避免循环认定

  1. 冻结统计对象：按实际课次保存名册快照和应到范围，包含合班与有效重修成员；已批准免考勤 / 请假单独列出。一人一票，多标签、多设备、重复事件都不能增加权重。课后新增成员不悄悄改变历史分母。
  2. 第一轮实时识别：从已接收且可信的事实建立个人时间线，先标记“有课堂网络登录证据”。群体样本足够时标为“识别符合，待结束核对”；尚未形成多数不显示缺课。临近开课前为“预识别”。教师可以提前人工确认出勤，随后受人工覆盖保护。
  3. 第二轮全体复算：结束后对整个冻结名册重新计算，不只重算之前失败的人。先从原始可信事件建立班级基准，再统一判断每个人；基准不从“已判出勤”的结果反推，防止越算越偏。
  4. 结算与人工优先：第二轮决定正式自动出勤，暂定结果若不再符合则转待确认，并说明依据变化，不能转缺课。教师人工确认始终保护。正式结算后，不得仅因群体中心移动或晚到补报自动撤销已确认出勤；发现身份或网络事实矛盾时生成教师复核事项，保留原结论和新证据。
  5. 版本化：保存基准样本数、名册版本、窗口、算法版本、证据截止时间、各维度中位数与排除原因。补报只产生新计算版本，不篡改原始时间线。

2.4 群体基准的保守构建

每人的主时间点 A=min(窗口内可信网络上的成功登录、已登录认证请求)，后续重登录或晚操作不能覆盖较早的 A。教师认可的等价教室出口合并计算时间基准，保留各自网络标签；不能把各走一个出口的两个半班拆成两个不足多数的群体。仅事先明确的教学分组可使用独立冻结分母。一个账号仅贡献一个代表点。应到人数为 N，默认主群体至少 max(5, floor(N/2)+1) 人，才称为多数基准。不足 5 人的小课直接使用教师明确认可的时间参考与网络证据，不强造多数统计。

排序 A 后寻找跨度严格小于 20 分钟的最密集窗口；该窗口须满足上述严格多数人数。用主群体中位数作为 μ，再以 |A−μ|<20 分钟 评估每人。主群的窗口宽度与个人容差是两个不同参数，不能把相距 39 分钟的两个半班合成一个虚假的中间峰。最密集窗口并列且中位数相差 ≥10 分钟时标为基准不稳定，不任取首个；“10 分钟”是待校准的保守参数。没有严格多数或有多个无法解释的峰时走教师时间参考 / 待核路径。

后续操作可按明确教学阶段单独形成多数参考，补充认定时使用同类指标，不能改变最早 A。全班下半节才首次登录时，若确有可靠网络与课中活动，可按本方案宽松认定“出勤”，但必须提示“全班首次平台接入偏后”，不能称为准时或补造上半节在席证据；存在系统级采集中断时先显示故障，不能让缺测数据相互证明正常。边缘样本的去自身敏感性只检查中位数变化及个人 20 分钟边界，不重新否定已经建立的全班多数资格，避免 5 人全到或 200 人恰有 101 人主群时全体落入复核；仅个人相似度因此跨界时记为边界待核。

首次接入符合可靠多数基准时优先通过；若首次接入偏离，但同一课堂网络下的后续实际活动与全班操作阶段一致，也允许补充认定为出勤。操作、末次活动的偏离只产生解释性提示，不否决已有到课证据。若只有一条真实课堂网络登录、但没有其他活动：只要它处在合理窗口且符合可用群体接入基准，同样可以通过。

班级整体采集故障、样本不足、双峰无法解释、教师网络错误时，界面显示“基准不足 / 需核对”。可按可信网络证据批量给教师“建议出勤”，但不伪称已完成多数统计，也不自动把未识别者判缺课。

5. 点名、作废、结课与申诉

未开启 / 预约→进行中→已结束 · 结算中→结果已发布→申诉 / 人工更正

任一非删除状态可由教师作废，作废保留原记录、原因和时间。单课次允许多轮历史，但至多一轮有效进行中；重新点名生成新轮次并指定替代关系，不覆盖旧轮。页面关闭、浏览器断网、教师电脑关机不影响服务端到时结束。

轮次时间合同：课程时段、轮次证据窗口、接收截止和实际结束时间分别存储。正常自动结束使用第 4 节的 E+10 / E+12 宽容结算；教师在 T<E 主动提前结束时，旧轮新事件窗口截至 T（不再吸收 T 之后的新接入），结算默认 T+2 分钟，申诉从 T 开放。迟到到达但可验证发生在旧窗口内的事实可形成旧轮更正版本，不能把新轮事件灌回旧轮。

课内重新开启时，创建新的有效轮次及完整课程窗口，允许引用同课次此前真实证据，但按规范证据 ID 去重，不能伪造新的登录时间；旧轮固定其截止和历史结果。既有人工裁决默认带来源继承，教师明确重置后才重新判定。作废当前轮次不自动复活上一轮；教师明确选择有效版本，外部已发生的操作仍按同步审计处理。课后只允许补核和改签，不重开实时点名。

结束自动定时与教师手动结束共用状态转换；后台重启会扫描到期未结束轮次；重复执行无副作用。提前结束需显示其实际截止与原因，不能自动把未识别者置缺课。
改签支持 6 种正式状态、单个 / 多选 / 全选。每个目标带 revision；批量提交明确选中 ID，返回成功、版本冲突、无权限清单；冲突保留选择和编辑理由。已确认缺课需要教师动作，不由 0 时长推导。
作废停止本地统计和未执行同步；保留已发生的远端操作事实。不得把“作废本地”实现成自动抹除远端点名；远端如何更正需单独生成可审查差异。
结课现有结课操作缺少可直接复用的持久签到关闭状态，需显式接入“禁止新点名”。已存在轮次按选择结束，历史查询、申诉处理、人工更正和已授权的更正同步继续可用。
删除、合并与成员变更历史考勤按稳定课次 / 学生 ID 保留；课堂合并写迁移映射；移出学生不删证据。强制删除先处理活跃轮次、申诉与同步任务，不能留孤儿任务。

申诉与提醒

学生只看到自己的课次状态、结束时间、简单说明和申诉按钮；点名结束前按钮禁用并解释原因。结束后每人每轮最多一个待处理申诉，可补充说明。默认建议提交期限为结束后 7 天；已提交案件不因结课或期限到达消失，教师可延长。后续自动补报把该生修正为出勤时，申诉可标记“已由新证据纠正”，通知双方，避免教师重复处理。

复用 approval_workflow_service，新增申诉类型，不建立第二套审批。教师收到持久站内强提醒及邮件任务；邮件缺地址 / 失败有可见状态和重试，但不阻断申诉受理。站内“已读”“已展示”“已确认提醒”“案件已处理”分开记录；多标签只由一个展示所有者弹出，不使用容易消失的普通 toast 冒充强提醒。

链接携带明确课堂、课次、轮次、学生和申诉标识；登录后先做权限校验，再打开正确课堂课次及该生详情，显示本次证据及最近最多 5 次同课程记录。不得回退到“今天某堂课”。邮件不携带密码、完整 IP 或其他学生数据。

审批与改签统一锁顺序：课堂 / 课次 → 轮次 → 学生记录 → 审批请求。不能一条路径先锁审批、另一条先锁学生，造成死锁。处理时重新验证任课权和 revision；已经作废、被更正或被他人处理的申诉显示当前事实。

8. 远端同步完整流程

8.1 能力分级，不把未知协议写成既成能力

运行方式成立条件教师体验
A：经过验证的后台适配器（目标）明确、允许的学校接口及写权限；实际排课定位、开始、结束、逐人修改、回读均通过受控验证；真实定位要求有正式支持。在指定课程授权后，系统自动执行并显示逐项回读结果。认证挑战出现时暂停并请求教师完成。
B：教师端交接（保底）后台读取可用，但开始点名需要本人手机定位，或写协议不完整。准确给出本周 / 星期 / 课程定位卡；教师在官方小程序开始、结束；系统发现并绑定该轮，具备已验证修改能力时再推送差异。
C：教师设备上的界面辅助确无可用接口、用户明确启用，微信客户端与小程序版本支持稳定识别；设备在线且真实登录 / 定位已经满足。按可识别页面逐步操作并截图脱敏核对；验证码、权限、画面歧义或未知提交停在原步骤。不能承诺锁屏、断电、客户端退出后仍可运行。
D：差异清单与官方端人工处理外部能力或权限暂不允许自动写。生成每人旧值 / 目标值和具体课次清单，教师处理后重新读取确认；任务保持“待人工”，不伪报同步成功。

优先补齐后台适配器，避免为每个学生启动浏览器或依赖固定屏幕坐标。界面辅助只是明确的降级路径；不会通过破解小程序、伪造位置、猜测第三方密钥来实现。

8.2 准确定位周、星期、课程与点名

  1. 锁定当前教师、远端账户身份、学年学期和本地稳定课次 ID；从当前日历 / 校历计算周次，再与远端当前周查询核对。校历有调休、补课时以明确排课为准，不能仅按开学日除以 7。
  2. 读取该周完整课程列表，按日期、星期、节次、课程代码、教学班、授课教师共同匹配；教室用于进一步核对。课程同名、合班、同日多次授课必须消歧。
  3. 取得该场真实排课的外部标识。授课班列表的代表 schedule.id 不等于每场实际排课 teacherScheduleId；现有“历史远端点名 → 本地课次”映射不能反向套用。不能拼接或猜写目标 ID。
  4. 列出已经存在的远端点名轮次及进行状态。如果有老师已开的一轮，先显示绑定候选；对非本系统创建的轮次，不默认接管、结束或改签。模糊匹配拒绝执行。
  5. 学生按学校稳定学生 ID / 学号与本地学生 ID 一一匹配。不得只按姓名；重名、学号冲突、名单缺失逐项待核；远端多出的学生保持原状。

8.3 持久任务状态机

预检 / 差异预览→授权范围核验→定位排课→绑定或开始点名→确认结束→逐人校正→完整回读→确认一致
环节执行与确认要求
预检冻结本地结果版本、有效名册、远端原状态、账号代次、授权版本、目标排课和映射版本；展示将改动 / 保留 / 冲突 / 未映射人数。网络和权限检查不能触发新点名。
开始先写持久操作意图，再执行已核实的开始调用；记录真实外部 round ID，并回读证明只创建一次。若真实定位授权缺失，进入 needs_teacher_action。已有合法点名按绑定规则复用。
结束远端签到时长与本地 90 分钟课堂窗口是两件事；按远端已验证的时长 / 结束接口执行并回读关闭状态。不能把随机数签到 3 分钟改成伪造的 90 分钟在线。
逐人校正默认每远端账号单路串行。每次发送前检查本地 revision、授权仍有效、远端当前状态与保存基线一致，再写已决目标。没有变化的学生跳过。每个学生拥有独立操作记录。
确认回读读取完整点名名单，核对外部 round、学生 ID、逐人状态、总人数和各状态总数；需要时再次短延迟读取以应对远端最终一致性。仅 HTTP 200、成功弹窗或总人数相同都不足以判成功。
发布结果分别显示“已确认 x 人 / 待核 y 人 / 冲突 z 人”。只有当前目标版本全部可同步学生都回读一致，且无未决阻断项，才显示“本轮确认一致”。记录验证时间和远端指纹。

8.4 未签到默认为缺课的风险如何闭环

小程序截图中的未签到清单可能显示缺课，而本地“待确认”没有等价远端状态。因此绝不把待确认、采集失败、未映射或无数据直接发送为 UNCHECKED。自动创建远端轮次前，预检必须说明它是否会即时产生全班默认缺课，以及是否有草稿 / 延后发布能力。

推荐默认：本地签到独立进行；待本地结果已决且写能力核实后，在远端允许的时段建立或绑定点名、结束并校正。如果远端只允许课中开启、结束即立刻产生可用于成绩的缺课，且不能延后发布，则不启用“无人值守创建并发布”。改用教师在课中正常开启的既有点名，课后在本地完成复核后校正；任务对未决项持续告警。不会为了追求全自动，擅自将剩余学生设缺课或全部设出勤。

若已有远端点名包含未决缺课，必须显示“远端仍有未核实结果”，不自动将这一版本升为本地新确认成绩来源。外部系统本身如何即时使用这些记录，需要能力核验和学校规则说明；本系统不能承诺控制第三方的成绩消费者。教师可批量确认剩余学生状态，完成后系统续传并回读，这才关闭本轮任务。

8.5 重试、冲突与外部人工改动

  • 结果未知：请求发送后超时、连接中断或 worker 崩溃进入 outcome_unknown，先回读实际状态。开始点名不能盲目重发；无法唯一定位已创建轮次时由教师选择，不再创建一轮“试试”。
  • 三方比较：上次确认的远端值 B、当前远端值 R、本地目标 L。R=L 时无需再写；R=B 且目标版本有效时可写；R≠B 且 R≠L 时显示冲突，保留远端人工变更，不自动覆盖。
  • 保护状态优先：远端原有病假、事假、研学、实践、志愿，即使 R=B，也不被自动出勤覆盖。需要教师在差异预览中逐项明确选择覆盖这些状态，授权同时绑定旧值、目标值和版本；后续远端再变化即失效。保护规则优先于一般三方比较。
  • 无远端 CAS 的局限：如果学校接口没有版本条件更新，读取与写入之间仍可能有外部人工竞态。本地锁无法控制微信端。应缩短间隔、写后立即读、提供并行操作提示；发现不一致暂停，不能宣称绝不会覆盖。
  • 401 / 403：401 统一刷新一次认证，未发送请求可继续；已发送写请求先核对结果。403 停止当前能力并提醒授权，不反复尝试。业务 JSON 中的失效码也要识别。
  • 409：只读获取新状态，重新生成差异；不带旧 revision 无限重试。429 尊重 Retry-After，其他临时错误采用有界退避，保留 next_attempt_at，不占工作线程睡眠。
  • 本地更正：申诉通过或教师修改产生新 revision。旧的排队操作标记过期，已发旧操作先完成回读，再计算向新目标的差异，防止“旧缺课”迟到覆盖新出勤。
  • 停止 / 作废 / 凭据撤销：停止未发动作，已经发出的动作留待回读。补偿不是盲目回写旧值，必须重新对比外部现状并有新的明确授权。

现有智慧课堂 API 同步、原始 PDF、已确认解析、历史归档、成绩取数都保留。增加独立“本地登录签到”事实源，页面并列显示本地结果、外部实时快照与已确认归档版本。同步成功不改写历史 PDF，不自动撤销教师已确认的旧解释；新远端事实有变更后生成新归档候选，依原流程确认。

本地人工决策只对本地裁决有最高优先级；不能因此自动压过远端人工修改。每个来源保存 provenance、origin_operation_id、revision、读取时间。写入后再读回的事实标记为本次操作回声，不再次生成相同出站任务；外部独立修改走冲突流程。默认不改变既有出勤率、70% 保护规则和已发布成绩政策，接入本地新来源须由明确政策版本决定。

对旧解析器只支持五态的地方补充“已知特殊状态 / 未知状态”的无损保存及展示；验收所有统计分母、PDF 导出、成员页、课次页、成绩建议和归档消费者。不能用新增字段的默认值悄悄改变历史学生结果。

10. 参与度、修为与雷达图

10.1 用可观察的参与记录，而不是声称测到心理专注

“课堂专注度”可以作为教师讨论的概念，产品指标建议命名为课堂参与记录 / 平台参与度。浏览器无法看见学生在其他应用中的学习，也无法测量听讲投入、人格或情绪。记录少只能说明平台证据少，不能输出“不认真”“懒惰”或人格判断。

教学阶段可统计什么不能推断什么
讲授 / 听课网络接入、教师确认、可选课堂互动无点击、后台页、0 秒有效学习都不能说明走神。
平台内练习有效活动覆盖、任务完成、测验与提问等明确事实单纯鼠标抖动、刷新次数不等于投入；自动播放不等于吸收。
IDE / 外部网页 / 实验教师认可的任务成果、提交、课堂观察平台隐藏时间不能算低专注，不采集其他网页内容、键盘文本或屏幕。
采集不健康 / 未设置教学阶段只展示已知事件、覆盖率和缺口不能计算完整课堂的专注百分比或将未知补零。

教师可选“讲授”“平台练习”“外部实验”阶段；默认混合 / 未声明，不给教师增加必须频繁按按钮的负担。可在课后统一标记阶段，保存更正版本。操作高峰可以提示阶段候选，但自动推断的阶段不能作为扣分分母。

建议记录 visible_active_seconds、verified_operation_count、task_evidence、observable_seconds、collection_gap_seconds、teaching_mode 和 coverage_ratio。仅对明确要求使用平台且采集健康的窗口计算 参与覆盖=有效活动区间并集 / 可观察窗口；没有分母或覆盖不足时返回 null。事件计数、时长、任务成果分开显示，先不合成一个诱导刷分的总分。

10.2 与已有修为的关系

默认线性修为 raw=材料×45 + 任务×35 + 互动×15 + 稳定×5（各分量为 0—1），随后展示为 100×[1−(1−raw/100)^1.45]。稳定分目前已经包含：活跃天数 30%、连续天数 20%、focus 22%、online 18%、操作 10%；时长分别在 90 分钟 / 120 分钟封顶。教师自定义权重需要继续生效。

推荐方案：第一阶段只展示参与证据，不改已发布修为。经课程校准后，在“学习稳定”内部替换原 focus+online 的 40% 槽位，总权重不增加；其余天数、连续性和有效活动仍有各自定义。按默认权重，这一槽位在线性 raw 中上限为 2 分，并非直接给展示修为加 2 分。

替换后的课堂参与证据可综合教师认可参与、明确任务成果和健康平台练习；讲授 / 外部实验获得教师确认时与平台练习具有等价可用证据。未知证据不作 0 分或下降原因：缺测课次不进入评价分母；无可评课次时只保留被替换的 40% 槽位旧值并标记陈旧，活跃天数、连续性和有效活动继续计算。完全没有旧值时新槽位返回 unknown，不补零或满分；第一版不启用新计分，全班仍按现行政策的已公开可计算规则运行，候选槽位仅作影子展示。正式切换前必须确定同班统一的未知值政策，不对个别学生偷偷换公式。

任务提交、材料与互动已经有对应分量；同一成果在此只能作为参与时间窗的佐证，不能再按提交次数或成绩质量奖励一次。以证据 ID 去重、课次区间并集和课次上限防止叠加；政策切换时旧 focus/online 槽与新槽只能选其一。迁移不回溯削减历史修为，教师确认政策版本后只向前生效。

若希望增加趣味性，可以增加“课堂同行”纪念章、个人参与时间线、课程实践足迹。这些是原有事实的解释或纪念，不另加一遍同源分数；不做在线时长排行榜，不通过刷点击解锁签到。

11. 内部分析与学生数据隔离

本节仅供教师与维护者审阅。学生页面、接口、资源、消息、AI 回复和导出都不得透露“侧写师”“侧写词”的存在；仅在页面隐藏或要求模型保密不足以达成这一要求。

课堂数据可以支持教师侧事实摘要，例如“本课平台操作少，但有课堂网络接入；教师标记该阶段为讲授”。它不能可靠支持人格、心理状态或作弊意图判断，因此本设计不把 IP、停留、切后台、点击节奏接入人格推断，也不把内部推断作为隐性考勤或修为扣分因素。

必须先处理的源码边界

  1. 统一学生 DTO：当前学习进度 metrics 中含 interaction_quality/source/label/reason/factor，学生进度 API 和 student.learning_snapshot 可透传。建立明确字段白名单，由 API、SSR、Agent、通知、导出共用；不返回内部模型原始字典或任意 metadata。
  2. 内部摘要独立存储：停止将内部 profile_summary 写入公共 students/teachers.description。历史迁移必须根据来源识别，保留用户自己写的简介，无法识别时隔离待核而不是整列清空。
  3. 学生 AI 只拿事实：清理平台认知、Agent meta 和工具结果对内部摘要、prompt、词表和推断原文的输入；学生 AI 使用本人课程事实和本人主动声明的偏好。教师内部服务也按授课范围授权。旧会话 context_prompt、workspace 回退上下文、问候缓存、已排队消息及 Agent 历史工具结果均需版本失效与安全投影；保留原历史记录，不整批删对话，也不能让旧缓存继续送入学生 AI。
  4. 隐性系数停止参与新规则：现有互动计算使用内部质量系数 0.5+0.5q，默认 q=.7 即 .85。新功能上线前必须明确向前生效的公开评分政策，新计算不再依赖内部人格或不可复核推断。若保留内容质量评价，只能使用公开、可复核的内容规则；历史已发布分数保留原政策版本，不静默改写。此项与 DTO / AI 隔离共同作为 P1 开放门禁，不能推迟到远端写同步阶段。
  5. 所有出口共同验收：学生页面源码、静态 chunk、manifest、source map、HTTP JSON、SSE 分片、历史对话、错误响应、邮件、通知、报表及下载，均使用合成 canary 验证。历史读出也要检查，不能只处理新生成内容。

词语过滤保留为最后一道防线，但不能替代访问控制和数据分离。学生可以得到正常的事实统计用途说明及申诉渠道，不需要暴露内部角色名、词表、实现路径或分析提示词。教师端 IP 默认脱敏，查看完整网络证据需要课程权限并留审计；日志不保存密码、token、敏感正文或完整心理分析内容。

12.3 证据保全与清理

现有部分行为窗口约 7 天、收件记录约 10 天，已应用事件正文会被清理；不能等申诉时才从消失的原始数据重建。结算时必须保存可解释的规范化证据摘要、网络可信来源、时间区间和质量，哈希不能替代实际事实。默认建议考勤裁决与审计保留至学期结束后 180 天、详细证据与原始 IP 90 天，存在未结案件时冻结相关清理；这些期限需学校 / 项目现行保留政策最终确认。到期删除详细信息仍保留必要的已决统计和删除审计。

13. 采集异常与系统恢复

继续沿用已改进的持久收件和 401/409 恢复机制，不为签到复制一条高频采集链。新增工作重点是补齐首次可信接收时的认证与网络信封，并将“正常零值”与“无法计算”从存储到界面保持一致。

风险设计要求
行为 batch 缺可靠 IP / 认证上下文服务端在首次持久接收时写入 actor、会话引用、规范 IP、代理来源和接收时间。重试时不改第一次信封；新字段不进入旧客户端 payload hash，避免制造新 409。
客户端时间与离线重放分别保留发生时间和服务端接收时间、时钟质量；历史回放不能用当前 LAN IP 证明当时在教室。来源不充分仅补学习记录，不升级地理证据。
静默登录没有新审计使用受限频率的已认证请求观测补“本次接入”，不虚构密码登录；长期会话不视为一直在线。
WebSocket 身份替换仅连接时认证的旧 socket 不能无限续作有效身份。重认证 / 会话撤销检查复用现有认证机制；签到采信新鲜有效请求。
0 秒与失败混淆可靠覆盖内明确没有有效学习才可显示“0 秒有效学习”；无足够覆盖显示“未知 / 采集异常”。在线观测、有效学习和签到状态各自独立。
“server”标签误认当前部分 observation 分类不等于真实服务端业务操作。只有服务端成功提交的任务、互动等才算对应业务事实；页面点击不升级为权威操作。
worker / 应用 / 数据库故障幂等收件、事务出站、租约与 fencing 代次恢复；到期轮次启动时补结束；回读未知远端动作；不依赖内存定时器保存状态。

若数据库不能确认持久接收，返回可重试失败，不假 ACK。签到计算积压时显示最近处理截止，不把“尚未算到”展示成未到。采集恢复可以自动增加证据，不静默覆盖人工改签、已经结案的申诉和已冻结的归档版本。

课后结算保存两套水位：各来源在截止时已持久接收的记录集合 / 序号，以及本场已完成应用的水位。已 ACK 但尚未 apply、正在重试或隔离的相关批次必须显式计入“待处理”，不能当无证据。到 E+12 分钟仍未排空时允许发布已确定学生，未确定者保持“已结束、待核实”；超过约定恢复期限升级教师处理，不无限阻塞整班，也不伪装全班已完成。迟到应用和后续补报产生新的评估版本，并保留原截止快照。

14. 200 人性能预算

此前记录器已做过隔离 200 人持续负载测试，但它没有涵盖本次新增的签到规则、强提醒和远端写流程，也未证明所有冷页面均达到目标。本设计不把旧容量结果当新系统验收。

  • 不增加每学生进程 / 线程 / 定时任务。复用记录器收件；课堂聚合按 dirty 标记合并，默认每 10—15 秒最多更新一次投影，课后全量二次统计一次。规则计算对每课次约 O(N log N)，N=200 无需逐生查询历史全表。
  • 教师面板只拉当前课堂投影，前台可 10—15 秒增量刷新，隐藏时暂停；优先复用现有推送通道，不新增全站高频轮询。200 张卡片采用分页或有界渲染，避免每张卡片独立背景模糊。

  • 后台任务持久化且有界，远端同步与本地课堂读写隔离资源配额。最小任务批次可为 10—20 人，任务到期调度，不常驻等待 80 分钟。邮件每案件去重，强提醒合并，避免全班申诉产生弹窗风暴。

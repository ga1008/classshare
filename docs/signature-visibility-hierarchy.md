# 签名可见范围

签名的可见范围可设置为平台、学校、学院、系部、个人。班级及小组不是签名的新配置选项；班级中的学生沿所属组织继承可见性，小组业务仍未启用。

| 配置 | 可见人员 |
| --- | --- |
| 平台 | 平台内有效登录的教师和学生，允许跨学校 |
| 学校 | 对应学校及其下属学院、系部、班级人员 |
| 学院 | 同一学校的指定学院及下属系部、班级人员 |
| 系部 | 学校、学院、系部三者均匹配的人员 |
| 个人 | 签名归属人和绑定的签名者本人 |

超管可查看全部层级。归属人和绑定本人始终可查看自己的签名，身份按 `role:id` 比较，教师与学生的同号账号互不混用。

## 设置、申请与使用

- 管理页的图片上传、手写上传、属性编辑，以及个人中心使用同一个可见范围控件。拥有者可选择五种范围，但组织必须来自本人当前有效归属；超管可选择组织目录中的有效学校、学院和系部。
- 职务身份只参与签名点默认候选筛选，不再清空系部或扩大可见范围。范围不完整时明确报错；未知范围不自动降级。
- 可见不等于已获使用授权。归属人、绑定本人可直接使用；教师可直接使用其可见范围内的批语章。其他个人签名仍需按具体材料版本、具体签名点申请和审批。
- 超管可在管理界面查看原图；下载与材料使用仍经过使用权限检查。原有超管代审批能力保留，并继续记录审批身份。
- 范围收紧后，列表、详情、图片、认领、待审批批准和实际使用均重新校验当前范围。历史申请和使用日志保留；历史幂等记录必须属于同一个账号，且原授权仍有效。
- 文档重新解析签名绑定时重新校验材料归属人的当前范围及该材料版本的授权。范围设置不删除历史文件，也不伪造或迁移历史使用记录。

## 组织来源与历史兼容

`signature_scope_service.py` 使用同一层级定义生成单条权限判断和列表 SQL，避免搜索结果与详情接口分歧。部门名称必须连同学校和学院比较，不能仅比较同名系部。

教师读取所有有效学校归属。已有归属记录但全部停用时不回退到账号旧组织。当前组织模型是每个教师每所学校一套学院、系部归属。学校缺失不默认授权到 `gxufl`。

学生以账号组织为准：班级仅可在学校相同、学院相容时补足缺失学院，或在同校同院时修复空系部及旧同步误写的“学院名＋系”占位值。账号与班级跨学院冲突时不合并授权，也不改写学生原始数据。

启动迁移 `20260908_signature_visibility_levels_v1` 只运行一次：旧 `college` 保持原先按系部解释的含义；历史系部为空、有明确学院的签名改为学院范围；连学院也为空但学校明确的旧签名改为学校范围。后续新增的 `college` 保持学院语义，缺失组织不再自动扩大范围。autoCorrecting 导入工具使用明确的 `department` 默认值。

## 验证

权限矩阵覆盖五级、教师及学生、超管、跨校与跨院同名系部、第二学校归属、停用归属、空组织、所属人与签名者身份、SQL 与详情一致性、上传和编辑。流程回归覆盖申请、审批、授权、认领、幂等使用与文档出口；浏览器回归覆盖管理和个人中心、组织联动及移动布局。

发布前使用隔离 PostgreSQL 恢复快照演练。报告明确列出预期签名范围迁移，逐行核验其余原字段和序列不变，第二次启动必须幂等。

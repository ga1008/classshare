# 成绩记录类材料生成验收规范

本规范由“学生平时成绩记录表”的已验证流程提炼，并同时约束“考核登分表”。目标是让教师在材料库内完成来源选择、生成、定位、预览和导出，后台处理不泄漏为额外材料。

## 一、用户流程

1. 教师从对应成绩表管理页发起“课堂生成”，无需先跳转到课堂页面。
2. 先选课堂，再选该材料真正需要的业务来源：
   - 平时成绩记录表：3 份平时作业、1 份测评、考勤和成绩策略。
   - 考核登分表：1 场已绑定试卷、具备大题分值且至少有 1 名学生已评分的考试。
3. 来源不足时必须在当前步骤说明缺少什么；不可用来源可以展示，但不能提交。
4. 提交期间禁用重复提交、返回和关闭操作，错误后保留当前选择以便修正重试。
5. 成功后关闭生成弹窗，停留在原列表页，刷新并滚动到新材料，给予一次性高亮。
6. 用户只看到最终材料。成功的后台任务、解析记录、临时 JSON 和中间状态不得作为第二份材料卡片展示。

## 二、数据与业务规则

1. 课堂、考试、学生和成绩均以服务端权限校验后的权威数据为准，前端选择不能代替后端校验。
2. 生成材料必须绑定当前教师有权管理的课堂，且目标目录必须是教师可写文件夹。
3. 考核登分表只允许使用当前课堂已绑定试卷的考试：
   - 试卷必须能解析出大题及满分；
   - 课堂必须有在读学生；
   - 至少一名在读学生已经得到考试总分；
   - 未评分学生保留学号、姓名，成绩留空，并形成聚合警告。
4. 大题分必须与最终总分一致。迟交、小组互评等导致卷面分与最终分不一致时，按既定规则分摊到大题，并在工作簿隐藏核验页保留卷面分、最终分、调整值和原因。
5. 负分按 0 分处理，超过试卷满分的成绩按满分处理并记录警告；不允许以 500 错误暴露可预期的脏数据。
6. 生成使用确定性本地逻辑，不调用 AI 猜测成绩，不生成供用户处理的中间文件。

## 三、Excel 交付标准

1. 主表固定为学校考核登分表结构：标题、课程/班级/教师信息、序号、学号、姓名、大题、总分。
2. 使用明确的中文字体及东亚字符集；标题、元数据、表头和正文的字号、粗细、对齐、边框保持一致。
3. 学号按文本保存，成绩按整数保存；总分由大题单元格公式计算，不能硬编码为不可追踪结果。
4. 大题单元格使用 0 至该题满分的数据验证，避免后续手工修改越界。
5. A4 纵向、固定页边距、横向居中、宽度缩放为一页；每 25 名学生人工分页，后续页重复第 1 至 4 行标题和表头。
6. 冻结标题行和学生身份列，隐藏网格线，设置打印区域和“第 n 页 / 共 n 页”页脚。
7. 工作簿打开时自动重算公式；导入同类工作簿时仍能从大题分恢复总分，不依赖已有公式缓存。
8. 每次改动必须实际生成代表性工作簿，检查公式、字体、合并单元格、打印设置、分页和至少一次可视化渲染。

## 四、材料与兼容性

1. 最终材料沿用统一 `final_material` 契约、材料包、查询字段和按需 Excel 导出链路。
2. 后台解析记录和材料正文用于预览、检索、审计与重新导出，但不得额外占用用户列表的一行。
3. Excel 导入、课堂生成、预览和导出必须归一到同一份 `export_payload`，避免同一材料在不同入口产生不同结果。
4. 保持 SQLite/PostgreSQL 查询兼容、普通学生行为不变、既有课堂内生成入口可继续使用。

## 五、发布门槛

1. 服务层、页面契约、JavaScript 语法和相关回归测试全部通过。
2. 代表性 Excel 通过内容检查、公式错误扫描和实际渲染检查。
3. 部署前运行 DryRun；正式部署后核对公开健康检查、发布版本和关键页面静态资源。
4. 提交只包含本功能相关文件，推送后本地 `HEAD`、远端分支和生产发布版本可追溯。

# 职业发展与简历改造实施记录

本文件记录实施状态，配合 `career-development-audit-and-plan-2026-09-06.md` 使用。原调查报告保持为实施前证据；这里不会把隔离测试、模型 stub 或桌面机器的结果写成生产容量承诺。

当前处于本地集成与验收阶段，尚未部署。已只读核验官方校招来源并准备候选；学校优先接入来源和人工专业评审仍未指定。生产环境没有导入合成或候选职位。

## 已实现的业务和技术边界

- 新专业立即提供按专业族划分的基础方向、问卷与简历入口。专业知识增强异步执行；GET 不入队、不重置失败预算、不更新学生会话。
- 职业与简历共用已有 `ai_jobs` 账本，注册领域处理器，使用租约、持久候选、业务 revision CAS 和原子发布。结果保存与发布分离，取消、重测、资料更新后旧结果不能成为当前版本。
- `CAREER_JOBS_ENABLED` 独立控制本领域，不连带开启既有批改 worker。AI 默认并发 1、可配置至 2，渲染并发 1；跨进程数据库准入、学生限额、总排队上限、公平轮转和等待老化。超时/运行中取消后共享保留冷却名额。
- 个人推荐使用明确答卷、资料证据、城市/目标偏好、收藏/屏蔽与毕业阶段。求职意向不算能力，否定材料不算正向技能；结果输入带版本哈希，隐藏支持档案不进入推荐。
- 专业别名以受控职业映射表达，不伪造官方专业代码。图谱结构严格校验，稳定方向 ID、网络历史、候选切换与显式恢复保持关联。
- 新旧图谱经过统一公开投影：不直接展示无来源薪资、招聘增长或固定晋升年限；保留原始历史、方向 ID、连线和收藏。公开投影版本使旧缓存与旧 AI 建议失效。
- 网络生成采用紧凑合同：模型只提供方向、准备项和关系，稳定方向 ID、阶段与通用说明由平台生成。历史同名按 NFKC 规范化保留 ID，新名称生成新 ID；模型复制长 ID 不再影响生成或转移收藏，不能明确映射的历史反馈保留待核对。先使用快速模型，只有上一次执行因结构错误失败才升级推理；限流、断网和超时不自动升级。展开前限制集合大小、规范化名称去重，拒绝无效局部 tag 和连线；已存完整网络仍严格校验 ID。
- 真实职位设施要求来源、原始链接、地点、检查时间、失效时间、状态与 JD 版本，支持幂等管理导入、分页、到期过滤及保存个人目标。没有真实来源时保持空态，方向搜索不称为在招职位。
- 资格匹配增加提取覆盖守门：复杂毕业区间、首次就业、语言分数与等效证明等未支持的条件明确为待确认，不进入 confirmed；证书备选条件不误当作全部必需。明确单一年份且全部已填毕业年份不符时才提示已知届次差距。
- 简历草稿允许不完整保存；修改使用 revision，候选需学生确认，历史恢复产生新版本。预览、导出与投递使用固定内容版本，原材料删除不抹去已有快照。
- 导入先保留原件和候选，按学生选择的字段/材料应用，冲突不静默覆盖。附件、头像、原件和不可变快照均纳入文件引用保护；新引用绑定使用同 hash 的事务锁。由于全站旧富文本/Git/历史快照的引用尚不能穷尽，逻辑删除后保留共享字节，当前不自动物理回收，不虚报释放空间。
- 全部经历类型使用共享注册表；既有八类保留，增加全职工作。材料证明附件仍在资料管理中单独访问，不自动作为简历正文图片；头像随简历渲染。
- 所有 Office 转换共用跨进程容量槽，默认 1。工作进程死亡后，持久槽记录仍保护存活的已验证转换子树；超过原截止时间后核验归属并清理。忙状态保持 429/Retry-After 或持久任务退避，不改走不受限的 Office 分支。
- 队列聚合在维护线程每约 60 秒刷新，健康接口只读内存。活跃队列和最近任务/尝试均有采样上限、截断及过期标识；无样本不冒称成功率 100%。

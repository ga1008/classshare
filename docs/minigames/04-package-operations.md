# HTML 小游戏管理、流式包验收、隔离内容网关与运维恢复

**实施说明。** 当前内容站逐次核对权威会话、受众、版本和文件清单，通过 ASGI 持跨进程共享读锁发送文件，直至发送结束。Nginx 负责 TLS、凭据剥离和日志脱敏。以下涉及 `X-Accel-Redirect` 的设计属于候选加速路径，启用前需要证明代理发送期间可保存同等的读锁与删除语义。教师上传、发布、回滚、删除及备份恢复以[接入与验收](06-run-and-verify.md)和[本轮实施记录](07-implementation-acceptance.md)为准。

本章规定教师从上传 ZIP 到隔离验收、发布升级、秒级下架与净室彻底删除的服务端工程契约，特别是面向共享教学服务器（2c/4G）的**权威授权后交给 Nginx 投递文件，以及通过撤权验证后可启用的 HMAC 快速路径**、**无源沙盒（Opaque Origin）CORS/CSP 精确配对**与**受限浏览器试跑防雪崩机制**。

## 1. 教师管理权限边界与两层状态机

### 1.1 管理权限铁律
- 管理页面 `/manage/library/games*` 与管理 API `/api/games/v1/admin/*` 仅向在职教师开放（`require_teacher_domain("library")`）。
- 单款游戏的后台读写、候选版预览、上下架与删除仅限该游戏归属教师及具有全站资源代管权的在职超级管理员。先核验第三章的真人 Web 会话及教师域权限，再调用 `teacher_can_manage_owned_row(conn, teacher_id, game, owner_key="owner_teacher_id")`。显式指定归属列，防止普通归属教师被默认的 `teacher_id` 列误拒。预览使用独立的合成席位、进度、历史和消息，玩家大厅与正式统计均仅查正式数据。[管理权源码](../../classroom_app/services/resource_access_service.py)
- 学生访问管理 API 返回 `403`；无管理权的其他教师访问他人游戏管理接口统一返回 `404`（不暴露草稿存在性）。教师以普通玩家身份在 `/games` 游玩他人游戏时，严格按玩家可见范围核验。

### 1.2 游戏与版本双层不可变状态机

| 实体 | 状态迁移 | 原子提交条件与对外效果 |
|---|---|---|
| **游戏 `games`** | 新建 → `draft` | 允许先建空草稿或由首次 ZIP 上传自动创建；未绑定首个 `ready` 版本前 `game_key` 待定且不可发布。 |
| **游戏 `games`** | `draft / unlisted` → `listed` | 锁定游戏行，核验 `expectedRevision`、所选版本 `ready`、受众策略非空（指定课堂/班级时目标有效）、存档谱系兼容；更新 `current_version_id`、递增 `policy_revision` 并同事务写管理审计。 |
| **游戏 `games`** | `listed` → `listed`（升级/回滚） | 切换 `current_version_id` 指针并递增 `policy_revision`；历史版本物理目录保持只读不可变。自动取消旧版排队票与未开局倒计时房；仍在运行且玩家仍具资格的对局允许在原锁定版本自然完赛。 |
| **游戏 `games`** | `listed` → `unlisted`（下架） | 递增 `policy_revision`、撤销全部活跃启动租约、终止排队与在途单人/多人对局；**完整保留已确认的玩家存档、游玩历史与版本包**，支持随时重新上架。 |
| **游戏 `games`** | `draft / listed / unlisted` → `deleting` → `deleted` | 经影响快照与二次确认后封禁访问及迟到写入。已绑定游戏手输 `gameKey`，空草稿或首包仍在验收时手输界面显示的固定草稿标识 `draft-<gameId>`。清理作业逐项核销独占文件与业务行后提交终态并保留脱敏登记。 |
| **版本 `game_versions`** | 上传接收完 → `validating` → `ready / rejected` | 唯独全部通过五步流式解包、Schema/规则图校验与隔离浏览器试跑的版本可置 `ready`。同一游戏下已 `ready` 的 `release_version` 永久绑定唯一内容指纹；仅 `rejected` 的版本号允许修正后以新幂等键重传。 |
| **版本 `game_versions`** | `ready` → `retired` | 停用非当前发布且无任何活跃对局/租约引用的旧版本（若仍有在途对局返回 `409` 及引用计数）。 |
| **校验作业 `mg_admin_jobs`** | `queued` → `running` → `waiting_probe` → `running` → `succeeded / rejected` | 阶段一持久保存原 ZIP、静态检查结果及资源清单。执行器未配置时释放工作器；已配置但离线时所有包共用两分钟退避。浏览器校验成功前，版本保持 `validating`，只有教师可看作业，不能预览或发布。删除草稿会同时清理等待中的包。 |

### 1.3 管理 API 一览（前缀 `/api/games/v1/admin`）

所有写请求均须通过同源与会话校验，并携带 `Idempotency-Key`（修改既有游戏另带 `expectedRevision`）：

| 方法与路径 | 职责 | 成功状态与返回摘要 |
|---|---|---|
| `GET /games`、`GET /games/{id}` | 按管理权限分页检索、筛选，读取游戏详情、版本列表与活跃对局统计 | `200` 游标列表或完整详情 |
| `POST /games`、`PATCH /games/{id}` | 创建草稿；修改展示标题、简介、精选、规范化标签、受众范围与修为闭区间 `[minTier, maxTier]` | `201 / 200` 最新 `revision`、策略自然语言摘要 |
| `POST /games/{id}/versions` | 流式接收单个 `.zip`，落暂存区并入队持久校验作业。教师点「上传新游戏」时，页面先以稳定请求键调用 `POST /games` 创建草稿，再以返回的 ID 走同一个版本接口。中断重试沿用草稿 ID，两步对教师呈现为一次上传操作。 | `202` `versionId, jobId`（支持关页重进恢复进度） |
| `GET /games/{id}/versions/{vid}`、`GET /jobs/{jobId}` | 查询五阶段校验进度、结构化阻断错误（精确到包内相对路径与 JSON 字段路径）及试跑摘要 | `200` 阶段状态、报告明细 |
| `POST /games/{id}/versions/{vid}/preview` | 为当前管理教师签发指向候选 `ready` 版本的隔离预览租约（独立 `preview:` 命名空间） | `201` 预览宿主 URL 与短期过期时间 |
| `POST /games/{id}/versions/{vid}/playtests` | 对尚需人工复核的玩法登记预览结果。绑定教师、预览会话、包指纹、校验器版本、被测模式/实际人数、场景和结果。服务端核对预览中发生的相应启动/完成事件。离线通关使用隔离工具的运行结果。自动试验已覆盖的场景直接复用同指纹证据。 | `201` 验收记录与尚缺场景列表；保留失败记录，禁止它被新的成功回执静默覆盖 |
| `POST /games/{id}/publish`、`POST /games/{id}/unlist`、`POST /games/{id}/versions/{vid}/retire` | 发布/兼容回滚指定 `versionId`；整款下架；归档无引用旧版本 | `200` 最新状态、受影响队列/房间处理摘要 |
| `POST /games/{id}/deletion-plans`、`DELETE /games/{id}` | 第一步生成实时影响清单与短期确认令牌；第二步凭确认令牌、手输 `gameKey` 与 `expectedRevision` 启动净室删除作业 | `200` 影响快照 / `202` 删除清理 `jobId` |

管理命令的请求键按 **真人账号、动作与目标对象** 隔离，并绑定服务端复算的正文或 ZIP 字节摘要。同键重试认回原草稿、版本或删除作业，同键异载荷返回 `409`。成功提交但响应丢失时先查回执，再判断修订冲突，避免重复操作。回放前仍核验调用者管理权。删除完成后的发起人/在职代管人可读取最小删除回执。其他主体及生产玩家继续得到统一的不可用响应。

#### 发布、旧局与回滚的事务边界

- 发布前在事务外核验只读目录和文件摘要，在游戏栅栏的短事务内重读目标版本、已验证清单指纹、校验器/SDK 版本、目标范围、存档兼容结论及原游戏修订。草稿属性的技术修订与玩家策略代次分别维护，避免一次纯文案保存误撤全站游戏租约。版本记录采用唯一绑定 `(game_id, release_version)` 的已验收指纹，拒绝稿及重试作业保留各自 ID。两个校验工作器抢首包或同号异包时，只能产生一次有效绑定与一套计费资产。
- 切换当前版本时，旧版尚未开局的随机票、等待私房及倒计时统一关闭，释放占位并取消房码。仅已开局、仍有资格且版本为 `ready` 的参与者可得到绑定原 `runId/versionId` 的新代次资源许可。重新进入大厅和新开局一律使用当前版本。达到 `retired` 或 `deleting` 后，旧回执、内容缓存与恢复任务都不能建立新会话。
- 同一 `(series, saveVersion)` 仅允许向后兼容的字段和里程碑增补。发布必须同时检查在玩旧客户端可能提交的写入。宿主按锁定版本做字段白名单受控合并，保存旧客户端不认识的新增字段，公共进度只取已确认最高值。无法安全合并时，先排空旧局再切版。回滚检查新旧协议、已提交的最高 rank、可读私档字段和所有在玩新版本的可能写回。兼容性不能确定时保持当前版或由教师下架修复。确需更换谱系/结构时单列新版本档位，保留旧档并在发布预览说明可恢复边界，跨谱系迁移仅由平台登记的幂等转换执行。
- 下架提交即使所有正常玩家会话及写请求失效。提交前成功落库的存档保留，提交后到达的旧代次写入返回失效，包括重新上架后重放的离线请求。在线宿主卸载子帧并显示最后确认的检查点。下架保留教师对 `ready` 版本重新授予独立预览的权利。权限范围缩小时只终止失去资格的参与者及按第三章规则应中断的房间。所有发布、属性更新、排队终止和下架均以同事务的持久事件驱动目录/宿主更新，消息丢失后重连读取当前状态。

## 2. 五阶段流式上传、契约审计与受限试跑管道

### 2.1 配额与允许的静态媒体白名单

针对共享教学主机设定 V1 边界（服务端统一通过配置下发给前端 `lq_upload` 展示；Nginx 对上传路由单独设定 `client_max_body_size 72m` 以留出 multipart 头部余量）：
- **体积与数量配额**：压缩 ZIP ≤ `64 MiB`，解压总字节 ≤ `192 MiB`，单文件 ≤ `32 MiB`，常规文件数 ≤ `1,000`，ZIP 目录项总数 ≤ `2,000`，规范化相对路径长度 ≤ `240` UTF-8 字节、目录深度 ≤ `16` 层；单教师并发暂存与总存储配额在接收前原子预扣，失败即退还。
- **静态资源白名单（扩展名 + 文件魔数嗅探双验）**：
  - 入口与代码：根级唯一 HTML `main.html`（`text/html; charset=utf-8`）、`js/**/*.js`（classic `text/javascript; charset=utf-8`）、`css/**/*.css`（`text/css; charset=utf-8`）、根 `config.json` 与 `contracts/*.json`。
  - `static/**` 素材：图像 `png / jpg / jpeg / webp / gif`、音频 `mp3 / ogg / wav`、视频 `mp4 / webm`、字体 `woff2`（`font/woff2`），以及**纯数据 `static/**/*.json`（`application/json; charset=utf-8`，供关卡地图、骨骼动画与图集帧配置使用，校验合法 UTF-8 JSON 且递归层数 ≤ 16）**。
  - 图标 `config.icon`：限 `static/` 下的 `png` 或 `webp`，尺寸 `128×128` 至 `1024×1024`（像素总数 ≤ `1,048,576`），验收通过时由平台安全解码并重编码生成无元数据的大厅静态缩略图（`160×160` WebP/PNG）。
  - 其余可执行文件、嵌套压缩包、SVG 脚本载体、额外 `.html` 页面、Service Worker 或外链 URL 一律阻断并报出精确文件路径。

### 2.2 五步流水线与 2c/4G 试跑防雪崩控制

1. **流式分块接收（零长事务）**：写入 `DATA_ROOT/games/staging/<job_id>/upload.zip`，边收边算压缩体积与 SHA-256，超限立即断流回收暂存目录，期间不占用数据库连接。
2. **中央目录预检（防 Zip Slip / Zip Bomb）**：拒绝加密、符号链接、硬链接、设备文件、`..` 越界、控制字符、Windows 保留文件名（`CON/NUL/AUX` 等）以及 Unicode NFC 归一加大小写折叠（`casefold`）后的重名冲突。若整包仅包裹在一层同名顶层文件夹内，自动安全剥离该单层外壳。
3. **有界流式解包与确定性整包指纹**：逐条目按实际解压字节上限与最大压缩比阈值流式写出，核对 CRC，生成每文件的 `(canonical_path, byte_size, verified_mime, sha256)` 清单；按 `canonical_path` 排序计算确定性包摘要（忽略打包时间戳差异）。
4. **静态契约、依赖图与规则可达性审计**：
   - 使用平台内置 Schema 校验 `config.json`、`contracts/writeback.json` 与 `contracts/rules.json`（含 `finite-turn-v1` 与 `grid-line-v1` 统一分发），绝不解析外部 `$ref`。
   - 核验 `js/lan-game-sdk.v1.js` 的字节 SHA-256 与平台发行版完全一致；以固定前缀剥离方式解析 `js/offline-contracts.js` 中的 JSON（**严禁在服务端 `eval` 执行 JS**），确认与包内三份 JSON 逐值相等。
   - 扫描 `main.html` 与 `css/**/*.css` 的静态引用及 `config.assets` 声明，拦截任何缺失文件、大小写不符或 `http(s)://` 外链依赖。
   - **跨字段与玩法公平性检查。** 校验 `minPlayers <= maxPlayers`、`randomSizes` 落在闭区间内，棋盘规则的 `line <= size`（错误码 `E_RULES_LINE_EXCEEDS_SIZE`）。有限状态图按 `(node, highestRank)` 有界验证无死胡同或里程碑跳级。对纯轮流玩法，若从**初始章节全新开局**即不可能轮到所声明的全部席位，给出证据（状态、合法步数、涉及席位）及单独的公平性诊断。从高进度续关可能只余一步，须允许按共同进度恢复。仅凭最短路径很短、出现 `actor:any`，或某人选择不操作，不能证明某席位必然不可参与。可证明被排除的初始必轮流席位阻断，其他可选短路线仅记 `W_RULES_IDLE_SEAT` 供试玩复核。
5. **资源受限的隔离无头浏览器试运行（保护课堂主机内存）**：
   - 试跑在专用低优先级执行器进行，全站同时运行一份，一次启动探针的初始预算为 512 MiB 内存和 20 秒墙钟时间。浏览器使用非特权用户并保持其进程沙盒；启动时检查实际隔离与资源上限，容器仅挂载本次只读包和独占临时目录，禁用宿主机网络及生产凭据。宿主不能提供该隔离时把作业交给独立执行器或保持排队。不得为通过探针关掉浏览器沙盒。资源不足、超时、工作器失联标记为基础设施可重试，稳定复现的包内错误才判 `rejected`。同时验证资源上限和课堂延迟目标，记录实测数值。
   - 试跑进程仅挂载本地回环只读内容桩与模拟宿主（无任何业务库连接、Cookie 或模型密钥），自动验证：① 平台模式 `MessageChannel` 握手、`ready()`、首屏渲染无未捕获异常、零外网请求；② `file://` / 离线模式加载 `offline-contracts.js` 正常启动；③ 图标、字体、音频与 `static/*.json` 零 `404` / 零 `CORS` 报错。
   - 全部通过后，关闭全部文件句柄，同卷原子 `rename` 至只读 `DATA_ROOT/games/versions/<game_id>/<version_id>/`，再以短事务提交 `game_versions.status = 'ready'`。

**试跑的结果分两层。** 20 秒启动探针覆盖加载、握手和资源访问。每个声明的玩法还要通过受限合成场景或教师在隔离预览中的验收步骤，实际离线完成一局、在线验证最小/最大席位和随机目标、合法回写及刷新恢复。单人包可无 `rules.json`，这时离线契约的 `rules` 必须是 `null`。对依赖 `static/*.json`、Web Audio 或需读像素的包，要在真正的 `file://` 环境验证离线资源分支，例如把关卡数据构建进本地 classic JS，并以可用的本地媒体方式播放。平台 `fetch` 正常不能替代这项检查。启动/结构通过且字节封存后才可 `ready` 并开展人工预览。每条声明玩法的验收凭据关联同一候选指纹，发布门禁检查凭据齐全，AI 文本不能代签。

**持久任务与磁盘收尾。** 接收前登记独占路径、配额、作业与输入摘要，区分“收到 ZIP”“排队”“进行中”“待重试”“已通过/规则拒绝”。校验与清理领取采用租期、唯一 claim token 和条件提交。每一代工作器使用独占的尝试目录，旧 token 失效后禁止写入公共版本、提交状态或释放新作业配额。发布磁盘改名由按版本互斥的协调器执行，依次核验仍有效的作业、完整文件清单及 `deleting` 状态。成功改名与数据库确认之间中断时，仅用账本定位已有目录并比对指纹，幂等认领或安排该目录的清理。路径已被其他归属使用则隔离待核对。退出前停止本代子进程、关闭全部句柄后释放预留配额或转为实际占用。断流且摘要不同的重传须换请求键。材料 ZIP 辅助函数会一次返回全部文件字节，游戏流程应复用路径/格式边界并单独实现按块落盘。[ZIP 读取](../../classroom_app/services/material_zip_service.py) · [教师题包导入](../../classroom_app/services/project_topic_package_service.py) · [持久调度任务租期与条件提交](../../classroom_app/services/scheduled_task_service.py)

## 3. 无查库高性能内容交付网关、Opaque CORS 与沙盒隔离

### 3.1 双层部署隔离模式（兼顾公网多域名与单备案/校园局域网）

为彻底阻断上传包内的任意 JS 读取平台 `access_token` 或调用教师管理接口，平台实行严格的**内容源隔离契约**：

- **Tier-1 推荐生产模式（独立可注册域）**：内容站部署在独立可注册 HTTPS 域名（如 `https://lanshare-sandbox.example.cn`，与主站 `guardianangel.net.cn` 不同 eTLD+1），天然完全隔离一切同站凭据。
- **Tier-2 专用子域 / 校园内网隔离模式。** 可选同一可注册域下的专用 HTTPS 主机名（如 `games-content.guardianangel.net.cn`），内网和本机 E2E 同样使用两个不同的受控主机名。Cookie 按主机与路径匹配，同一主机名仅换端口仍会把主站 Cookie 发送到内容端点。启动自检必须全部验明以下四项，任一失败即保持小游戏启动关闭。
  1. 主站 `dependencies.apply_access_token_cookie` 与续登凭据严格为 **Host-Only Cookie**（绝不设置 `Domain=.guardianangel.net.cn`）；
  2. 内容源 Nginx `server` 块不代理任何主站 `/api` 或模板路由，并在入口无条件清空凭据头：`proxy_set_header Cookie ""; proxy_set_header Authorization "";`；
  3. 所有 HTML 响应强制下发 HTTP 头 `Content-Security-Policy: sandbox allow-scripts; ...` 与 `Origin-Agent-Cluster: ?1`，即使玩家把内容 URL 直接粘贴到浏览器顶层地址栏打开，文档依然被浏览器锁死在**不透明唯一源（Opaque Origin `null`）**，无法读写同域 Storage/Cookie；
  4. 父页 `<iframe sandbox="allow-scripts" referrerpolicy="no-referrer">` 永不授予 `allow-same-origin`、`allow-forms`、`allow-popups` 或 `allow-top-navigation`。

### 3.2 短期 HMAC 租约、跨进程撤销与 Nginx 文件投递

首版正确性基线是**逐资源权威鉴权后交给 Nginx 发送正文**。对 40 个素材的游戏，优化目标是降低百人集中打开时的数据库压力。只有实验证明所有相关撤权入口、故障恢复和跨进程一致性均覆盖后，才可为相应用途开启免逐文件查库的快速路径。下文的准入协调器与变更事件属于拟建优化，现有课堂和登录写操作尚未接入。两条路径使用同一份包、稳定内容 URL、资源清单和撤权规则。

1. **路径稳定，授权限时。** 按第三章的 `POST /games/{gameId}/launches` 确认真人、活动会话、用途、版本与权限。返回 `/l/<handle>/main.html`，handle 为每次启动独立生成的至少 128 位随机不透明值。网关用其摘要索引当前服务端签发的 HMAC 凭据，签名绑定 `kid, handle_digest, lease_id, actor_digest, session_binding, game_id, version_id, purpose, run_id?, policy_revision, authorization_epoch, exp`。90 秒票据只留在授权服务与网关，宿主提前 30 秒经 `POST /launches/{leaseId}/renew` 重新鉴权并替换当前已签票据，相对 URL 全程稳定。任何到期、已撤销或换号的旧租约不得续活，重新启动取得新 handle。允许的用途及文件权限写入签名。预览不共享玩家 handle。轮换密钥限定 `kid`、最迟过期/吊销时刻，不回退接纳未知密钥。
2. **每个新资源请求均过授权。** 仅开放 GET、HEAD，处理 Range、条件请求及错误路径时执行同一校验。拒绝非空查询字符串。先验签、有效期、会话和最新代次，再按不可变 `version_id → canonical_path → (verified_mime, digest, size)` 清单精确查找。LRU 可缓存在版本内不会变化的文件信息。动态准入由下面同机权威服务判定。文件服务与各层代理、错误日志、追踪系统需为外部 `/l/` 和内部文件路径配置脱敏。现有 Nginx map 仅特判材料路径，接入时须新增游戏规则并以真实代理日志核验。[现有网关](../../nginx.conf)
3. **Nginx 投递。** 通过检查后，以清单中的服务端游戏、版本和文件标识生成 `X-Accel-Redirect`，客户端路径字符串不能直接用作内部目标。只读卷只暴露已验收版本的运行树，原 ZIP、暂存/预览和清理目录不得映射。内部 location 显式设置 `internal`、准确 MIME、CORS、CSP、no-store 等最终响应头，直接外部访问拒绝。大文件正文由 Nginx 投递，应用不读取字节。无 Nginx 的隔离开发环境可走相同授权的 `FileResponse`。确认 Nginx 实际发出的 200/206/304/416 响应及 Range 上限、并发与连接关闭，分别记录生产投递和开发回退的开销。

#### 可撤销的资源准入

- 同机所有网关进程通过受保护的本地 IPC 访问**唯一准入协调器**。协调器在内存中持有按游戏/版本、主体/会话、用途的当前代次、关栅状态和有效票据。进程各自每秒轮询或仅靠通知无法保证提交边界。采用单写者实例、启动代数和排他所有权，任意一个对外请求均需从当前实例取得放行判定。已发到 Nginx 的请求算作已准入。每次判定仅持短暂读锁，放行后不为整条媒体连接持锁。
- 下架、删除、换版、缩小受众以及账号登出、换会话、退学/离职、转班、撤销选课、组织或修为资格变化，均须经过相应作用域的变更入口。在业务提交前，协调器**先关闭受影响域的内容准入**并排空正在作出决定的短读操作。随后权威事务获取第三章规定的游戏/账号等锁，更新必要的业务或会话状态、修订和不可重用的操作 ID，同事务写持久变更事件。事务内不等待网络或执行文件 I/O。提交后按新修订重新安装仍有权的票据（含合格旧版在局成员），提交确认后才开放受影响域。未受影响的游戏与主体可继续读。持久事件去重按对象修订和操作 ID，不以时间戳或未提交事务的序号大小推断“所有更早事件均已完成”。
- 写入失败、连接断开导致结果未明、变更乱序或协调器重启时，相关域保持关闭。重启先阻断所有内存准入，以一致的已提交数据库快照重建租约/撤销、策略和未完成变更，再逐域追赶变更事件、校验代次后准备就绪。用数据库事务/屏障建立快照与事件读取的交接点；落后或身份未明的实例禁止接流。关闭已成功而业务事务失败时，查明事务已回滚且无新变更后才恢复原代次。预提交关闭窗口不计为最终下架，管理接口未知提交结果时用原请求键查回执。
- **权威回退。** 若某个非游戏业务写入口无法接入预关闭流程、部署跨主机、协调器失效或不能证明同步完整，必须禁用相应快速路径。使用逐请求权威鉴权，在有界执行器中检查登录、最新游戏/版本策略与成员资格，再交给 Nginx 投递。无法完成权威查询时禁止交付。快速路径与逐请求鉴权分别压测和报告，不能以缓存陈旧的一秒宽限替代。全站登出与课堂变更无需等待图库重建。上线前核对所有可以改变玩家资格的实际写入口。
- **截止点。** 权威事务提交后，所有新的授权与业务写入受新状态约束。此前已获放行并开始传输的音视频字节可能继续到该次请求结束，已有浏览器缓存/离线副本无法召回。下架由宿主立即移除媒体与 iframe，并拒绝新的 Range。物理删除须另等待已有交付关闭、释放文件描述符后复核实际清理，不能拿“放行查询返回 0”充当物理删除证明。

### 3.3 关键兼容细节：`sandbox="allow-scripts"` 下的 Opaque Origin CORS 与 CSP 配对

在 `sandbox="allow-scripts"` 子帧内，文档 origin 为不透明的 `"null"`。根据浏览器标准，子帧加载同包 `@font-face` WOFF2 字体、使用 Web Audio API `fetch("./static/sfx.mp3")`、读取关卡数据 `fetch("./static/level1.json")` 或在 `<canvas>` 上对 `<img crossorigin="anonymous">` 执行像素读取时，浏览器发出的请求均带有 `Origin: null` 且强制执行 CORS 检查（参见仓库已有先例 [`project_topics.py`](../../classroom_app/routers/project_topics.py) 第 261 行）！

因此，内容网关对有效租约下的响应必须精确下发以下响应头组合：

- **通用安全头（全部响应）**：
  - `Cache-Control: private, no-store`
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: no-referrer`
  - `Cross-Origin-Resource-Policy: cross-origin`
  - `Origin-Agent-Cluster: ?1`
- **子资源 CORS 头（`js/*`、`css/*`、`static/*` 响应）**：
  - `Access-Control-Allow-Origin: null` 仅随有权读取的包子资源返回，配合无凭据请求。多种独立沙盒都可能产生 `Origin: null`，授权仍须逐一核对路径 handle、当前资格与精确文件。平台业务 API 不向该来源开放 CORS。不要设置 `Access-Control-Allow-Credentials: true`。
- **`main.html` 精确 CSP 头**（`<CONTENT_ORIGIN>` 与 `<HOST_ORIGIN>` 取部署实值）：
  ```http
  Content-Security-Policy: sandbox allow-scripts; default-src 'none'; script-src <CONTENT_ORIGIN>; style-src <CONTENT_ORIGIN> 'unsafe-inline'; img-src <CONTENT_ORIGIN> data: blob:; media-src <CONTENT_ORIGIN> blob:; font-src <CONTENT_ORIGIN> data:; connect-src <CONTENT_ORIGIN>; frame-ancestors <HOST_ORIGIN>; base-uri 'none'; form-action 'none'; object-src 'none'; worker-src 'none'
  ```

上述头需在两档部署中的最终交付端验证。内容站只接受配置的 Host/SNI，所有代理层与内部文件投递位置均不得设置业务 Cookie 或转发到主站登录。可信父页的 `frame-src` 精确限于内容源，子帧首次握手后发生导航即关闭旧端口。显示在大厅的缩略图也必须通过该玩家的可见范围鉴权。用户可离线传播自己已获得的包，日志测试核验的是平台能够控制的请求路径、查询和凭据记录。

## 4. 独占资产账本、净室彻底删除与备份恢复

1. **物理独占命名空间（零跨游戏共享耦合）**：
   - 全部小游戏文件位于 `DATA_ROOT/games/` 下：`staging/<job_id>/`（临时接收与解包）、`versions/<game_id>/<version_id>/`（原包备份、只读运行树、清单与派生缩略图）、`preview/<job_id>/`（试跑瞬态目录）。
   - **严禁将小游戏素材并入全站 `DATA_ROOT/media/blobs/sha256` 去重池**：每款游戏独占自己的物理子树并逐项记入 `game_asset_ledger`，确保删除游戏 A 时绝不会误伤包含相同按钮音效或背景图的游戏 B。
2. **可重入分步彻底删除流程**：
   - 第一步 `POST /games/{id}/deletion-plans` 返回统计时刻、版本集合、磁盘字节、存档人数、对局及聊天条数。短期、一次性确认凭据绑定教师、游戏、当前修订、目标集合与处置范围。在线活动计数是快照，版本集合、管理权或处置范围变化须重新预览。取消到此结束。
   - 第二步 `DELETE /games/{id}` 检查凭据、确认文字和修订，按游戏排他栅栏在同一事务设置 `deleting`、递增策略代次、写 `game_deletion_register`、持久撤销通知及唯一清理作业。原请求键重试必须得到同一作业。教师界面仅显示“清理中”或准确失败项。再次上架、旧确认凭据、迟到的校验完成或对局结算均不能覆盖该状态。
   - 清理作业先等待或撤销在途上传/试跑租期，再仅对 `game_asset_ledger` 核实的 `DATA_ROOT/games/` 严格子路径执行删除（**拒绝符号链接/目录联接，严禁按目录名通配符或修改时间批量扫盘**），随后以分批短事务清空该 `game_id` 的存档、历史、队伍模板引用、房间、队聊、事件流、聚合热度与标签关联；
   - 数据库按外键依赖顺序分批清除。对仅含 `room_id / run_id / version_id / stream_id / job_id` 的子表，先封存所属 ID 并据此删除从属记录，再删父行。还须覆盖待配票、邀请码、个人最近、占位/租约、共享进度推进前快照、幂等回执正文、AI 与预览派生数据、缓存和检索投影。保留跨游戏账号、社交关系和其他游戏自己的素材。独占目录出现未登记的内容、符号链接、外部挂载或所有者不符时停止涉及的清理项，记录可核验对象，禁止为清空计数顺手删除未知文件。
   - 资源交付层须具备可证明的排空边界。为已准入的正文请求登记请求 ID，跟踪最终完成/取消回执，内部内容位置关闭长驻文件描述符缓存。工作器崩溃导致无法逐请求证明退出时隔离并排空**独立内容服务**的相关进程代次，验证读句柄释放。清理器每批记录高水位，重试只认同一归属与代次，异常保持 `deleting`。最终同时核验文件、在途句柄、在线数据与衍生索引归零，以及无作业可重新发布。最后一次短事务提交 `deleted`、按类别的零残留计数和最小处置回执。可保留内部游戏 ID、处置任务、受权操作人标识、时间和结果，回执无 ZIP、聊天、存档及玩家名单。
3. **旧备份恢复防复活守卫**：
   - 确认后生成的删除登记须以持久 outbox 投递至**独立于被恢复数据库/文件快照的受保护追加账本**，包括单调可校验的处置序列、游戏 ID、操作 ID、处置时间与封存水位。摘要必须能重建需清理的对象集合。`DELETE` 仅在独立账本确认后返回表示已受理的 `202`。若本地已封禁但独立存储一时不可用，返回可重试的 `503`、原操作 ID、任务查询地址与“正在确认登记”，保持封禁并按原键重试。按操作 ID 去重，可处理外部登记成功而响应丢失。后台只有在独立记录获得持久回执且在线清理验证完成时才报告彻底删除成功。保留登记覆盖最老可恢复副本及恢复窗口。教师确认页列出备份实际保留期限，隔离备份按既定期限到期清理。
   - 备份应成对保存数据库一致性时间点、该时点所引用的不可变游戏版本目录、文件清单/摘要及删除登记水位。已有部署代码备份明确排除 `data/`，数据库 dump 不包含游戏文件，须为游戏卷单独配置快照或逐清单备份。核实实际生成的备份、完整性摘要及测试恢复结果，部署日志中的“跳过备份”不能算作可恢复证明。[现有部署脚本](../../deployment/deploy_remote.ps1) · [数据库恢复演练](../../tools/db_backup_rollback.py)
   - 恢复先在独立服务、关闭内容和玩家流量的环境完成。重放从旧快照至最新封存水位间的全部删除记录，含已受理但尚在清理的游戏。检查登记连续性、在线行、文件和索引，丢弃旧内容租约并轮换服务启动代次。缺记录、找不到与数据库匹配的版本文件、权威资格不可核验时保留相应用途关闭。恢复不回退已受理的删除，不将课堂生产库作为游戏功能回滚的目标。

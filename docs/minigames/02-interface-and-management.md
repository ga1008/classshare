# 小游戏大厅、游戏宿主与教师工作台的交互设计

本章定义小游戏平台的页面路由、响应式布局、交互、无障碍与前端性能验收。设计沿用[液态玻璃组件开发合同](../lq-component-contract-2026-09-27.md)、[场景色调契约](../lq-scene-ink-2026-09-26.md)及[模板自适应规范](../lq-template-adaptive-2026-10-24.md)。以下页面、接口配合和指标是开发目标，取得正式构建的验收结果后再记录实测值。

## 1. 路由职责、现有模板锚点与页面壳选型

### 1.1 现有顶栏与侧栏的精确代码接入点

学生端截图中的「观点与交流」实为 `frontend/src/lib/blog-topbar.ts` 在无未读动态时写入 `[data-blog-topbar-caption]` 的副文案（有关注更新或今日新帖时会动态变为 `关注更新 N` 或 `今日新增 N 篇`）。因此，**严禁在运行时用 JS 查找“观点与交流”文本插槽**，必须在服务端 Jinja 模板中紧跟 `[data-blog-topbar-entry]` 节点之后输出真实 `<a href="/games">` 链接，标签固定为 **「小游戏」**：

1. **图标登记。** 实际入口复用已登记的 `play` 图标。声音控件提供文字状态及可访问名称。旧教师管理侧栏使用独立 `manage_icon` 映射，应明确委托到共享 `lq_icon` 或选已有登记图标。验收覆盖这两条渲染路径。热门排行用文字序号即可。
2. **全壳层同步挂载**：
   - `templates/partials/lq_navbar_topbar.html`：同时覆盖未折叠分支（第 39 行 `[data-blog-topbar-entry]` 后）与 `navbar_shell_condensed` 分支（第 70 行 `[data-blog-topbar-entry]` 后），调用 `{{ lq_btn('小游戏', href='/games', variant='ghost', icon='play', attrs={'data-games-topbar-entry': ''}) }}`。窄屏收纳进原生 `<dialog class="lq-shell-pane lq-topbar__overflow">`（「更多操作」）时自动保持「博客 → 小游戏」顺序，无需额外克隆节点。
   - `templates/partials/app_topbar_utility_actions.html`（旧版兼容顶栏）：紧接 `[data-blog-topbar-entry]` 后输出同构 `app-topbar-action` 玻璃链接（主标题 `小游戏`，副标题 `休闲与协作`）。
   - `templates/manage/lq_utility.html`（教师管理壳顶栏常用入口）：紧接 `[data-blog-topbar-entry]` 后输出 `size='sm'`、`variant='ghost'`、`icon='play'` 的「小游戏」入口，使教师在后台任意页均可一键切往玩家大厅。
   - `classroom_app/services/manage_nav_service.py`：在 `MANAGE_LIBRARY_DOMAIN` 的 `"教学资源"` 组新增 `ManageNavItem(key="games", domain=MANAGE_LIBRARY_DOMAIN, group="教学资源", label="小游戏管理", icon="play", href="/manage/library/games", search_text="小游戏 游戏 HTML 包 协作 对战 minigame game", ai_hint="小游戏：上传独立 HTML 小游戏包，经隔离验收与预览后按课堂、班级、组织范围及学生修为等级发布。")`。

### 1.2 为什么 `/games` 与 `/games/{slug}` 直接继承 `base.html` 而非 `base_navbar.html`

- `base_navbar.html` 会强制注入限宽 `.main-content.container`、学生密码弹窗以及移动端底部固定四格学习导航 `lq_app_bottomnav.html`，这既违背大厅的**全视口沉浸布局**，也会在 `/games/{slug}` 遮挡游戏底部操作区。
- `/games` 基于 `base.html` 复用全站主题令牌、六套配色、页面背景图层 `lq_page_backdrop.html` 与 Toast 容器，顶部采用共享 `lq_topbar`（`variant='standard'`）。
- `/games/{slug}` 同样基于 `base.html`，但在模板上下文中显式设置：
  - 拟为 `base.html` 增加默认关闭的宿主专用抑制参数。`suppress_page_backdrop` 为真时从服务端省略背景层及相关预加载，避免先下载照片再由 CSS 隐藏。当前基类直接 include `lq_page_backdrop.html`，只传变量尚不生效。
  - 在同一基类以 `suppress_back_to_top` 包住返回顶部按钮及其脚本。默认不设置上述参数，现有页面继续执行原有逻辑。
  - 使用 `ai_workspace_mount.html` 已支持的 `embedded_mode` 或其集中策略排除游戏宿主，涵盖 head 与 body 的工作区入口。核验宿主没有悬浮 AI 工具及其页面上下文采集，教师管理页的自愿验收解释可单独调用。

### 2.2 响应式空间断点与网格数学规范

全视口容器 `.lq-games-hall` 使用 `min-height: 100dvh`，内边距 `padding: var(--ls-s-3) clamp(var(--ls-s-3), 2.5vw, var(--ls-s-6)) calc(var(--ls-s-6) + env(safe-area-inset-bottom))`，无 `1280px` 窄盒限制，充分利用宽屏空间：

| 视口区间 | 主副栏结构 | 左侧游戏网格列宽策略 | 旁栏与导航自适应行为 |
|---|---|---|---|
| **宽屏桌面** `≥ 1280px` | 双栏 Grid `minmax(0, 18fr) minmax(0, 7fr)`，扣除栏间距后右栏占 28%。宽显示器不设使右栏跌破 25% 的固定像素上限。 | `repeat(auto-fill, minmax(148px, 1fr))`，间距 `var(--ls-s-4)`。列数由可用宽度决定。 | 右栏可 sticky，对齐实际顶栏高度。低高度、放大或内容换行时退回整页滚动，避免形成过矮的内滚区。 |
| **标准桌面 / 横屏平板** `960px – 1279px` | `minmax(0, 7fr) minmax(0, 3fr)`，右栏占轨道可用宽度的 30%。 | `repeat(auto-fill, minmax(136px, 1fr))`，间距 `var(--ls-s-3)`。 | 右栏保持并排；顶部次要操作进入现有的“更多”面板。 |
| **竖屏平板** `640px – 959px` | 单列纵向流：`minmax(0, 1fr)` | `repeat(auto-fill, minmax(132px, 1fr))`（4–5 列） | 筛选栏下方呈现页内快捷锚点胶囊（`最近游玩` · `热门` · `好友在玩` · `推荐`）；右栏四分区以 `2×2` 双列网格排在当前页目录与分页器下方。 |
| **手机窄屏** `320px – 639px` | 单列纵向流。 | `repeat(2, minmax(0, 1fr))`，允许游戏名换行。超大文字或缩放导致两列不再可读时切一列。 | 分页紧随目录，随后列出旁栏各区。触控目标至少 `44×44 CSS px`。布局以缩放后的实际可用宽度为准。 |

### 2.3 液态玻璃五层材质与场景墨色配对契约

为防止“白底白字”、“暗色外观叠亮背景照片发灰”以及“嵌套 `backdrop-filter` 拖垮旧核显”，大厅每个层级严格绑定单一材质职责：

| 区域 | 采用的 LQ 材质与类名 | 模糊宿主（`backdrop-filter`） | 前景墨色与降级规则 |
|---|---|---|---|
| **顶部导航栏** | `.lq-topbar.lq-glass`（`chrome` 层级） | 顶栏一个边界采样宿主。右侧边界如启用另计。 | 采用共享材质墨色。滚动产生遮挡时用 `.lq-scroll-edge`。 |
| **直接落在背景图上的分区标题 / 结果计数** | `.lq-on-scene`（无独立底板） | 否 | **必须使用 `--lq-scene-ink` / `--lq-scene-muted` 与 `--lq-scene-halo`**（随背景照片明暗切换），严禁直接写随系统深浅翻转的 `--ls-ink`。 |
| **搜索与模式筛选条** | `lq_filter_bar`、共享原生 `input[type="search"]` 及模式 Chip。 | 否。 | 搜索图标由共享 Input 绘制。需要跨浏览器「清空」时在 `.lq-search` 尾槽提供有名称的按钮，与已有浏览器清空行为去重。 |
| **游戏图标卡片** | 原生链接采用 `.lq-surface`，配图标、名称和装饰槽。列表专属布局置于页面 CSS，材质与可选背光配方登记在共享组件层。 | 否。 | 复用现有填充、边缘和前景令牌；支持关闭透明、Tier C、减少透明与强制色。预期更改和消费者以当前模块记录本为准。 |
| **右侧四分区旁栏** | 外层唯一载体 `<aside class="lq-games-aside lq-surface lq-surface--boundary">`；内部四个分区 `<section data-lq-surface="embedded">` + 紧凑横条列表 | 仅外层 `<aside>` 可选声明一次边界层，**内部所有分区与横条严禁重复声明模糊或实心框（消除“框套框”）** | 横条悬停使用 `--ls-surface-2` 轻柔过渡；所有小字与副文案实测对比度 **≥ 4.5∶1**。 |

### 2.4 游戏卡片、指针跟随背光与键盘焦点

每张游戏卡片在 DOM 中是**唯一一个原生可聚焦链接**，支持左键新标签打开、中键后台打开、右键复制链接、键盘 `Tab / Enter` 与读屏完整播报：

```html
<li class="lq-games-grid__item">
  <a class="lq-game-tile lq-surface"
     href="/games/beacon-relay"
     target="_blank"
     rel="noopener noreferrer"
     data-lq-interactive
     data-game-tile
     data-game-id="0193...">
    <span class="lq-game-tile__halo" aria-hidden="true"></span>
    <span class="lq-game-tile__icon-wrap" aria-hidden="true">
      <img class="lq-game-tile__icon"
           src="/api/games/v1/games/0193.../icon?v=1.0.0"
           alt=""
           width="80"
           height="80"
           loading="lazy"
           decoding="async">
    </span>
    <span class="lq-game-tile__title">航标接力</span>
    <span class="lq-game-tile__meta">单人 / 2–4 人合作</span>
  </a>
</li>
```

1. **图标光学质感（Squircle Jewel）**：
   - `.lq-game-tile__icon-wrap` 固定 `width: clamp(68px, 6vw, 84px); aspect-ratio: 1 / 1; margin-inline: auto; border-radius: 22.5%`（连续感圆角方标），内设 `box-shadow: inset 0 1px 0 hsl(var(--ls-glass-rim)), var(--ls-shadow-1)` 与 `overflow: clip`，上方留出 `var(--ls-s-4)` 呼吸空间。
   - SSR 输出确定的 `width="80" height="80"`，首屏预计可见行优先加载，其余使用 `loading="lazy" decoding="async"`。在网格根以捕获阶段监听图片 `error`（此事件不冒泡），替换为大小相同的共享 `play`。通过布局偏移归因验证成功／失败图标替换均不推动文字或相邻卡。
2. **标题与微元信息排版**：
   - **名称始终位于图标正下方**，使用 `var(--ls-t-callout)` 和共享字重令牌，最多两行，DOM 保留全名。截断时用共享 `bindTooltip` 支持指针和键盘焦点，触屏通过游戏详情标题查看全名。
   - 底部仅保留一行安静的玩法微标签 `.lq-game-tile__meta`（`var(--ls-t-caption)`，颜色 `hsl(var(--lq-material-muted, var(--ls-ink-2)))`），如 `单人`、`双人对战`、`单人 / 2–4 人合作`。目录整体仅放置一次 `sr-only` 说明文案「点击卡片将在新标签页打开游戏」，不在每张卡的 `aria-label` 里重复啰嗦。
3. **高性能 GPU 合成层指针跟随背光（Pointer Halo）**：
   - **严禁在 `pointermove` 中修改 `background: radial-gradient(circle at Xpx Ypx, ...)` 或 `left/top`**：动态渐变圆心会在 60/120Hz 下触发整卡逐帧光栅化重绘（Paint），在学校机房核显机型上造成明显掉帧。
   - 卡片内放置 `168px` 的装饰柔光盘，用固定渐变绘制，借 `transform` 平移；渐变采用有效的共享色值（如 `radial-gradient(circle, hsl(var(--ls-primary) / .24), transparent 70%)`），深浅色单独用主题令牌调节。父链接负责裁剪，装饰层 `pointer-events:none`，图标和文字位于其上。材质样式在共享 opt-in 配方中维护。
   - **单委托 + 单 `rAF` + 零静止开销生命周期**：
     - 整个网格容器 `[data-games-grid]` 仅挂载**一组**委托监听（`pointerover`、`pointermove`、`pointerout`），并在具备精细指针（`matchMedia('(hover: hover) and (pointer: fine)')`）且未开启减少动态/关闭玻璃/强制色/Tier C 时启用。
     - 仅在从另一张卡进入时测量该卡的视口边界；比较 `relatedTarget.closest('[data-game-tile]')` 或等价的包含关系，跨同卡子元素不会重复测量或闪烁。激活标志给当前卡，临时 `will-change` 仅在移动时赋给其柔光盘。
     - `pointermove` 只缓存视口坐标并预约一个动画帧。帧中按卡片左上角换算局部坐标后写 `transform`。几何有效时不读布局，不依赖浏览器对图层提升的具体选择。位置写入在主线程提交，实际合成开销需要用浏览器 trace 验证。
     - 滚动、尺寸变化或布局替换会使边界失效；下一帧先读一次最新矩形，再写位移。静止时不运行动画帧循环，结束移动后释放临时提升提示；移出、窗口失焦、页面隐藏、偏好变化或控制器销毁时清理帧、计时器和活动标志。减少动态、强制色、粗指针设备保留静态焦点／边界反馈。

### 2.5 四维旁栏与搜索状态合同

| 分区 | 视觉构成（单行高度 48–56px） | 数据与隐私规则 | 交互与空态 |
|---|---|---|---|
| **最近游玩** | `32×32` 圆角方标 + 游戏名 + 右侧微胶囊（如 `继续 · 海角` 或相对时间 `昨天`） | 当前真人账户实际进入 `running` 的游戏，按最近开局倒序去重（默认展示前 5 条，可展开“查看更多”）。 | 新标签打开 `/games/{slug}`。空态显示安静内联提示「玩过的游戏会出现在这里」。 |

| **为你推荐** | `32×32` 图标 + 游戏名 + 右侧真实来源 `lq_chip`（`size='sm'`：`教师精选` 或 `同标签 · 棋类`） | 优先当前可见的教师精选，其次匹配本人最近游玩标签，冷启动用可见热门/新作补齐，区内去重。 | 新标签打开游戏；无可推荐候选时整节优雅留空或显示精选空态。 |

- **搜索、分页与旁栏刷新。** `q / mode / tag` 和过滤条件对应的游标同步至 URL。条件改变回首页，翻页保留浏览器后退历史；游标失效提示并重置到该条件第一页。只有服务端提供总页数才显示「1 / 3」，否则显示「上一页 / 下一页」。中文输入法组合完成后才检索，`AbortController` 与请求代次防止旧结果覆盖。空目录、无搜索结果分别给出说明和清除筛选；失败保留已显示的本页，提供重试。侧栏各区独立恢复，支持手动刷新和切回前台重取。
- **游玩设置与好友动态。** 设置保存走 `PUT /me/preferences`，带修订号。保存失败保留昵称／分享草稿；并发冲突只重提本人刚修改的字段。界面分别编辑游戏昵称与「允许好友看到我在玩」，其中分享开关默认关闭。游戏昵称为空时使用平台允许展示的称呼，仍为空时用席位名。从撤回同意、屏蔽或权限变化提交起，后续读取和缓存均不再返回对应动态。已打开的大厅用带过期时间的短期展示快照：前台到期时先移除旧行，再按需批量刷新一次（展示有效期最多 60 秒，刷新采用提前抖动）；后台不发心跳，切回时先丢过期行再重取。请求失败也不延长旧行的展示期。可用的平台失效通知可提前触发刷新。SSR 和 API 都不得把越权游戏的图标 URL、总数或关系原因送到浏览器。已展示给对方的历史页面无法远程抹除。

1. **舞台比例与安全区适配（Stage Framing）**：
   - 宿主用 `minmax(0,1fr)` 分配顶栏剩余高度，避免将 44／52px 示意尺寸硬写为运行真值。考虑实际换行、缩放与安全区。舞台可用高度随当前设备可见区域变化，横竖屏切换不替换 iframe 实例。

     - `"free"`：`<iframe>` 铺满整个 `.lq-game-stage`（`width: 100%; height: 100%`）；
     - 固定比例支持 `16:9 / 4:3 / 1:1 / 3:4 / 9:16`。同时受可用宽与高约束，以能完整容纳的最大等比矩形居中；可用容器比例尺寸或 ResizeObserver 单次测量宽高计算。`stageTone` 选择平台登记的深／浅／随主题舞台色，一枚共享边缘足以区分画面与留白。画框限定外部尺寸，包内仍须自行适配控件、文字和 Canvas 分辨率。
   - **零二次模糊铁律**：`<iframe>` 自身及覆盖在其上方的父级容器不得声明 `filter` 或 `backdrop-filter`；仅宿主顶栏和按需打开的抽屉/弹窗在各自边界采样，确保子帧 60fps Canvas/WebGL 渲染不引发父页面合成重采样。

### 3.2 开局路径、选章重玩与组队微交互

| 宿主打开时的状态 | 首屏呈现与流畅闭环 |
|---|---|
| **本游戏已有本人活动** | 先读取本人活动，按当前 `queue / room / run` 权威快照恢复；同游戏重复打开不新建。控制权在另一页时以只读状态提示「返回原活动」或由本人明确「接管」，成功后旧页停发操作。其他游戏的多人活动只阻止第二份多人席位；不同单人游戏按各自游戏恢复。 |
| **纯单人（`solo: true, multiplayer: null`）** | 幂等开局、握手后直接可玩。短暂加载不闪骨架，超时给出「重试／返回大厅」。已有共同章节时默认从最高解锁章续玩。选择重玩先展示起点与当前局影响，确认时保存并关闭原局，以新局 ID 从服务端已解锁的 `startRank` 开始。章节名称来自已验收的 `milestones[].label`，缺失显示「第 N 章」。仅一个里程碑隐藏选章；重玩不回退已解锁等级。 |
| **单人 + 多人双栖（如《航标接力》）** | 默认直接进入本游戏单人局。打开或取消建队／入队／匹配面板均不暂停单人局。玩家提交目标后，宿主请求 SDK 保存屏障 `sdk.progress.onFlush(handler)`，等待 SDK 交回最后完整私档或 `null` 并冻结新输入，随后把该私档、预期私档修订与目标组成同一幂等切换命令。服务端一次提交才挂起单人局并占多人席／票。错码、竞争落败、保存失败、超时未生效都留在原单局并解冻。响应丢失先用原键查询或重放，再决定恢复或转场，禁止产生第二次入队。 |
| **纯多人，仅随机、单一人数** | 无己方已有活动且 `privateRooms=false`、`randomSizes` 仅一项时直接幂等排队。显示玩法、目标人数、实际已等候时长与「取消匹配」，隐藏未成队候选身份；明确取消与配成同刻时按服务端唯一结果转场。 |
| **纯多人，可私组或有多个人数档** | 只显示清单允许的创建、加入、历史队伍与随机人数。私房人数选 `[minPlayers,maxPlayers]`，固定值以静态文本展示；合作私房房主另可选已解锁起点。队列人数只从 `randomSizes` 选择。没有房间时可直接返回，无需放弃席位。 |

### 3.3 四位无歧义队伍码、5 秒倒计时仪式与进度预告

1. **无歧义四位邀请码体验**：
   - 采用剔除 `0/O/1/I/L` 的 31 字符集（`ABCDEFGHJKMNPQRSTUVWXYZ23456789`），在候选面板以四格大号等宽字块展示，附一键复制（Clipboard API 失败时自动全选供 `Ctrl+C` / 长按复制）、剩余有效时间及房主专属「换新码」。
   - 加入框为单一原生文本输入，使用 `inputmode="text" autocomplete="off" autocapitalize="characters" spellcheck="false" enterkeyhint="go"`。粘贴和回车均在文本组合完成后剥离允许的空白与 ASCII 短横线，英文转大写；归一化后严格 4 位且字母数字均须出现。禁止先截断原串再判断，也不自动提交粘贴结果。误输混淆字符给字段级说明。不存在、过期、满员、失权或屏蔽统一提示「暂时无法加入，请核对验证码或向房主索取新码」，限流后按服务端返回的下次可试时间解锁。
2. **历史队伍一键复用**：
   - 列出本人确实参加过的私房，按队名、目标人数与上次开局日期辨认。同名同人数而阵容不同是不同项。成员显示仅由服务端基于本人历史参赛记录、受控阵容引用和当前关系投影：仍为双向好友、双方互不屏蔽且称呼可展示时才返回当前称呼，其余席位统一「前队友」。指纹用于去重，不能反查姓名或恢复旧码。选择后预填并可检查人数／模式；「按此配置新建」明确提交后获新房、新码。旧成员自行输入新码，版本已不支持的配置提示重选；本人可删除自己的历史模板。
3. **5 秒权威同步倒计时与共同进度透明预告**：
   - 满员事务记录 `generation, serverNow, startsAt`（`startsAt = serverNow + 5000ms`）。宿主用校准后的单调时钟绘制 `ceil(remaining / 1000)`，显示当期成员名片；未授权真实头像时用首字或席号图标。倒计时从当前剩余秒数开始，迟到或退后台的设备不补播。归零仅显示「正在进入游戏」，收到 `run.started` 或有效 `running` 快照才向游戏开放输入。动态按系统和平台偏好降级。
   - **无障碍礼貌播报**：`aria-live="polite"` 区域仅在倒计时开始（「队伍已满员，5 秒后开始」；迟到设备播报实际剩余时间）与正式进入游戏（「对局已开始」）各播报一次，严禁逐秒抢占读屏打断交流。
   - 仅公开本局起点 `S` 及其名称，不公开队友个人等级。如果默认从全队最高公共进度开始，低于 `S` 的玩家本人会看到其解锁进度的变化。房主显式选章重玩时，分别显示「本局从第 S 章重玩」与「个人已解锁至第 N 章」；实际开局后本人解锁为 `max(原最高等级, S)`，界面按服务端当次个人投影展示；只在开局事务成功后标记已同步。开始前的预告属于只读信息。倒计时取消则撤回遮罩，私房显示仍有效的新房码，随机组显示恢复的排队进度，双方都保留已提交存档。

### 3.4 局内队伍抽屉、软键盘保护、全局静音与舞台焦点移交

1. **按需懒加载的队伍与房聊面板**：
   - 顶栏「队伍」使用共享 Drawer／Sheet，桌面右侧约 `340px`，窄屏从底部展开。`dialogs`、`composer` 用已登记的 `LQ.load` 懒加载；表情选择器按需导入现有 `static/js/emoji_picker.js` 的 `createEmojiPicker` 并在面板销毁时释放资源。`LQ.load('emoji-picker')` 在当前仓库没有注册项。没有房间时隐藏队伍面板；无房聊能力时仍能查看允许展示的席位。
   - 消息流使用共享 `lq_bubble`（`incoming / outgoing`），输入区使用共享 `lq_composer`（尊重中文 IME `isComposing` / `keyCode === 229`、发送防重、失败保留原草稿一键重试）。收到新消息时若抽屉关闭，仅在顶栏「队伍」按钮点亮未读红点，**绝不弹出抢焦点的横幅打断正在进行的游戏操作**。
   - 窄屏键盘弹起时，尽量固定底层舞台占位，仅在 Sheet 内依据 `VisualViewport` 修正消息区和输入区。设备不提供该 API 时使用正常可滚容器与安全区。校验输入框可见、关闭后布局恢复、iframe 不重载且不会另起对局；系统因旋转／缩放触发 viewport 变化属正常适配。
2. **宿主一键静音与保存九态语义**：
   - 有声音的游戏使用顶栏「静音」切换按钮（固定可访问名称配 `aria-pressed`）。读取账户静音偏好并作为 `ready().audio.muted` 初值，通过端口 `audio.changed` 更新已挂载的包；恢复、换版、重新握手都重发当前状态。包须在首次有声播放前应用此偏好，并管理 HTML 媒体与 Web Audio 两条通道。宿主无法直接静音已隔离的任意子帧，未响应的音频作为验收阻断项。偏好提交失败保留本标签当前静音、提示账户设置未同步，可重试。
   - 宿主根据后端确认展示共享 `SaveStatus`：`dirty/local_saved/offline` 表示不同持久状态，`syncing/synced` 反映云端回执，失败和冲突保留本人草稿并提供重试或核对。未占私档权限时不展示包的私档保存状态。不要向玩家把本地持久化或未确认操作标成云端已保存。
3. **关键交互细节：弹层关闭后的舞台焦点移交（Stage Focus Handoff）**：
   - HTML 小游戏大量依赖键盘方向键、WASD 或空格键（事件绑定在子帧 `window` 上）。玩家可操作舞台或平台导航。关闭队伍、帮助、规则面板时应按打开位置和退出意图恢复焦点。帮助内容使用经审核的游戏简介及玩法摘要，离线／加载失败时仍可查看平台操作说明。
   - 关闭由键盘或顶栏按钮打开的抽屉时，`LQ.layer` 默认把焦点归还原触发器，并紧邻提供「返回游戏」操作。若玩家明确选择「返回游戏」或从舞台内触发的宿主菜单退出，且房间仍在运行、无上层模态，才在 `onReturnFocus` 把焦点移回当前 iframe。宿主为 iframe 提供可读 `title`，游戏内部设置可键盘聚焦的主操控区和清晰的 Tab 出口；跨源父页不能聚焦子帧内部选择器。测试触发器恢复、再入舞台后方向键可玩，以及从 iframe Tab／Shift+Tab 返回平台。
4. **离开保护与离线/独立模式透明呈现**：
   - 退出根据当前阶段说明真实后果。排队取消后释放票；私房等候离开释放席位，房主离开按既定顺序转移；倒计时退出撤销当前代次；运行中明确退出会结束联机局。均在服务端确认后返回大厅。刷新、断网、切后台不等于明确退出。已开局多人由服务端发现租约超时后保位 60 秒，成功恢复原座位／修订；超时或失权给出本局中断与最近已提交进度。
   - 双击本地 `main.html` 时展示本地模式；纯单人可独玩，纯多人可同机轮流／多席位完成整局。本地存储可用时说明保存位置，不可用时改为「本次仅保存在内存，可导出文件」，提供导出／导入。可信平台宿主如允许从本机导入，仅接受当前游戏同谱系的本人私有字段，经文件检查、差异预览与修订确认后写入。断网不自动切入访客适配器。

## 4. 教师管理工作台（`/manage/library/games`）

教师工作台完全沿用 `manage/layout.html` 与资源库（`materials`）的成熟交互范式，不发明陌生的后台布局：

1. **列表页结构。** 游戏归属教师或具有该对象管理权限的超级管理员可以维护条目。其他具备资源库资格的教师只看到其可管理的记录；以玩家身份可玩某款游戏不会获得编辑权限。学生看不到教师入口，直接请求管理 API 也会被拒绝。
   - 页头使用 `lq_page_head(title='小游戏管理', description='上传独立 HTML 小游戏包，经隔离验收与预览后按教学范围与修为等级开放。')`，右侧唯一主按钮为 `variant='prominent'`、`icon='upload'` 的「上传新游戏」，辅以「在大厅体验」（新标签进入玩家视角）。
   - 筛选区使用 `lq_filter_bar`（搜索名称、`gameKey`、标签）搭配状态/模式/范围下拉及已生效条件芯片，显示 `lq_result_count` 与一键清除。
   - 桌面表格列为图标／名称／gameKey、当前公开版与候选版、玩法人数、标签、受众／修为、近 7 日去重人数和更新时间。游戏本身区分草稿、上架、下架、删除中；候选版本的验收中、就绪、失败单独一列呈现，上传新版本不把在线版伪装成草稿。移动端用有明确字段名的 Row 或保留正确表头关联的表格。支持详情直达、返回原条件与页码。
2. **流式上传与校验可观测反馈**：
   - 共享 Upload 接收单个 ZIP，限制从服务端取得（初始上限 `64 MiB`）。通过草稿与待上传对象绑定游戏，报告上传结果。`100%` 仅表示传完字节，拿到 202 和持久化 `jobId` 后用 JobStatus 反映服务端报告的阶段。传输中断时先查同一请求结果；只有已建任务才能在关闭／刷新后靠任务 ID 接续观察，无分片续传支持时尚未上传完的字节须重选文件重传。清理取消仅针对本次上传／任务。
   - 校验失败按包内相对文件与字段列阻断原因，保留失败草稿并允许提交修订包。教师可按需请求 AI 解释经脱敏的诊断；显示来源并提供本来的结构化错误。AI 超时、限额不足时，仍可修包和重传。只有验收通过且当前获管理权限的候选版点亮「教师预览」；预览使用独立临时身份／房间／存档，既不作正式开局也不计热度。
3. **属性编目、范围修为联动与并发冲突保护**：
   - 使用共享 `bindDirtyGuard` 和 `LQ.layer` 的关闭否决保留草稿；独立详情路由同样有保存／放弃入口。`gameKey`、模式、人数与存档谱系只读。教师可改标题、简介、精选状态和去重标签；IME 组合时 Enter 不提交标签。精选按对象管理权限维护，推荐投影仍先判玩家资格，查询失败不会用失效精选填补。
   - **受众范围与修为双条件配置**：单选 `私有（仅管理教师） / 指定课堂（支持多选，自动涵盖合班关联班） / 指定行政班（多选） / 本系部 / 本学院 / 本校 / 平台全体登录用户`，并配置两个整数输入/双端范围 `学生修为等级 [minTier, maxTier]`（`0–10`，无证书学生计为 `0`）。表单底部实时渲染自然语言策略摘要框，例如：
     > 当前策略允许所选课堂中修为 2–6（含两端）的在籍学生游玩，符合受众条件的教师也可游玩。教师隔离预览还须具备对象管理权限和验收就绪的版本。

     显示等级名时使用服务端等级表。指定课堂／行政班必须至少选择一个本人可授权目标，空选择不会自动扩大范围。下限大于上限时定位错误并保留草稿。
   - 提交携带 `expectedRevision`；遇多人协同编辑 `409` 冲突时渲染共享 `Conflict` 组件，完整保留教师本地草稿并支持对照最新值后重提。
4. **上架、版本切换、下架与净室彻底删除**：
   - 「保存属性」独立生效。「发布版本」才切换对外版本。对已上架游戏收紧范围／等级前显示影响摘要并确认，成功后失权者的资格立即撤回；其他仍合格者按原局继续。发布／回滚对照列出版本、玩法人数、存档兼容性及等待房影响，校验可用旧指针和活跃引用。旧等待／倒计时取消，已开局且仍合格者可按原版完赛。不兼容的回滚显示具体原因，原版继续服务。
   - 「下架」从服务端取带时间的影响快照，明确停止等待与在途局、保留已提交存档并可再次上架。重复提交复用同一请求键。若确认页面已过期或游戏修订已变，刷新影响说明后重新确认。
   - 详情危险区使用完整管理 API `/api/games/v1/admin/games/{id}/deletion-plans` 作影响预览。确认人输入计划返回的精确确认短语：已验收并绑定稳定键的游戏使用 `gameKey`，尚未绑定成功的草稿使用 `draft-<gameId>`，用绑定修订的确认凭据调用 `DELETE /api/games/v1/admin/games/{id}`。从撤权提交即停止新访问，后续按任务分批清理游戏专属在线文件／业务行／缓存。区分完成、尚在删除和需重试，持久作业显示 `jobId`，重新登录后可继续查看。独立删除登记未获确认时显示「等待删除登记，可重试」，沿用原任务，保留撤权状态；只在最终核销通过后显示「已彻底删除」。最小处置审计和按制度到期的隔离备份单列，失败不复活旧版。

## 5. 前端性能预算与全平台可执行验收矩阵

### 5.1 硬性前端性能预算（CI 与浏览器实测门禁）

| 指标维度 | 预算上限与技术守卫 |
|---|---|
| **全站 LQ 入口体积** | 游戏脚本按路由独立加载，无关平台页面的游戏业务代码增量为 0。`npm run check:lq-size` 的共享入口门禁保持 `≤18,432` gzip bytes，新增生成图标须计入真实资产差值。三个路由自有首载代码各以 `≤14 KiB` gzip 为目标，记录正式构建的独占文件、共享依赖与首次开面板增量，不能用空壳入口掩盖其传递依赖。 |
| **实时 `backdrop-filter` 宿主数** | `/games` 大厅常驻模糊宿主 **≤ 2 个**（Topbar + 右栏边界，卡片模糊宿主严格为 **0**）；`/games/{slug}` 游玩态常驻模糊宿主 **≤ 1 个**（紧凑 Topbar，游戏舞台与背景模糊数为 **0**）。 |
| **静止态活动** | 背光增强自身在指针静止／离开后持续 `requestAnimationFrame` 循环数与临时 `will-change` 均为 0。不逐卡运行计时器或添加全页 DOM 扫描。另记浏览器及其他共享组件产生的活动。 |
| **布局稳定性与交互响应** | 图标成功／回退引起的布局偏移为零，记录整页 CLS 和其他来源。几何有效时背光帧无同步几何读取；滚动或调整尺寸后的首次校正最多一次矩形读取。使用正式构建收集滚动、跨卡和图片失败的布局及绘制 trace。 |
| **无障碍和降级** | 覆盖六套配色、亮暗外观及背景、关闭透明、减少动态、减少透明与强制色；对支持的偏好逐项取实图／计算样式，不支持时记录环境。自动 axe 扫描与键盘、触摸、焦点、读屏、实际背景小字对比度 ≥4.5∶1 分开验收。 |

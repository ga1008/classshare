# 小游戏运行态验收记录

2026 年 11 月 23 日。以下记录使用独立生成的账号、课堂、游戏与 PostgreSQL 集群。数据库仅在回环地址的随机端口监听。每个原生 PostgreSQL 目录都有本次预演的所有权标记，退出时停止服务、关闭连接、移除数据，仅保留统计、程序日志和清理回执。

## 可重复的业务检查

| 检查 | 实际覆盖 |
| --- | --- |
| 最后一席与重复指令 | 两个教师或学生的角色身份按角色及主键区分。竞争同一席位只产生一个成功加入和一次开局。同一请求键与相同内容复用原动作修订，不同内容按冲突处理。 |
| 用户私档和共有进度 | 三人具有不同进度，在第二人对齐后注入异常，确认整笔事务回滚。重新执行后三人共享同一里程碑，并保留各人原私档。选章重玩保留领先者最高纪录。 |
| 版本衔接 | 旧版单人仍可读写原版本允许的字段。新版增加私档字段后，切到新版多人以前在同一事务冲刷旧局私档，新字段使用新版默认值。 |
| 队伍、屏蔽、退出 | 200 个合成学生使用两人、四人匹配，含预设的屏蔽对。校验成局成员、每一席对应的桶和版本、换版后运行局及未匹配票的去向。局中新增屏蔽后检查名单、历史消息、幂等重放和同伴的后续动作。 |
| 随机满房后有人退出 | 仍在线的玩家从活动接口取回原票据和入队时刻，已退出者没有新的席位。将清理时钟推进超过 24 小时，活跃票据的入队回执仍可查，取消票的回执已回收。 |
| 同一存档的并发晋级 | 两个原生 PG 事务分别推进同一行至 1、2，检验两种写入顺序的最终等级和连续修订。另一连接锁住队友的进度行时，整次多人推进超时回滚，释放锁后用原请求键重试只产生一次结果。 |
| 控制权与持久化 | 同游戏接管使旧代数失效。在续租邮箱采集和冲刷之间换掉登录会话，数据行的原到期时间不前移。第六款单人使最久未交互的旧局挂起。管理员下架并彻底删除后，业务行按游戏清理。 |
| 登录会话与共享存档 | 随机匹配剔除登录已过期的候选人。私房满员后、开局前注销的玩家退出席位，剩余玩家可用新邀请码补员。此时检查旧私档、共享里程碑及变更账本；在局中替换队员登录会话后，其余成员的下一条动作在推进里程碑前终止对局。 |
| 同步与时钟 | 四个流共四十个本地等待者合批执行一次水位查询。空站最多四秒回读；另一实例可在五秒期限前发现满房、按数据库中的时间开局。 |
| 规则 | 用合法与非法输入检验有限状态回合和棋盘服务端裁决，同时检查嵌套私档结构。 |

SQLite 单元测试入口为 `python tools/test_backend.py --pattern test_minigame_runtime.py`。原生 PG 入口为 `python tools/minigame_runtime_pg_probe.py`，使用相同业务夹具，给每项测试单独创建数据库。发布前新增随机匹配撤权与三个登录会话回归，18 项检查在两个引擎上分别通过，PG 记录为 `rules-rooms-v0abfcm7`，清理回执为 `removed`。服务层可控地替换时钟及账号授权，原生 PG 执行实际事务、唯一约束、并发连接和回滚，HTTP 预演另行使用真实的登录会话、教师域、CSRF 和游戏可见性检查。

## 两个 HTTP 进程和真实上传验收

在本机执行 `python tools/minigame_runtime_capacity_probe.py --windows-2c4g --verify-http --seconds 5 --baseline 3`。此命令需要项目锁定依赖、Windows PostgreSQL 16、PyWin32、Playwright 及已安装的 Chromium。脚本固定仓库内“航标接力”样例 ZIP 与解包清单摘要，仅该样例可使用 Windows 的受审浏览器预演模式。

在 `http-mixed-4822r7lo` 中，创建者连接工作进程 A，候场读取从进程 B 等待。两人同时加入只剩一席的私房，只有一人取得席位，等待者读到满房倒计时。两个进程并发提交同一动作，返回一致的修订和游标。教师通过实际管理路由上传示例，后台任务完成浏览器检查并进入成功状态。教师下架另一款正在候场的游戏，另一进程随后的玩家读取返回 404。Windows 作业约束覆盖两个服务进程和该次新起的数据库，限制为两个逻辑处理器、总计 4 GiB 提交内存，观测峰值为 2,092,384,256 字节。

## 性能测量口径

短同步和命令用 HTTP 请求起止时间。开局偏差取数据库写入的 `startedAt - startsAt`。全房倒计时指标取满员时刻到十名订阅者均收到倒计时数据的时间；这个指标只覆盖网络数据抵达，屏幕绘制需结合浏览器验收。动作端到端指标从发送方发出请求开始，到另一个工作进程上该同伴首次读到对应游标为止。另记录每一动作九名同伴均收到的时间。

课堂对照使用真实的 `GET /api/classrooms/1/group-qr`。独立测量进程在基线与混压时都以同一账号、每秒五次访问同一路由，同时读取服务侧处理时间。20 个十人房间分别每 500 毫秒提交一次合法动作，控制页在每次返回后间隔 1.7–1.9 秒发起合并同步。测量期交错真实包上传、后台浏览器验收，以及对独立游戏的下架与跨进程撤权读取。课堂二维码读取只代表这一条课堂业务，完整课堂提交、登录考勤及生产反向代理需要分别验收。

持续负载夹具使用公开范围、修为全段的十人合作规则。每次 `tick` 都走真实指令校验、事务、事件游标和幂等回执；状态返回同一节点，共有最高里程碑始终为 0。高频房聊、限定课堂名单判定和跨里程碑存档写入须另看相应专测。客户端压力采集记录原始请求遇到的网络异常。

## 两核、4 GiB 进程调度对照

运行 `python tools/minigame_runtime_capacity_probe.py --windows-2c4g --seconds 120 --baseline 60`。首个候选样本为 `http-mixed-zjwdq7ny`。操作系统约束数据库、双应用工作进程及上传检查派生的浏览器进程。课堂压测客户端在约束之外，基线、混压使用同一独立进程。该组包含 1 次实际 ZIP 上传及验收、1 次独立游戏下架和跨进程撤权读取。

| 课堂 ASGI 服务处理，基线／混压 | 300／594 | 5.60／11.78 ms |

该组无请求失败，连接峰值每进程 2 条。游戏平均每秒 146.74 次连接借用、2,511.99 条 SQL、37.12 次有写入的提交。Windows 作业峰值提交内存约 2.07 GiB。课堂客户端 P95 相对增加 86.7%，同一请求的服务端时间也有所上升，由此确认部分额外时间发生在服务端。实验结束时尚在途的 414 条「动作 × 同伴」观测单列，未纳入成功到达延迟分位数。

第二个样本 `http-mixed-b33z03jj` 在同一命令加上 `--separate-classroom --deprioritize-games`，保留 60 秒基线、120 秒混压和同样的 200 人。两个游戏 API 进程采用较低调度优先级，课堂 API 由默认优先级的第三个进程处理。三个应用进程、数据库和上传验收启动的 Chromium 都在同一个两核、4 GiB 作业内。课堂客户端 P95 为基线 7.14 ms、混压 5.67 ms；服务端对应为 5.38 ms、4.22 ms。该样本满足课堂劣化上限，分位数受抽样波动影响。

游戏短同步 12,978 次，P95 为 63.75 ms；动作 4,466 次，P95 为 53.86 ms。跨进程同伴首见 P95 为 1,802.85 ms，十人收到倒计时 P95 为 424.45 ms，实际开局偏差 P95 为 64 ms。每个游戏服务器最多同时借 2 条连接，无请求失败。全部九名同伴收齐的 P95 为 2,050.77 ms，结束时尚有 349 条同伴观测在途。两核作业峰值提交内存为 3,021,807,616 字节。

## 部署连接预算与浏览器执行位置

上述两组对照都容许两个游戏工作进程各借 2 条连接。最终部署以每个专用游戏 API 进程各 1 条为预算，另为主站 SSR／续登和内容鉴权各预留 1 条。两组短样本只支撑调度方式的比较。

独立浏览器执行位置的功能预演 `http-mixed-g_ct7ola` 仍调用原管理 API 和后台作业。ZIP 接收、解包、静态校验、发布数据库写入均在课堂一侧。受审样例的浏览器启动和素材检查交给另一个 Windows 作业，该作业使用与主站不重叠的两个逻辑处理器并设独立 4 GiB 上限。课堂侧峰值 1,641,021,440 字节，浏览器执行侧峰值 466,243,584 字节；验收成功。试验用文件交接与固定清单摘要仅供本地预演，真实部署使用独立隔离执行机。

## 正式候选的持续混压

样本 `http-mixed-jap6mr3p` 在原定的 120 秒课堂基线后连续混压 1,800 秒。使用原项目专用 ASGI 应用的两个工作进程、普通优先级的独立课堂进程与原生 PostgreSQL 16，三者共享两个逻辑处理器和 4 GiB 提交内存。两个游戏进程调度优先级较低，分别只允许借 1 条游戏连接。课堂客户端与 200 个模拟玩家在服务器资源组外，使用操作系统默认 CPU 调度；两阶段课堂测量使用同一进程、同一账号、同一接口和频率。样例浏览器执行器位于本机另一组 CPU 与内存预算内。

```powershell
python tools/minigame_runtime_capacity_probe.py --windows-2c4g --separate-classroom --deprioritize-games --external-browser --production-api --connections-per-api 1 --seconds 1800 --baseline 120
```

每个游戏进程的连接峰值为 1，合计上界 2；部署方案另给主站及内容校验各预留 1 个游戏连接位置。本样本没有向内容服务发送 200 路游戏素材流量。两进程平均每秒共借用连接 150.11 次，执行 SQL 2,112.13 条，其中变更语句 196.08 条，有写入的提交 39.08 次。两个游戏进程平均共用 0.461 个 CPU 核。课堂及数据库侧峰值提交内存 2,541,883,392 字节，浏览器执行侧 496,103,424 字节。

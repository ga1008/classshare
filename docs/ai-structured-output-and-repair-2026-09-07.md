# 结构化输出规模与合并复核规则

实施日期：2026-09-07。补充业务路由 v2 计划的 §6.2、§9.2；不改变任务分类、厂商允许列表或历史成绩。

## 输出规模

`ai_model_policy.structured_output_size_tier(schema, question_count)` 是入队前与执行前共用的纯校验函数。它只接受可信整数题量，不读取题目、附件、学生答案或提示词中的“切档”指令。

| 输出结构 | 基础档 | 中档 | 大档 | 预先拒绝 |
| --- | --- | --- | --- | --- |
| `grading_v1`：简短逐题评分、扣分点与评价 | 1–20 题 | 21–40 题 | 41–80 题 | 超过 80 题 |
| `exam_generation_v1`：题干、选项、答案及评分说明 | 1–10 题 | 11–20 题 | 21–40 题 | 超过 40 题 |

基础档使用业务 profile 的既定总输出上限；中档至少为 `AI_STRUCTURED_OUTPUT_MEDIUM_MAX_TOKENS`（默认 16,384），大档至少为 `AI_STRUCTURED_OUTPUT_LARGE_MAX_TOKENS`（默认 32,768），均不降低 profile 本身的上限。配置必须满足 `1 <= 中档 <= 大档 <= 32768`。因此普通视觉评分的默认档位为 8,192 / 16,384 / 32,768；考试 high 和纯文字深度任务基础档仍为 16,384。

这些阈值是依据两种输出结构详略设定的规模控制规则，不是精确 token 预测，也不能保证模型思考与答案一定能容纳。实际出现 `length` 或 `incomplete` 仍停止完整成绩写回，不自动增大上限重跑。超范围返回人工处理或按完整题组拆分提示；系统不会擅自切割共用附件或跨题条件。

题量来源：

- 评分优先计数教师试卷快照 `exam_scoring_json.pages[].questions[]`，覆盖调用方的题量提示；不从学生答案数量推断。
- 出题由应用服务将已经校验的总题数、题型计数最大值写入 `business_context.expected_question_count`。AI 服务的出题 handler 固定使用完整出题 schema。
- 个人阶段出题使用服务端同一常量规定的最多 10 题。
- 非结构化普通作业、旧调用或自由提示词未提供可信题量时，保持基础档，并记录 `output_size_tier=unknown`；不宣称已经预测未知题量。

执行层在原始附件准备完成、实际输入模态确认后冻结计划。计划和实际执行 metadata 包含 `output_schema`、`expected_question_count`、`output_size_tier`、实际总输出上限。已有带规模信息的快照在配置改变后保持原上限；题量或 schema 与快照不一致时停止。旧快照如果不足以容纳当前已知规模，也停止并要求重新发起，不自动扩充它的额度。

题量同时约束结果完整性：主评分、high 复核、合并修复和持久结果恢复都使用同一个校验函数。教师试卷的题目 ID、对应题号和题目数量必须完整匹配；不能仅靠学生 `answers_json` 中出现的题目来判定覆盖。附件提交即使没有文字答案，也必须覆盖教师试卷全部题目。数量相同但替换、重复题目 ID 同样不通过。恢复到旧的漏题结果时不直接写成绩；若保留了完整有效的主成绩而复核结果漏题，继续保留主成绩并标记人工复核。

## 一次 high 同时修复格式与复核证据

普通 Pro low 返回可解析对象，但严格评分结构校验失败时，执行层检查该对象中可确认的风险字段，例如低置信度、明确要求复核、证据冲突，或“未提交答案”与实际有效图片矛盾。只有格式缺陷与这些风险同时存在，才将第二次生成机会合并为一次 high 修复／复核。

教师试卷覆盖校验失败本身就是本地确认的风险，记录为 `teacher_question_coverage_incomplete`，因此 low 漏题或错题 ID 会进入上述合并流程；high 仍未覆盖全部题目时不接受其成绩。

该调用沿用原始图片、评分标准及确定性证据，同时携带格式错误和风险说明，使用同一逻辑任务账本及每日复核预约。全站每日 10 次、每课程每日 3 次，重放不重复占额；单任务仍最多两次可能产生费用的生成、总共三次 HTTP 尝试。明确拒绝的 429 可以在同一预约内重试，未知超时保留额度。

未通过严格校验的候选只存为内部 `repair_candidate`，不能成为主成绩；日志和回调仅保留存在标记，不复制候选正文。候选与 `review_plan` 通过租约和 revision CAS 持久保存，恢复时不能被改写。

- high 成功且结构、证据校验通过：保存 `review_result`，标记 `combined_format_repair=true`；恢复和回调重试复用结果，不再次调用模型。
- high 失败、预算耗尽或预约不可用：返回待复核、`score=null`，由现有回调保护保留历史成绩。不会接受不合格 low 候选，也不会再补一次 low。
- 主 low 已经是有效成绩，但普通风险复核失败：继续保留有效 low 主成绩并附待复核标记。
- 只有格式错误而没有可确认风险：保留原有同档原图修复，最多再一次；若修复后仍有风险，额度已耗尽时转人工。
- 完全无法解析的文本不会被当成可信风险字段；high 主调用不会再次触发同档质量复核。

## 验证

隔离测试捕获真实 SDK 发出的请求，覆盖评分与出题档位边界、实际总输出参数、教师快照覆盖题量提示、超大任务零请求、旧快照保留、low→high 合并修复、429 的三次 HTTP 上限、预约只计一次、超时和额度拒绝不写无效成绩，以及成功或失败后的恢复零额外调用。CAS 测试验证候选与复核计划不可改写。测试使用合成数据和内存 transport，没有调用付费模型。

漏题回归使用真实的 25 题教师快照和仅附件提交，验证只返回 1 题不能进入 `graded`，25 题完整结果可通过，同样数量但题目 ID 错误需修复，high 漏题保留有效 low，以及旧缓存漏题结果恢复不新增请求。回调测试同时验证失败或待复核时旧分、旧评语和已应用的迟交扣分不被覆盖。

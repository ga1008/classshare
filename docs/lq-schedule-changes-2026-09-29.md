# 调课变更清单：对照标签与申请分组

## 行为与组件边界

- 每条调整采用 LQ Table 的 `matrix` 模式，原、新两行共享周次、星期、节次、教室列。列宽由两行最长内容决定，不解析旧的描述字符串、不缩写教室、不截断字段。窄屏由命名、可聚焦的表格区域横向滚动，不扩大页面宽度。
- 字段来自 `draft.original/proposed`；未改变的值与原行均使用中性 Chip，只有新行变化的值使用危险色并加粗，同时提供“已更改”的读屏说明。节次按连续段格式化，非连续节次不会误显示为一个连续区间。
- 课程名称后放固定宽度的原因、证明材料及教务详情 Button；正常换行，长文字在悬停或键盘聚焦期间滚动一次。共享 `bindOverflowLabels` 仅移动文本槽，不改变按钮尺寸、点击和焦点行为；off/quiet/reduced-motion 保持静止，触屏直接点击查看。
- 点击使用 LQ Dialog 的 `popover` 变体，完整显示原因、备注、材料链接或教务诊断。Escape、外部点击及焦点归还交给同一个 LQ layer；重绘、卸载及延迟模块加载通过版本号取消旧浮窗。关闭浮窗不关闭已选课次的属性面板。
- 清单面板复用共享 Surface，值和状态复用 Chip，动作复用 Button，比较区复用 Table；领域 CSS 只决定布局和数据强调，不增加独立玻璃材质、模糊层或动效引擎。

## 教务申请与业务闭环

1. 候选合并按教师、学年、学期、教学班 ID 分组，不能仅按同名课程合并。未知教学班的记录保持独立。
2. 保存后的实际申请必须同时满足 `status=pushed`、申请 ID 和明细 ID 齐全，才按远端申请分组。冲突/失败残留的申请 ID，以及编辑后留下的旧 ID，都不能作为已保存依据。已保存但缺身份的历史记录单独显示“申请待核对”。
3. 每项保留自己的原/新安排、原因、证明材料、定位及撤销/撤回入口。同一教学班共用申请，每次保存仍产生独立明细；撤回一项不会删除其余明细。
4. `pushed` 只表示平台曾保存成功，不代表当前申请仍待提交或已经批准。列表用简短“教务已保存”标签；详细远端信息、冲突诊断和申请/明细 ID 在浮窗保留。提交/审批进度仍以教务系统为准。
5. 保存不会自动提交申请；材料保存在平台，提交教务时仍需按要求附上。材料下载使用原有按教师与草稿归属校验的 API，未增加公开链接。右侧属性面板的上传、删除、原因编辑和锁定规则保留。
6. 教务表单只返回原始安排时，无法证明旧记录的目标与本次调整一致，因此不再自动关联，也不重复保存；提供核对提示。强制保存不能绕过此身份检查。
7. 撤回前验证同一申请及唯一明细、原始周次/节次/教室/教学班，撤回后再次验证同一申请与该明细确实消失。身份变化、仍存在或无法核验时，本地保持锁定并提示到教务处理。
8. 批量保存中途失败时，已确认成功的申请和明细必须落库，其余项显示失败/待核对；重试不会把已确认成功项再次保存。保留软冲突确认与硬冲突阻止，不自动升级权限。

## 验收与限制

所有业务数据均为合成数据。后端使用 `tools/test_backend.py` 在导入应用之前禁止 dotenv 和 PostgreSQL，浏览器拦截所有网络请求并禁止外部教务访问；未连接真实业务库运行测试。

- 编辑器及证明材料后端 30 项通过；可调时段 7 项、节假日与课次重排 8 项通过。
- 共享 Button/Chip/Dialog 单元回归 41 项通过。
- 共享滚字增强器浏览器 6 项通过，覆盖 RTL、末端完整可见、动态动效偏好、禁用/加载、重绘销毁、320px 触摸；没有空闲 rAF、timer、observer 或逐标签监听器。
- 清单浏览器 20 项通过（17.945 秒，零跳过/重试），覆盖浅/深色、390/1440px、320px 超长中英文教室、上下列及 Chip 等宽、差异颜色与字重、分组、材料链接、读屏/键盘、预检和保存期间重复点击、关闭和重绘生命周期。上下列及标签对齐误差不超过 1px，157 字符教室通过区域内横滚完整可达。正式资源图入口与懒加载实际加载 22 个资源，均来自同一 revision，零源码回退、浏览器异常或未声明请求。
- `npm run build`、类型检查及 LQ 源码门禁通过；LQ 主入口 gzip 17,771 字节，仍在 18,432 字节预算内。共享滚字功能按需由消费者导入，未扩大全局主入口。
- 全平台源码清点已重新生成：[源码摘要](lq-schedule-changes-source-summary-2026-09-29.json)。其 pending/unknown 是静态清点边界，不能解释为全平台运行时全部验收通过。

远端教务的真实提交/审批和真实附件上传未在测试中执行；这次未新增审批状态自动回查或数据库迁移。原始安排匹配但目标不可核验时需要人工核对，是防止错关联所必需的边界。

本地证据位于 `.codex-temp/course-schedule-editor-changes-verified/`、同名 JSON 完整测试报告、`.codex-temp/lq-overflow-label-tests-final/` 与 `.codex-temp/schedule-changes-native-validation.json`。本次没有测量真实旧电脑帧率，不以无常驻循环推断具体 FPS 增益。

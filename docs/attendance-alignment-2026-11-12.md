# 智慧课堂课程与课次对齐

课堂的自动点名浮窗使用“对齐课次”。橙色表示尚未完成，绿色表示当前课程和课次均已对齐。同步与推送在未对齐、尚未结算或已有同步任务执行时原生禁用。本地点名可以独立开始、自动结束、查看学生卡片及人工更正；学校连接和对齐失败不会丢弃本地记录。

## 课程与课次分层

课程核对使用同一学年学期、名单双方多数交集和课程证据。未对齐人数按双方学号集合的对称差计算，自动对齐要求总数小于 5；不能把两侧各 4 人误当成少于 5 人。代码、完整课次数、学时和学分同时有可靠一致证据时直接采用规则；缺少或存在别名的情况交给 AI 协助，仅允许返回本次学校读取的候选标识。缺失数据不能用两个零当作相等，点名历史数量不能当作完整排课次数。

AI 核对把已允许的少于 5 人名单差异及缺失学时、学分视为中性信息；课程编号、名称或常见别名、完整课次数等任一路充分证据可支持同课，不要求所有元数据齐全，明确冲突或多个可能候选仍需人工确认。AI 判断及有限安全失败代码、说明随课程对齐结果保存，并在存疑说明中展示，不保存厂商错误正文或凭据。

课次在已确认的课程下核对教学周、星期、完整节次及顺延课次序号，四项同时一致才自动绑定。疑似调课、顺延差异或多候选显示“存疑”，浮窗先比较课程，再比较该课程内的课次。老师选择学校卡片确认；学校数据、课程层版本和课次层版本都会重新校验，过期候选只保留对照，不能提交。人工确认较大名单差异仍要求双方多数一致，并封存学校名单指纹；不把不同学期或完全不同班级当作可确认候选。

## 自动运行与数据边界

- 开课、班级关联、课次生成、教务课次核对和正式调课发布在原事务中记录后台任务。事务回滚不会留下任务；同输入去重，不重置运行中的任务。旧输入任务只补投当前输入后退出。
- 后台整课对齐复用同一批学校授课班、排课和名单读取；已有目标保留，变化的课次标记需要重新对齐。已有课堂采用每 5 分钟、最多 20 个课堂的有限补漏，缺账号后补配账号也可继续。
- 推送前自动读取学校本次课的最新点名轮次。已有点名不要求定位；确需新建且学校允许时才请求位置，再使用同一幂等请求继续。
- 学校名单权威：本地独有学生的本地记录保留，不向学校创建学生；学校独有学生保持学校状态；双方共有学生按已有版本比较、请假保护和逐人回读流程处理。
- 复用旧绑定与实际推送使用同一名单授权规则；新差异超过自动范围，或已人工确认的大差异名单再次变化，会持久标记课程及所属课次待核对，保留原映射、人工选择与收据。确认单个课次不能绕过课程层名单复核。
- 每次学校写入前检查当前课程/课次绑定、凭据代次、本地结果及授权版本。响应丢失仍先只读回查，不因重新对齐而盲目重发旧请求。
- 学校排课 ID 与点名内部排课 ID 不一致时，必须由目标排课的历史列表唯一证明同一条点名，且课程、教学班、学期、周次、星期和节次全部一致，再按该点名 ID 读取学生；不改写学校返回字段或放松其他身份校验。课程名单发现与确切点名读取分离，无关候选异常显示为不可确认卡片，不中断整批核对。
- 合班保留目标课堂并使其旧对齐失效，源绑定进入原有合班快照；确认收据保留原作用域。删除课堂清理活动绑定，历史点名及审计按原生命周期保留。

## 组件与验证

复用 LQ Button、Choice、Status、Dialog 和原生禁用、焦点、取消合同。共享 Button 仅新增显式 `data-lq-action-tone=warning|success` 槽位，不修改其他消费者的默认外观。课程和课次左右对照卡片使用现有选择组件；领域 CSS 只负责排列和数据展示。

相关回归覆盖规则与 AI 分支、课程/课次人工确认、过期和并发冲突、学校名单差异、推送中名单变化、旧任务停止、未知结果回查、后台信号及合班/删除。正式构建、浏览器、原生 PostgreSQL、上线保护与 Git 推送分别保留证据；全平台源码清点不等同于全平台运行验收。最终发布结果另记于本次发布报告。

本次源码门禁发现三个既有审核条目只因 Windows CRLF 检出而误报：`cultivation_identity.js`、`student_login.js`、`teacher_login.js`。逐个核对它们与基线 Git blob 的 LF 文本完全一致，且与原审核 SHA256 相同后，将条目改为仓库已有的 `text-lf` 模式。原哈希不变、产品文件不变，任何实际内容或空白变化仍会触发门禁。

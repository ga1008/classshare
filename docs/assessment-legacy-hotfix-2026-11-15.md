# 作业访问与旧答案退回兼容修复（2026-11-15）

本轮线上学生作业页面直接失败的根因是 AI 工作区权限查询的 PostgreSQL 类型不匹配：`assignment_student_windows.assignment_id` 为 `text`，迁移后的 `assignments.id` 为 `bigint`，连接条件触发 `operator does not exist: text = bigint`。这与客户端题型解析不同；独立检查的两份学生模板脚本及共享模块语法均正常。

紧急修复 `ab6d6926` 将连接条件改为 `w.assignment_id=CAST(a.id AS TEXT)`，保留窗口字段原类型、索引及非数字历史 ID，不改表结构或用户数据。紧急版已上线，发布号 `20261115-102547-4879cf2a138a`；发布后保全检查和 71 项公网检查通过。它恢复服务端访问，以下兼容修复的第二批上线仍待确认，两者不混记。

后续兼容修复覆盖以下已存在的数据读取合同：

- 普通作业按题目文字恢复旧字典答案；旧纯文本、JSON 标量和字符串数组仍可在原答题区编辑。空或损坏条目不会阻断其他答案；正文换行和标点保留。
- 试卷已提交、重做和服务器草稿共用 `parseAnswerRecords`，保留有效记录的题目 ID、数组答案、填空编号及附件。没有题目身份的无效试卷条目不推测分配到其他题目。
- 考试重做在加载服务器草稿前，先恢复本次退回代次隔离的本地草稿及时间戳，继续复用已有本地/服务器时间优先规则；补种的原提交草稿不得覆盖本代较新的本地答案。
- 新编号填空仅在整个非空 `blanks` 数组均为编号唯一的正整数对象时启用；旧字符串数组、混合扩展或无效编号整体按旧题处理，避免部分过滤后错误拆分答案。学生试卷投影不泄露旧扩展中的答案。
- 教师退回补齐原答案和附件草稿；重复退回保留学生已编辑草稿和原始到期恢复基线。附件种子使用独占目录，提交失败只清理本次副本，不覆盖原提交或旧草稿。到期任务取得同一提交写锁后重新检查退回代次，防止旧任务覆盖重交或延长后的记录。
- 对部署前已退回但缺少当前代草稿的存量提交，授权读取草稿时在同一写锁内重新检查权限、代次和草稿后补种一次。已存在的当前代草稿（包括学生主动清空的草稿）保持原样；补种时间取退回时刻之后的最早有效时间，不伪装为刚刚编辑，避免覆盖较新的本地作答。
- 试卷页尾上传组件首次创建时恢复服务器通用附件，跨页重建保持当前选择。移除和清空共用原服务器写入队列及代次令牌；失败恢复可见附件、允许重试并阻止误交，409 仍停止旧页写入。删除已提交但响应丢失时，由后续成功草稿快照确认结果；多页只有附件的答卷可从首页顶栏提交，无须先访问页尾。

为避免通知或提交事务失败导致附件丢失，到期处理只事务性删除草稿数据库引用，暂保留物理副本；未增加全目录扫描或自动批删。历史缺失或不合法来源文件仍按既有策略跳过并计数，修复不承诺恢复本已不存在的文件。

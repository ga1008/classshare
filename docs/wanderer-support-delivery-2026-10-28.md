# 散修支持消息的发送闭环

本轮沿用既有身份、消息、通知、模型预算与持久收件队列。情感判定来自服务器提供的本轮真实发言，原文、引用、历史记忆、知识检索结果和其他散修的发言不能凭空创建新的求助事件。规则是有边界的支持入口，不是诊断或实时校园监控。

## 私聊持久化与容量

`wanderer_social_inbox` 增加三个增量字段：

- `support_urgent`：待处理消息是否包含当前明确危险。普通后续消息不清除标志，同一说话者明确安全或恢复可降级。
- `lease_lane`：`normal` 或 `safety`。正在运行的槽位不由新来信更改。
- `support_handled_message_id`：已实际发送安全支持的独立消息高水位，避免危机措辞在普通积压队列里再次被处理时重复兜底。

原普通通道默认两个在途会话；新增一个全局有界安全 lease，仅执行确定性文本，不调用模型，也跳过可能调用模型的记忆压缩。跨 worker 仍由原全局短锁、同一 inbox 行、lease token 和时间栅栏领取，不创建第二套消息发送接口。旧表迁移顺序为建表、补列、建索引；新索引不能先引用尚不存在的列。

安全任务重新读取当前有效消息，不信任 enqueue 时的旧标志。消息已经撤回或澄清时，安全任务释放回普通通道，不调用模型。安全路径仍遵守运行开关、身份状态、好友／拉黑权限和既有发送反刷限制；不会为了绕过限流另写一条消息。

同一会话正常等待模型时若来了新的明确危险，worker 每两秒检查当前行，协作取消本地模型 await，等待其清理后释放原 normal lease，再由 safety 通道领取。普通新消息不会取消模型。已经预留的模型额度不退回，也不宣称能够撤销供应商已经开始或计费的请求；没有即时响应 SLA 承诺。

## 恢复、撤回与积压

安全结果与原回复一样先存 `response_json`，再走原 `send_part` 与 `finish`。社交消息使用稳定 nonce；旧私信的发送与进度同事务提交。重启恢复无需再生成，过期令牌不能发送、保存或完成。

发送前重查当前消息。源消息撤回、明确恢复，或用户撤销本轮私人浪漫互动时，截掉尚未发送的旧分段，保留已经提交的部分，不将 `next_part` 归零。取消的旧学习包同时清除，不固化过时归纳；新消息保留给下一轮。

普通收件游标按最旧完整窗口推进；安全路径可以查看最近 40 条未处理消息，避免 30 条之前的普通积压挡住最新明确危险。安全结果保存真实风险来源 ID；完成后单独推进安全高水位，后续普通消息仍保留正文用于学业、就业和交流学习，但同一 ID 不再触发规则兜底。新的 ID 再次表达危险仍会获得支持。

## 公共场景与主动行为

博客评论、群聊及课堂在随机忽略、表情和额度判断前考虑当前明确危险；结果仍通过已有发评论、群消息、课堂消息函数持久化和通知。群观察每轮至多安排一位散修优先支持，避免多人同时围上来。公共回复不公开私聊关系、诊断或恋人状态。

课堂仅使用最近十分钟、此前访问快照之后的真实消息，并把已观察的来源上界记录到既有 `classroom_visit.detail_json`。模型等待期间的新消息不会被访问记录提前消费。明确危险因发送失败或原有节流未送达时保留旧来源游标，后续正常访问可以再尝试；普通沉默访问则推进观察上界，避免反复触发旧消息。

主动找好友、好友审核／申请与原创发帖没有新的求助消息；主动聊天清空支持触发消息，历史记忆不能自动重开情感或浪漫互动。学业／就业资料适配仅在当前用户表达对应需要时启用，身份与输入由服务器传入，不能从正文中的 `student:123` 一类文字推断。

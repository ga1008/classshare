# 本地自动点名与智慧课堂核对

本说明对应 2026-11-09 自动点名实现。发布、并发及线上核验结果以同日验收记录为准，本文不代替验收证据。

## 任课教师开始一节课

1. 在课堂页选择实际课次，点击知识树旁的“自动点名”。核对日期、节次和教学班。
2. 展开“教室网络与本课时段”，核对本次教室出口 IP 或学校明确提供的网段。系统可以显示教师当前访问 IP，但不会自行把一个公网 IP 扩大为整个 `/24` 网段。教师使用手机流量、VPN 或不同出口时，应先改为实际教室网络。
3. 勾选网络确认，必要时保存为本课堂网络，核对起止时间后开启。允许提前开启未来二十四小时内的课次；教师晚进入页面不会将课次起点改成点击时刻。课次已结束或课堂已经结课时不能新开点名。
4. 正常授课即可。学生登录并产生课堂网络访问记录后参与统计；听讲、切到 IDE 或其他学习网页不会因为缺少连续点击而自动记缺课。

学校时段以北京时间计算：2、3 节 08:30—10:00；4、5 节 10:20—11:50；6、7 节 14:30—16:00；8、9 节 16:20—17:50；10、11 节 19:30—21:00。中间十分钟课间包含在课次窗口内。

默认兼容课前、课后各十分钟的记录，并留两分钟接收延迟上报。因此课末会先显示“等待补报结算”，预计在计划结束后十二分钟进入最终核算；后台积压或采集待核对时，以实际结算状态为准。提前结束的轮次按实际结束时刻另留两分钟结算，不继续计入之后的课堂访问。

## 怎样理解名单

- **出勤**：已有课堂网络和时段内的肯定证据，或教师已确认出勤。
- **待确认**：证据尚不足；不是缺课，也不是作弊判定。
- **采集待核对**：采集存在异常、缺口或等待处理。不能把它当成真实的零分钟。
- **有效学习时长为零**：仅描述平台能够测得的学习活动；不直接决定出勤。登录、课堂访问、有效学习时长分别展示。

多数同学的时间分布会进行再次统计，每人只占一票，偏离严格小于二十分钟可作为补充肯定证据。小样本、相近的多个群体或时间分布不明确时保持待确认，不用异常标签推定代签。

名单提供搜索、状态筛选和分页。可逐人修改，也可多选或全选筛选结果，设为出勤、病假、事假、迟到、早退、缺课；修改须填写说明。教师决定不会被自动重算覆盖。其他页面已修改同一记录时会提示冲突，保留尚未提交的说明，刷新核对后再提交。

“作废本轮”保留审计与历史，但不再把本轮当作有效点名。仍在可开启的课堂时段内可重新开一轮；新轮次独立记录。结课后不再开启新轮次，教师仍可维护允许编辑的历史状态。

## 学生申诉

学生只看到自己的签到结果。点名结束且进入可申诉阶段后，可提交本人说明，默认提交窗口为七天；已受理的申诉继续处理，不因提交窗口过期而自动消失。

任课教师会收到持久站内提醒，并通过已有邮件队列接收通知。邮件投递异常会保留状态，站内案件不会因此丢失。点击提醒可定位原课次、学生记录及前几次情况；合并课堂后的历史仍按原轮次查找，不猜测替代课次。教师可批准为相应状态或填写理由驳回；学生结果随处理更新。

作废或替代的轮次不能新申诉，待处理案件会取消并保留记录。合班后历史学校绑定暂停；删除课堂后保留只读归档，提醒回到通知中心，不继续执行原远端任务。

## 智慧课堂账号与核对

管理中心的独立智慧课堂账号页，或点名浮窗中的“账号与同步设置”，用于配置当前教师自己的学校账号。使用现有学校账号，不要求学生提供密码，也不要求教师填写不明来源的接口密钥。凭据按服务端现有加密机制保存，页面不回显原密码。

当前可用范围是：读取授课班和点名、精确绑定课次、生成差异预览、持久后台逐人回读、显示冲突和核对结果。原有智慧课堂导入、历史 PDF 和成绩来源继续保留。

**学校端自动开始、结束和逐人改签尚未开放。** 官方小程序界面操作已经在获授权的课次受控核验，但公开网页资源不足以证实小程序的完整写入协议。因此当前流程为：

1. 核对学年、学期、周次、星期、节次、课程及合班信息；在官方小程序完成开始和结束点名。
2. 在本地选择学校实际存在的点名记录，检查点名编号及完整名单后绑定。只能绑定能够可靠匹配的学校记录；补点名时间与原课次不符时，目前不能强行绑定，应保留在官方端人工核对。
3. 生成差异预览，在官方端按已经确认的本地结论进行必要调整。尚待确认的学生不自动转为缺课；已有请假、研学、实践或志愿状态受到保护，不能被一般出勤推断覆盖。
4. 点击“后台逐人回读核对”。关闭浮窗不取消持久任务。只有回读一致的学生才计入已核对；冲突、未匹配、未读取和部分完成分别显示。
5. 学校会话失效时，重新验证原学校账号后续接；若换了学校账号，应重新选择授课班和点名，避免把旧绑定转交给另一个身份。

“逐人回读完成”只证明学生状态核对，不证明平台自动开启或结束过学校点名。不能把本地作废理解为已经删除学校原记录。

## 维护与故障核对

- 401、409、网络中断或服务重启后，先检查原始记录是否仍在待重试队列、是否已提交及内容摘要是否一致；不要删队列重置计时，也不要盲目重复一个结果不明的旧接口写入。
- V2 材料收件与行为上报共用有限次数的幂等事务恢复：失败后先回滚、释放连接，再按原批次和首次服务端接收时间重试。数据库已提交但响应丢失时，读取原回执，避免重复累计时长；权限失效等业务错误不按临时数据库冲突重试。
- 后台收件与聚合有独立状态。排查应同时看收件回执、应用状态、投影版本和结算水位，不能仅凭健康接口正常判断业务已恢复。
- 周快照后台逐个学生、逐个课堂提交，避免整批统计长时间占用材料进度相关行锁。中途失败后沿用本次执行周次重新处理，同周记录仍可更新；已经成功的学生不会因重试重复增加修为。整个任务的成功状态由调度器最终确认。
- 已存在且有效的 PostgreSQL 性能索引由系统目录确认后复用；无效索引或名称冲突会明确失败。缺失索引的创建具有超时限制。其他初始化锁竞争仍可能引发有界重试，最终须核对记录守恒。
- 原始课堂访问默认保留九十天；待处理申诉保护有关证据。历史已经固化的结果不因原始证据到期而重新推断为缺课。
- 上线执行既有隔离构建、停写备份和迁移流程，保护 `/lanshare/data`。后台角色逐个完成初始化，调度器最后启动，再重建入口代理；上线核验和 Git 推送分别记录。

# 散修手册目录修复（2026-11-08）

## 故障与原因

线上“在线文档 → 散修手册”打开时报“服务器内部错误，请稍后重试”。只读日志确认 `GET /api/materials/9714` 的详情接口与目录树接口均在 `int(material["root_id"])` 处因 NULL 抛出 TypeError。只读检查显示仅该根目录缺少 `root_id`，两本子手册 9715、9716 的父目录、根目录、文件哈希正常，正文没有丢失。

旧版播种程序在 PostgreSQL 插入目录后读取不存在的 `cursor.lastrowid`，异常被调用者捕获后，未完成的目录仍可能提交。历史修复 `82358b4e` 改用共享插入助手，仅覆盖新建路径；查到已有目录时直接返回，历史 NULL 未被补全。

## 修复范围

`wanderer_manual_library._ensure_folder` 在复用已有顶层手册目录时检查根编号；仅当其为 NULL 时条件更新为该目录自己的 ID。更新保留父目录为空与根编号为空的条件，不替换已有有效根，不改变内容、ID、时间、权限、索引或课堂发布关系。调用者仍拥有提交事务的责任。正常播种不会增加写入。

应用现有启动流程调用 `ensure_wanderer_scheduled_tasks`，从而重新执行幂等播种、恢复历史目录。后端修复没有新增请求时扫描或数据库迁移。

浏览器检查同时发现手机默认展开详细信息窗格时，文件标题与操作区横向挤压，元信息逐字纵排，并将正文高度压为零。`materials_library.css` 仅在不大于 760px 的领域布局中允许标题栏换行、操作区独占下一行，并禁止正文被 flex 压缩；正文由既有内容区滚动。没有新增共享组件、材质、事件、固定高度或第二套滚动监听。

# 课堂随机分组与 Python 期末项目核验

2026 年 11 月 21 日，本地工作区完成修复和隔离演练。

## Python 课使用设置

课程《考核实施与评分》规定 63 人分 13 组。教师打开 Python 教学班的「小组协作 → 创建分组」，先核对参与人数，再输入方案名「Python 期末大作业」，选择「立即随机分配全班」，每组最少 4 人、最多 5 人，组数 13。创建后应有 11 个五人组、2 个四人组。学生在同一课堂查看自己的小组、参与对话，并在第 13 周开始前推举组长。项目期间如需讨论或调整目标，保持方案进行中。

合班使用所有关联行政班的在籍成员。已确认的重修、免修学生默认免于抽组，教师可从大屏单独加入。实际参与人数与 63 有差异时，应先核对名单，再确定人数范围。题号与组号分别登记，第 14 题备选。

本课程总评按小组 40%、个人 60% 计算，登记组长加 5 分，封顶 100。课堂分组本身只建立协作名单。作业另行启用「按小组完成」会使用平台的个人作业分与队友互评分规则，两种用途应由教师分别决定。

## 调查发现及处理

| 环节 | 调查发现 | 本轮处理 |
| --- | --- | --- |
| 创建 | 原课堂按钮只建立空组。教师要等学生加入，或逐人拖入 | 教师可直接随机分配全班，也可保留学生自行加入。显示参与人数，在同一事务内按人数最少的组均衡分配。相同创建请求重试返回同一方案 |
| 补分和手动调整 | 旧流程容易留下少人组；重分可能变更教师指定的组数、已有队伍与组长 | 随机补齐只分配尚未入组的参与学生。少人组调整保留组号、组长与已有组内记录，优先只移动达到人数要求所需的成员。手动分配支持手机、键盘与拖放 |
| 手机大屏 | 手动分配成功后，名单刷新会使大屏提前关闭 | 大屏的生命周期绑定课堂面板，关闭后焦点回到相应方案按钮 |
| 归档 | 部分入口仍能改动历史名单；教师配置作业时找不到已结束的方案 | 归档与过期方案保留成员和对话供查看。教师可选择同课堂已有成员的历史方案。历史人数按实际存档成员计算 |
| 作业与互评 | 互评窗口重开后显示默认分；先出分、后收到互评时，已显示成绩可能与新互评不一致 | 回显本人给过的分数，变更互评后从原始作业分重新结算。已有提交、互评或成绩的小组受名单保护。其他组还能在容量允许时继续补分 |

## 复验

用 `npm run build` 生成正式资源，再用 `venv/Scripts/python.exe tools/validate_classroom_grouping.py` 启动临时回环服务与 Chrome。工具新建两个行政班、63 名参与者和 1 名已确认重修学生，记录的账号、互评和作业均来自本次合成数据。结束时先关闭服务，再清理运行目录。

- 教师创建、响应丢失重试、刷新后名单一致、学生查看与历史对话回看。
- 390 像素触屏视口完成学生自行加入、教师手动分配、随机补齐和单独加入免修学生。
- 归档名单绑定、学生实际队友、评分回读与换组冲突通过实际作业 API 检验。
- 真实 PostgreSQL 双连接测试核对同班抢位、重复创建、批量分配与学生入组并发、作业首次提交与教师调整名单并发。不同教学班可并行操作。

正式静态构建 `a2b0a6ebb24b` 在两次独立合成课堂演练中均通过 3 项浏览器与实际 HTTP 测试。12 个同时发起的快照请求逐人比对了 63 人与 13 组的对应关系，两轮分别耗时 1.47 秒和 1.17 秒。此数据衡量本机回环服务的整批读取耗时。[桌面与手机演练](../.codex-temp/evidence/classroom-grouping-hblrtmuv/results.json) · [独立复验](../.codex-temp/evidence/classroom-grouping-l0rihwy8/results.json)

# 作业与试卷 JSON 编写规范（八题型，2026-11-12）

新建试卷使用 [八题型模板](templates/assessment-eight-types.json)。旧四题型示例、已发布作业和历史审核记录只用于理解既有课程内容，不再作为新题包的字段模板。历史题目、答案、学生提交与草稿不因本规范自动转换。

本规范依据 `classroom_app/services/assessment_question_contract.py`、`exam_json_service.py` 和 `deterministic_exam_grading.py` 的实际合同。运行时模板 `EXAM_JSON_TEMPLATE` 是唯一维护源；仓库 JSON 由 `get_exam_json_template_text()` 导出，并有字节一致性测试。导入前应确认目标平台已支持这版八题型；不能为适配旧平台而把新题型随意降级。

## 一、先设计课程内容，再选择题型

题型是作答方式，教学目标决定是否使用。完整模板展示八型，不要求每次作业用齐八型。课程正式作业优先覆盖相邻两课的核心内容，并按需要复习旧知识；每份题包写清知识范围、建议完成时间和必要环境。

先列“知识点—学习目标—题型—题数—分值—预计时间”。建议由识别、解释到运用、分析递进。判断题应陈述完整条件；多选题必须明示漏选、错选的处理。程序题写清输入或初始数据、处理、输出、边界条件和测试要求。综合题可融合文字、计算、代码与附件；需要独立选项或多个独立填空控件时拆成对应题型，不能虚构 `subquestions` 等未实现结构。

已有教学分类仍可沿用：例如“解释原理”通常用简答，“诊断原因”用分析，“编程实现”用程序，“操作+验证+解释”用综合。不要把所有长答案都机械写为 `textarea`，也不要仅因有一段示例代码就把选择题改为程序题。

## 二、根结构和共同字段

JSON 根对象使用 `title`、`description`、`exam_config`、`grading`、`pages`。每个页面包含 `name` 与 `questions`。输出必须是合法 UTF-8 JSON：不能加注释、尾逗号或 Markdown 外围围栏；使用 JSON 序列化工具处理换行、引号和反斜杠。

| 字段 | 新题包要求 |
| --- | --- |
| `title` | 清楚标明课程、课次或考查范围 |
| `description` | 学生可见：题数、总分、建议时间、提交方式、AI 范围；不要放答案 |
| `exam_config.allow_student_ai` | 布尔值，默认 `false`；AI 规则见第五节 |
| `grading.total_score` | 正数，等于所有题的 `points` 合计 |
| `grading.description` | 整卷评分口径，不放学生作答必需的数据 |
| `grading.style` | `strict`、`medium`、`loose`、`rescue`，一般用 `medium` |
| 每题 `id` | 整卷唯一且稳定，建议 `p1_q1`；编辑后不要无故改名 |
| 每题 `type`、`text` | 下表中的规范值与完整 Markdown 题干 |
| 每题 `answer` | 非空标准答案，类型见下表；不得用“略”“见教材”替代 |
| 每题 `points` | 正数；题内各得分点之和与此值相等 |
| 每题 `grading_guidance` | 写清每个得分点及分数、等价解法、部分分与替代证据 |
| 每题 `deduction_points` | 写清对应扣分，避免同一错误重复扣分；不与得分点矛盾 |
| 每题 `explanation` | 建议填写理由或关键过程，供教师及允许查看的解析场景使用 |
| `placeholder` | 可选短提示；不是标准答案，也不替代题干条件 |

学生题面不会获得标准答案、解析和教师评分字段。为保证阅读时能看到分值，模板在 `text` 开头写了“（X分）”；需要的单位、条件、提交内容必须放在题干或学生可见说明里。不要把参考答案塞入 `placeholder`、附件说明或其他自定义字段。

## 三、八题型规范值

| 教学类型 | `type` | `answer` | 关键约束 |
| --- | --- | --- | --- |
| 单选 | `radio` | 字符串，如 `"C"` | 一个正确项；选项可按题目需要有3、4、5项，至少2项 |
| 多选 | `checkbox` | 字符串数组，如 `["A", "C"]` | 至少2项；正确项不重复，漏选/错选规则清楚 |
| 判断 | `boolean` | 字符串，如 `"A"` | 推荐明确给出 `["A. 正确", "B. 错误"]`；与单选共用选择控件 |
| 填空 | `text` | 按空位排列的字符串数组 | 新题必须同时有 `blanks` 和 `{{编号}}`；见第四节 |
| 简答 | `textarea` | Markdown 字符串 | 分点解释、列举、短推导 |
| 分析 | `analysis` | Markdown 字符串 | 说明证据、原因、步骤和结论 |
| 程序 | `code` | Markdown 字符串，可含代码围栏 | 给完整代码/可判定算法和测试预期，不虚构自动运行能力 |
| 综合 | `comprehensive` | Markdown 字符串 | 多任务评分点独立，可含代码、分层列表、附件证据 |

选项推荐连续字母 `A. …`、`B. …`，答案写对应字母。模板中的 `boolean` 表示判断题型，不表示标准答案必须是 JSON 布尔值。新文件统一使用上述规范值，不依赖旧别名。

## 四、动态编号填空

每个空位有自己的稳定正整数编号（字符串），题干标记与 `blanks` 一一对应：

```json
{
  "id": "p1_q4",
  "type": "text",
  "text": "（10分）Python定义函数用 {{1}}，返回结果用 {{3}}。",
  "blanks": [
    {"id": "1", "answer": "def", "placeholder": "定义关键字"},
    {"id": "3", "answer": "return", "placeholder": "返回关键字"}
  ],
  "answer": ["def", "return"],
  "points": 10,
  "grading_guidance": "编号1正确5分，编号3正确5分，按空分别评分。",
  "deduction_points": "错答或空缺只扣对应空位5分。"
}
```

- 新题通常从 `1` 开始连续编号；删空后允许保留 `1、3` 等不连续编号，不把其它编号整体挪位。
- 每个编号在题干只出现一次，在 `blanks` 中也只出现一次。不得出现缺少定义的标记、没有题干标记的空位、`0`、负数、`01` 或任意文字编号。
- 输入框数量就是 `blanks.length`，没有“最多4空”的平台限制。旧指引中的“≤4空”只是控制单题阅读负担的教学建议；复杂题仍应考虑拆题。
- `blanks` 顺序决定输入框及 `answer` 的对应顺序；建议与题干出现顺序一致。`blanks[].answer` 为标准答案，顶层 `answer` 必须逐项一致，不是多个可接受答案的集合。
- 同义答案、单位和允许格式写进 `grading_guidance`，不要塞进答案数组或把多空答案合成一个字符串。
- 历史 `text` 没有 `blanks` 时继续使用旧单框模式，不自动猜空位、不拆旧答案。只有教师明确重编该题时，才核对后添加编号结构。
- 学生作答使用数组并保留空字符串占位；`blank_ids` 是提交/草稿数据，不是教师标准答案字段，不要混进出题模板。

## 五、AI 协助范围

默认设置 `exam_config.allow_student_ai: false`。需要协助的开放题单独设置 `allow_ai: true`。模板只在综合题演示题级开放；其他题不开放。整卷设置 `true` 会开放全部题，题级 `false` 不能用于撤销整卷授权。

教师在说明中写清可以求助的内容和学生必须完成的验证。允许求助不代表可以直接抄写答案。AI 入口仍受服务端的发布状态、作答时间、学生访问权限和提交状态校验；修改按钮或客户端 JSON 不能绕过授权。`ai_policy_note` 只是非标准说明文字，不能作为授权开关；新版模板不使用它。

闭卷考查一般全部关闭。开放作业可只开放程序调试、分析或综合题；题级许可仅表明是否开放，不代表系统能自动核验所有学术诚信要求。给外部 AI 的材料应使用虚构或匿名数据。

## 六、Markdown、代码和附件

题干、选项、答案、解析以 Markdown 表达。优先使用段落、`**加粗**`、有序/无序列表、反引号行内代码，以及带语言名的三反引号围栏。JSON 字符串中的换行写为 `\n`，代码保留四空格缩进。不要依赖原始 HTML、脚本、复杂插件语法或编辑器内部数据。

编辑器的自动序号、对齐和代码块按钮是交互功能，不需要在 JSON 中增加 `editor`、`code_blocks`、`auto_height` 等字段。程序题代码块用于编辑与展示；当前题型本身不承诺沙箱执行、隐藏测试或自动判题，不生成伪造的运行结果。

只有 `textarea`、`analysis`、`code`、`comprehensive` 保留 `attachment_requirements`。可选示例：

```json
{
  "enabled": true,
  "required": false,
  "min_count": 0,
  "max_count": 1,
  "allowed_file_types": [".png", ".jpg", ".txt"],
  "allow_drawing": true,
  "description": "可选：一张运行图或一份文字记录。"
}
```

`min_count > 0` 即意味着必传；必传时要明确至少交什么，`max_count` 不小于 `min_count`。类型和大小仍受平台上传安全策略约束，不能仅靠模板突破限制。依赖实验环境的题应允许报错/现状和排查过程作为指定的替代证据，并写清替代路径能得哪些分；可选附件不能暗中设置为满分前提。

## 七、评分边界与交付检查

单选、判断可按选项固定判分；多选全对可固定满分，漏选/错选仍须根据 rubric 判断。编号填空只有位置匹配且每空达到确定性匹配时直接固定满分；部分空正确由评分指导决定部分分，不自动等分。确定性短文本匹配会忽略部分大小写、空白和标点，并接受相等数值；不要用这种题型单独考查大小写或格式的严格区别，可改用分析/程序题。

教师仍需核对参考答案、知识边界和实际工作量。解析成功不等于题义正确，也不等于已导入、发布或运行代码。

交付前检查：

1. JSON 可解析，且通过真实 `parse_exam_json_text()` 完整导入校验。
2. 八型规范值、整卷题号唯一、选项字母与标准答案对应；不能只检查字段非空。
3. 全卷分值之和正确；每题的得分点、扣分点与替代计分自洽。
4. 新填空编号唯一、一一对应；`answer` 与 `blanks` 同序、等长、一致。
5. 主观题参考答案可判定；代码与给定测试实际核对，不把预期当实测。
6. AI 配置与学生说明一致；附件必传/可选与评分一致。
7. 新题包在平台预览后再导入或发布；不会覆盖已有学生作答的历史卷。Git 提交/推送不替代平台导入。

在 lanshare 仓库运行模板回归检查：

```powershell
python tools/test_backend.py --pattern test_assessment_json_template.py --report .codex-temp/evidence/assessment-template-tests.json
```

校验实际新题包时，在 lanshare 仓库执行下列只读命令，把末尾路径替换为新文件；它不会连接业务数据库或导入发布：

```powershell
python -c "import sys; from pathlib import Path; from classroom_app.services.exam_json_service import parse_exam_json_text; result=parse_exam_json_text(Path(sys.argv[1]).read_text(encoding='utf-8-sig')); print(result['stats'], result['grading']['total_score'])" "C:/课程目录/新作业.json"
```

## 八、给课程生成 AI 的任务段落

> 先读本规范与八题型 JSON 模板，结合教师指定课程和课次生成新题包。先核对既有课件的知识边界，列覆盖与分值计划，再输出合法 JSON。八型按需选择，不为凑全题型超纲。新填空必须用唯一 `{{正整数}}` 与 `blanks`，并按同序填写 `answer` 数组；判断使用 `boolean`，分析/程序/综合分别使用 `analysis`/`code`/`comprehensive`。每题提供可验证标准答案、正数分值、具体得分点与扣分点，全卷分值相等。题干用 Markdown，代码用语言围栏。整卷 AI 默认关闭，只按教师允许在开放题设置 `allow_ai: true`。不要复制旧题包字段结构，不改历史答案和提交，不虚构运行证据、不部署或发布。交付前调用当前导入校验器，报告题数、分值、题型、填空数量与验证结果。

# 自动点名：实际时间、可选网络限定与结果定位

## 问题与修复

线上只读诊断发现，截图对应轮次的 42 人全部待确认，其中 40 人有窗口内服务器接入记录，39 人符合原网络条件。39 人被旧版“20 分钟内形成至少 5 人且超过全班半数的时间峰”阻断；另有 2 人无可信接入、1 人网络未对应。因此问题不只是教师与学生网段不同。

新记录采用逐人服务器证据判断：学生属于本轮名单，在实际记录窗口内有已认证的服务器访问记录，即可正向认定出勤，不再等待其他同学凑成时间基准。没有证据仍为待确认；教师的病假、事假、迟到等人工决定不被自动计算覆盖，已有正向事实不因后续证据不足自动降级。

## 教师操作

- 新增“限定课堂网络”开关，新策略默认关闭。开启时展开一行一个的 IP/CIDR 输入，建议值取服务器识别到的教师连接网段，教师可调整；关闭时不按 IP 判定。开关和有效网络设置用于后续课次，每轮保留自己的策略快照。
- 点击“开始记录”时，以服务器收到请求的时间为实际开始；预计时长默认取本地课次长度，缺失时用可修改的 90 分钟，范围 1—240 分钟。临时补课不要求实际上课日期与原课表日期一致。
- 原课次的课程、学期、周次、节次和学校绑定身份保持独立。临时上课不会把记录自动绑定到当天另一节智慧课堂课次；未对齐时仍可本地记录。
- 顶部显示服务器基准的已上课分钟数、实际开始时间及 IP 限定状态。浏览器用单个单调时钟更新文字，不以学生或教师终端时钟作考勤依据。
- 普通结束后显示补报等待及倒计时；等待到期显示后台排队状态，完成后自动更新统计与卡片。立即结算保留真实任务阶段、失败说明、恢复和确认中断重算。
- 卡片保留姓名/学号搜索与各出勤状态筛选，新增登录跨度、学习时长等升降序。未知时长放在末尾，筛选/排序不丢失选择和未保存的改签草稿。

“登录跨度”是首末服务器接入之间的跨度，不代表连续在线；“学习时长”沿用已有经过验证并去重的学习区间。两者只辅助查看，不设最低学习时长门槛。关闭 IP 限定能证明本班学生在该时段访问平台，不作物理到达教室的额外推断。

## 旧待确认记录

已有轮次不因部署、普通扫描或刷新自动升级规则。教师在旧轮点击“立即结算”时，会看到采用新规则的确认说明；确认后沿用原始记录窗口和原 IP 限定，重新按逐人服务器证据判断，并记录规则升级审计。人工改签与原考勤历史保留。原来不符合 IP 或缺少服务器记录的学生仍需核对，不能无证据全班改成出勤。

本次同时发布此前本地审查的单人“保存／保存并推送”和立即结算功能；前两阶段报告仍是其当时源码与验收快照。

## 实现边界

新增字段为 `login_attendance_policies.enforce_network`，默认值为 0；新增 `(student_id, received_at_ms)` 索引支持服务器时间检索，不清空或重建原表。旧轮策略 JSON 不批量修改。

新规则仅使用服务器访问时间；关闭 IP 时可补充同课堂、已处理成功的服务器活动回执。客户端自报时间、待处理或隔离回执不能直接生成出勤。学习区间继续独立统计，不改动学习积分或原计时机制。

每轮保留原策略、实际时间及规则版本，重算受现有版本校验、任务代次、执行标识和学校未知请求保护约束。课程课次对齐和学校写入门禁保持原有合同。验证使用隔离合成运行环境；线上诊断与上线核验只读，不创建真实测试考勤或强制使学校 token 过期。

发布版本、Git 推送、数据库迁移保真、正式构建与上线核验结果见本轮发布报告。

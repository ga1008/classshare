# 教学删除与合班：业务审查及 C 确认接入边界

基线：本地实现检查点 `0283be34`。前半记录改进前的只读审查；末节记录本批实际实现与验收边界。本批教学测试仅用临时 SQLite 数据库及浏览器组件夹具，没有连接生产或本地日常业务数据库。实现不等于生产验收。

## 当前业务事实

| 操作 | 正常 Web 当前行为 | 尚未闭合的风险 |
| --- | --- | --- |
| 删除班级 | 仅教师有权管理的班级；学生、主课堂、作业及学习历史等引用阻断 | 检查漏合班的非主班级关联，以及部分无外键逻辑引用；没有影响快照或版本确认 |
| 删除课程 | 校验课程管理权限；课堂、作业、文件阻断；有教务排课需二次确认；删除课次模板，教务记录的课程外键置空 | 学习文档包、教学文档等无外键课程引用未纳入阻断；旧界面说明仍暗示能级联删除课堂；没有绑定第一次确认的完整版本 |
| 删除课堂 | 仅课堂所属教师；当前公布成绩阻断；删除课堂与合班 links，其余依数据库外键 | 实际混合级联删除、置空、保留旧 ID 三种行为。不能把“课堂下的作业、互动与成绩均删除”当成事实 |
| 合并课堂 | 同教师、课程、学期，行政班集合互斥；主课堂保留；作业并存加原班级后缀；成绩版本续接；源课堂删除；保存同事务 JSON 档案及日志 | 用户确认未绑定完整预览版本；课次引用覆盖不全；目标无课次时仍可删除源课次；运行中生成任务持有旧地址；部分逻辑作用域字段未被登记守卫发现 |

源码入口：`classes_courses_classes.py:745`、`classes_courses_courses.py:290`、`classes_courses_offerings.py:564`、`offering_merge_service.py:360/535`。引用阻断在 `base_resource_modes_service.py:157/229`。合班原业务决策见 `combined-class-offering-plan-2026-08.md`：源课堂物理删除、作业并存、仅本人教师、档案供人工恢复，均已明确；本批不把它替换成隐式软删除或一键回退。

## 已实际验证的问题

1. 在完整 schema 的临时数据库执行现有课堂删除 SQL 后，原 `assignments.class_offering_id`、`class_offering_learning_materials.class_offering_id` 仍为已删除 ID，原作业提交也仍存在。二者当前无 offering 外键。`manage_offering_hub.js` 的全删除提示不准确。历史成绩公布同样有意保留；能保留行不等于有完整的历史访问入口。
2. 正常合班后，`smart_classroom_checkin_sessions` 及 `smart_classroom_checkin_students` 的课堂 ID 已迁入主课堂，但 `session_id` 均被源课次删除的 `SET NULL` 清空。合班目录仅三种课次引用有重映射规则，遗漏了这两张表。
3. `execute_offering_merge` 在已有 SQLite 事务内调用会触发 `cannot start a transaction within a transaction`。因此不能直接放入用户操作账本事务；应复用调用者事务，禁止隐式提交。
4. `course_doc_packs` 以课程和教师为归属，没有课程外键。删除其课程不会删除材料包、生成状态或 blob，原课程关系却失效。课程删除应先明确阻断该业务引用；不能为清空数据库引用而删除可复用材料。

尚属源码推导、需专项回归证明的边界：

- `blog_posts.visible_class_offering_id` 未被只搜索 `offering_id/class_offering_id` 的守卫发现，合班删除源 links 后会改变原定向帖子的可见性；需按原可见性规则处理，不能机械扩展读者范围。
- `polls.origin_class_offering_id` 虽名为来源，仍被学生自定义投票修改参与者使用；不能当作纯历史字段忽略。
- 目标无课次时 `_session_id_map` 返回空映射；源生成任务的 session 外键是级联删除，学习记录的 session 外键是置空，而无外键材料绑定可能留下旧 ID。
- 运行中的文档生成器已经取出旧 `task_row`，仅迁移数据库行不能迁移该内存状态；正常生成任务不应因 Agent 请求被静默取消。合班应在锁内发现并提示等待，不持事务等模型。
- 学习文档包属于课程，不直接属于课堂；课堂迁移应处理绑定关系，保留包、目录、素材及每课生成历史。
- Agent 和 scheduler 的 payload、历史链接及回执可能引用旧课堂；既有回执是历史事实，不应批量改写。执行中的领域操作必须按实时资源权限拒绝失效目标；需要继续工作的任务由新授权及已有回执恢复，不能借合班复活旧 token。

## 最小改进与接入次序

1. 先提取普通 Web 共用的教学生命周期服务。空班级和未被业务引用的课程提供影响预览，完整引用值摘要生成 revision；操作时锁资源、重新校验当前权限和引用、比较 revision 后删除。显示将删除、将解除关联、阻断三种事实。新增引用不得因列表截断或相同计数而漏检。
2. 保留课堂原业务删除语义，先提供真实影响审查；含业务课堂的 C 删除保持 `needs_adapter`，直到逻辑引用、历史访问与后台任务处置得到完整证明。不能用一个强制删除参数消除阻断，也不把已有作业或材料无声转成垃圾数据。
3. 合班复用既有目录和原子迁移，补齐课次及逻辑作用域引用；当前无目标课次且有引用时阻断。预览返回明确影响、警告和完整 revision；执行锁内重读，改动任何被迁移/归档数据或策略均使确认失效。已有“最近课次”规则必须在预览中明确显示映射，不改变作业并存语义。
4. 与排课锁序对齐到课程、课堂、作业；生成任务/课次遇反序竞争采取立即冲突退出，避免在锁内等待异步模型。仅未开启 SQLite 事务时取得写事务；启动期已迁移的 schema 不在预览执行 DDL。档案 token 使用不会在同秒碰撞的标识。
5. 正常 Web 也消费预览 revision。变更选中的主课堂、过期预览、重复点击、响应失败均不能沿用旧确认；失败保留填写内容，冲突要求重新预览。合班成功展示主课堂链接、档案编号和结果，不能宣称可一键撤销。
6. C 只负责当前用户确认入口：模型可提出操作和目标，无法产生本人确认。现有终态任务 owner、当前 session、fresh-user 账本、权限指纹、提案 marker 与业务共用一次事务。接入范围由实际通过的动作决定，不把只读影响预览计成删除能力。

建议领域接口：`prepare_teaching_confirmation(conn, action, params, user)` 返回绑定版本的 `params` 和 `review`；`execute_teaching_confirmation(conn, action, params, user, confirmation_inputs)` 只做领域操作、不 commit、不另开账本。公共 C 引擎由根任务统一，避免为教学再写一份身份和幂等流程。核对信息包括 `kind/title/summary/impact_sections/warnings/blockers/can_execute/expected_confirmation_text`；真实用户提交 `accepted_warning_codes`、`confirmation_note` 和手工输入的 `confirmation_text`。

## 验收约束

- 正常 Web 与 Agent C 对同一主体/参数结果一致；普通教师、超管动态属性、同编号学生/其他教师隔离，合班仍仅所属教师。
- 预览不写库；更名、同计数替换引用、增加材料/学习/成绩记录、目标变化使旧确认 409；二次预览后可继续。
- SQLite 与真实 PostgreSQL：确认并发只生效一次；课程/排课/生成/评分竞争无反序死锁；提交故障使业务、账本与提案 marker 一同回滚。
- 合班保留作业提交/评分、公布版本/学生快照、学习和考勤课次关系、主材料列表、排队生成任务；未核实的复杂作用域不得假定自动迁移安全。
- 不从浏览器或模型清理共享 blob；档案恢复必须先隔离演练、比对合并后新增写入和唯一约束，再由运维实施，不把还原整库当作单次操作撤销。
- 能力台账只登记通过以上闭环的具体动作；生产部署、真实 DSH 操作和完整课堂删除仍须独立验收。

## 本批实际实现与收尾限制

已接入 C 本人确认的三个动作：`delete_empty_class`、`delete_unreferenced_course`、`merge_class_offerings`。普通入口分别为 `DELETE /api/manage/classes/{class_id}`、`DELETE /api/manage/courses/{course_id}`、`POST /api/manage/class_offerings/merge/execute`；对应 `delete-impact` / `merge/preview` 提供完整核对版本。上述删除与合班没有登记为 B 通用请求能力。既有教学 B 九项创建、成员和排课能力维持其原限定参数。

普通 Web 与 C 共用 `teaching_lifecycle_service`、`agent_teaching_confirmation_actions` 和既有合班业务服务。班级/课程预览涵盖显式阻断、级联删除和历史解除关联；JSON 合班映射的候选扫描也受 50,000 行/16 MiB 上限约束，超过即拒绝，不生成截断确认。合班迁移快照受 100,000 行/32 MiB 上限约束，绑定参与课程、行政班和学生归属；同计数改动也改变版本。SQL archive 和源删除同事务，服务不隐式提交，SQLite 已有事务可复用。

普通删除需逐项接受警告、填写说明并手工输入名称；普通合班需当前版本、不可逆声明及手工名称。页面更换目标、旧响应、409 或未收到确定结果均不能沿用旧确认，保留输入并要求重新预览，提交中防重复和关闭。界面使用中文业务名称，不显示数据库表名。移动端已检查宽度及 Escape 焦点恢复。

已修正两类真实课次引用的合班映射，保留考勤场次和学生记录的 session 关系；无目标课次但存在课次引用、运行中的材料生成、源课堂定向博客及投票分配均阻断。`poll_assignments` 包括管理中心创建的投票，不能因 `origin_class_offering_id` 为空而扩大参与者。排队生成任务可随真实目标与课次迁移，未取消领域任务或删除共享 blob。

引用并发保护的实际范围：

| 写者 | 当前保护方式 |
| --- | --- |
| 有真实课程/课堂/课次外键的学习数据 | 保留原外键，并在合班锁住实际父行；不以外键证明所有逻辑引用都安全 |
| 创建作业及三种教学文档、变更文档课程归属 | 共享 course → offering 锁后重读目标；文档已持行锁时 NOWAIT 冲突退出 |
| 材料包创建 | 写包前锁课程，保留正常包/文件副作用与事务边界 |
| 合班班级 links、定向班级博客、教务 JSON 班级映射 | 共同班级父锁，引用变更与删除不能在检查后交错 |
| 分组及邀请 | 复用既有课堂成员锁；未重写原协作业务 |
| 投票分配及文件上传范围 | 写前复核真实 course/offering；文件还保护 class；已有领域锁时 NOWAIT，失败回滚 |
| 原账单范围与历史 Agent 回执 | 按原语义保留，未批量重写历史事实 |

测试证据见 `agent-teaching-lifecycle-verification-2026-09-10.json`。本批新增普通 Web 7 项真实 HTTP/SQL/限额检查、6 项合班专题、3 项严格整数列表、4 项实际 Chrome 组件测试；根任务另外完成 C 提案与回执的 8 项真实 HTTP 检查。权限审阅者在三文档锁稳定后补了考核计划/逆向材料 31 项通过，源 SHA 前后一致。测试之间存在重叠，不能把分组数量简单相加当独立覆盖率。

**上线前阻断**：新增教学父资源/上下文锁未做本批独立 PostgreSQL 竞争验收；需核验真实数据库的课程删除、文档/作业写入、合班和上传/投票交错后，才能部署本批生命周期改动。本次按用户要求在已有局部回归后收尾，不继续扩展测试或业务。另：含业务课堂的原硬删除仍有逻辑引用与历史入口问题，本批未将其开放给 Agent；全量课堂删除/归档、自动撤销合班、真实 DSH 三动作完整任务和生产验收均未完成。JSON 合班档案只供人工核查与隔离恢复，不宣称一键撤销或全生命周期完成。

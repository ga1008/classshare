# 首页与课堂页第二版：界面与交互改进计划

日期：2026-09-07。状态：**调查完成，设计提案，尚未实施**。代码基线：`3aa41bc1`；主要对照 `c79f1674`（改版前）、`79ed8c4b`（9月5日收敛版）以及 `bcef3fe0`、`9176ea10`、`ea39ae93`（课表与日历后续修正）。

## 1. 设计结论

第二版要恢复清楚的功能区域、可识别的操作入口和连贯的状态变化。保留上一轮对重复统计、冗长说明和错误指标的清理，用稳定布局、适量边框、轻柔阴影、明确按钮、青春色彩与功能性动画，让学生看得懂、找得到、点得准、回得来。

本次问题涉及三个层面：**首页的视觉分组变弱，课堂导航被收得过深，任务入口缺少可点击线索。** 单纯加颜色或把旧版整页恢复，都不能完成改进。

明确采用以下方向：

1. 学生首页以常显的“课程日程”集中承载3D课表、日程和完整授权课堂入口，删除独立“我的课堂”区；未排课、本周无课和往期课堂仍能在这里查到。
2. 课堂页恢复可横向拖动的课次小卡片。拖动只浏览；点击或键盘激活即选中课次并打开二级详情浮窗。底部使用紧凑按钮；点击“进入本次学习材料”后，0份显示空态，1份可访问材料直达现有阅读页，多份才展示列表。
3. “课堂任务”对学生呈现为“作业与考试”；标题可进入，操作有按钮，已提交与历史记录常显可达。
4. 参考博客中心的实体表面、分组工具条、主次按钮和重复卡片节奏，补全进入、退出、加载、失败与返回的过渡。
5. 学生配色只用一个显示当前配色名的下拉选择，支持即时预览与账号保存；课堂本课修为值移到顶栏并可直接打开原详情。作业与课堂活动并列，主区取消所选课次材料面板。
6. 当前请求止于调查与第二版计划。后续实施应以本文件的界面方向替代9月5日方案中冲突的布局条目；其权限、数据口径、性能与业务保全要求继续有效。

本文件已按用户本轮追加意见统一修订。初稿中的独立课堂区、主区材料面板、单击课次仅选择、单列修为工具带及额外配色入口均已被取代；以下历史对照描述保留为调查证据，不作为现行布局决定。

## 4. 视觉与交互设计原则

### 4.1 让视觉形式准确表达功能

采用“清爽的学习桌面”：浅中性页面底色、白色模块、细边框、克制柔影。模块头固定包含标题、范围/数量及操作。组内紧凑、组间有距离，不能让一个功能的按钮漂到另一块内容附近。

- **边界**：课程日程、待处理、作业与考试、课堂活动各有可辨识表面，课次详情和材料在二级浮窗承接。模块内用轻分隔线或重复卡行，不给每个字段再套框。
- **层级**：名称与动作先读，状态与日期其次，说明最后。单项数据少时缩短面板，不用固定巨高空白凑对齐。
- **青春色**：学生主行动默认采用现有靛蓝，可按4.3节切换个人配色；材料类别、完成、时间提醒和风险保留各自稳定的语义。颜色与文字/图标共同表达状态。
- **点击线索**：导航卡和按钮在静止时就能辨认；hover增强确定感，不能依赖鼠标扫过才发现功能。
- **留白**：用于分组与阅读，不用于掩盖未设计的布局。单课堂、单作业和零材料是正式设计状态。

### 4.3 学生个性化配色（用户补充要求）

配色是第二版正式功能。首期提供五组完整预设，每组包含行动主色、主色上文字、浅选中底、页面底色、边界与焦点色；以统一结构承载不同偏好。

| 预设 | 视觉方向 |
|---|---|
| 经典靛蓝（默认） | 延续平台识别，清楚的靛蓝行动色与淡紫选中底 |
| 晴空蓝 | 明亮清爽的蓝色行动色与浅蓝底 |
| 薄荷绿 | 清新的青绿色行动色与浅绿底 |
| 鸢尾紫 | 柔和紫色背景搭配清楚的深紫行动色 |
| 珊瑚粉 | 浅粉底搭配可读的深玫瑰色按钮与链接 |

**入口与操作：** 学生首页及课堂共享导航的个人区只提供一个下拉选择，收起时直接显示当前配色名，例如“经典靛蓝 ▾”。不再单列“配色”label、色点、打开面板的第二个按钮或保存按钮；有名称的预设即下拉选项，“经典靛蓝（默认）”同时承担恢复默认。控件以不可见的可访问名称说明“界面配色”，支持键盘、鼠标和触屏。个人中心外观设置若提供同一能力，也复用这一个下拉控件，不另造色板操作。选择立即预览并自动保存，不刷新页面，不改变课次、任务筛选、讨论草稿或课表周次；关闭选项后焦点留在下拉触发器。

**生效范围：** 第一阶段覆盖学生首页、课堂页、对应共享顶栏、课表外壳、任务/材料/课次弹层及外观设置中的同一下拉控件；页面跳转后保持一致。3D课表内部区分不同课程的颜色、博客栏目颜色、修为等级颜色和警告/错误/成功语义不随个人主色重新映射。教师与管理页面继续保留角色设计；不通过全局属性无意给未适配的业务页改色。控件的帮助说明注明当前覆盖“学习首页与课堂”，不在顶栏额外占一段固定文字；其他页面后续按同一语义令牌逐页验证。

**状态与过渡：** 主色、浅底与边框在约180–240ms内协调过渡，布局位置保持不变；已有颜色过渡统一到有限的明确属性，不使用`transition:all`。减少动态时直接换色并保留选中反馈。每套预设检查正文、弱文字、按钮前景、hover、focus、disabled和错误提示对比；首期不开放任意HEX输入，以免学生把按钮或边界调到不可读。颜色主题不等于深色模式，本期不因个性配色扩成全站深色重构。

**账号保存与失败处理：** 正式产品按登录学生账号保存，刷新和换设备后恢复。同浏览器切换账号不能继承上一人的配色。选择后即时预览，以短暂状态或aria-live报告“已保存”，不在顶栏永久再放状态文字。失败保留当前临时预览并说明“未同步，下次登录可能恢复原配色”；在同一下拉内重新选择可重试，不新增第二按钮。选回默认预设走同一保存链。连续切换只提交稳定后的最后选择，不能每次颜色动画都请求服务器；写入串行合并最终意图，旧响应不能覆盖最新预览。浏览器缓存不可用时仍可换色与使用服务端保存。

**现有架构核查与实施决定：** 当前`profile_service.py:18-28,254-269`未提供账号级外观偏好；`/api/profile/basic`是完整资料更新，不能仅传一个palette字段，否则可能连带覆盖个人资料（`profile_service.py:707-751`）。首期新增独立、字段级的UI偏好服务及最小`user_ui_preferences`表，主键为认证身份`(user_role, user_pk)`，字段为`palette_key`、`version`、`updated_at`；初期仅开放学生本人写入。客户端只提交允许的预设键与版本，不提交目标账号ID；未知预设回退默认。提供独立读/更新合同（拟`GET/PATCH /api/profile/ui-preferences`），不复用职业偏好或课堂settings字段。SQLite/PostgreSQL同步迁移，教师/学生相同数字ID不能串号。

首屏通过既有身份加载链取得这一条偏好，在SSR输出前应用，避免默认色先闪现；无记录直接采用默认，不为每个新登录自动写入一行。localStorage仅作按身份隔离、可失效的缓存，服务端为账号偏好真源。更新使用版本检查，冲突时读取最新版本并提示重新选择，不靠取消HTTP请求假设服务器旧写入也被撤销。该操作不触发课表取数、AI、业务列表重建或整页刷新。

保留`templates/base.html:2`的`data-theme="lanshare"`，在适配的学习工作区及弹层宿主使用专用`data-ui-palette`和共享语义令牌。不得覆盖修为卡的`data-theme`；Portal挂在body时显式继承相同配色上下文。梳理`ui-system.src.css:323-380`的角色/导航tone覆盖、`classroom_workspace.css:3-8`的固定`--cw-accent`及`course_schedule_deck.js:59-77,309`的紫蓝硬编码，确保按钮底色、文字、阴影和课表外壳一致。预设CSS集中定义，页面消费别名，不能为每组配色复制整页样式。

这是用户追加个性化后引入的**唯一必要数据库范围扩展：个人UI偏好**。教学业务表、作业归属、计分与教务数据结构仍保持原范围。实现时单行主键读取与版本更新有明确预算；只在页面启动及用户改色时使用，不轮询。

### 5.2 3D课表作为日常入口

- 课程日程首次默认3D，按用户身份保存明确的“3D/日程列表”偏好。旧`flat`仅是已取消的独立课堂列表偏好，不迁成隐藏日程或恢复独立课堂区的指令；新版日程偏好单独版本化。已有本人新版明确选择继续保留，旧角色级存储不能造成同浏览器不同学生互相继承。
- 小屏保留浅层堆叠3D预览、明显的模式选择与放大按钮；周日程由同一overview的weeks/lessons派生，保持相同周、学期、选中课程与缺排课说明。完整授权课程集合另由既有授权offerings投影补齐，不能仅从有排课的lessons反推。减少动态时保留静态分层和平面信息，不减少入口。
- 常显学期、周次、日期范围、上一周、下一周、回到本周、放大。完整课程名、节次、地点在放大/详情里可读；课程单元有可感知的点击边界。
- 保留现有触屏首点预览、再次进入的能力，同时在详情提供明确“进入课堂”按钮，用户无需猜第二次点击。普通链接支持Enter、组合键与新标签。
- 学生明确显示“仅显示本平台课程，所有课程请查看教务系统”。调课按实际日期，取消课次不伪装正常；缺日期或节次显示待完善说明与课堂入口。
- 日程内“全部课程”可查全部授权学期及仍可访问的往期/归档课堂；未排课、本周无课与节次不完整的课堂都保留课程名、班级/教师、学期与“进入课堂 / 作业与考试”。完整集合按授权offerings构建，默认可查看全部学期；回到周视图恢复原周次。集合搜索只过滤集合，不能暗中改变周课表或待办范围，显式课程筛选有范围提示和清除动作。
- 鼠标位于普通3D课表画布时，滚轮直接切换周次，不要求额外点击激活；成功切周保留前后卡片的3D层叠位移、透明度和深度变化。统一delta阈值、方向与节流，快速滚动合并意图而不重建deck。到第一/最后周且不能再切时放行页面滚动；课表外部、弹层详情内部滚动、控件操作以及Ctrl/Meta缩放不被切周逻辑拦截。方向键、可点前后周按钮与触屏横滑保留等价入口。

当前共享deck的stage约460px高、卡片约380px高且主要按viewport断点适配，不能直接塞入7/12窄列。先将标题工具条和堆叠画布改为容器适配；课表列低于约680–720px时主区转单列，或经真实渲染证明紧凑模式可读后再双列。7:5是起始比例，清晰度优先。待办不跟随课表强制等高；无课周缩短空态，但保留周次控制和未排定课次入口。

**完整集合来源不能推测：** `student_course_schedule_service.py:115-126`会跳过缺日期/节次的课次，`:163`的`courses=_build_course_stats(items)`也仅含已排定项目。因此全部课程优先复用dashboard既有SSR完整授权`class_offerings`，或从服务开头`_load_student_offerings`所得完整集合补一个轻量只读投影；不从weeks、lessons或overview.courses去重拼全集，不追加逐课查询。未设置学期、无排课、所选学期无数据等早return也要保留这个课程入口投影。往期/归档只列当前仍授权可访问的记录，撤销关系不得留在缓存中；“本周无课”和“没有授权课堂”使用不同空态。

### 5.3 待处理区与自定义待办

“需要处理”优先显示确有下一步动作的作业、考试、个人待办；课程安排在课表与下一次课摘要中表达。完整“日程与事项”继续包含两种内容。**时间位置、业务完成和可执行性三个维度分开**：过去日期不等于完成，未来课程不等于紧急待办。

摘要计数沿用完整事实集合，在服务投影中一次算出各类数量，分页后不重新数DOM。当前SSR的`all_items`仅20条、`focus_items`最多3条，不能前端过滤它们后声称得到完整待办。应在`dashboard_workspace_service`现有完整事实遍历内生成明确的`action_summary/attention_items`展示字段，不额外查库，不改变其他消费者使用的`is_actionable/pending_total`含义。仍可补交/重交、退回需处理以及实际进行中的投票等行动应持续可达；未来未开放任务不能冒充当前紧急项。

当前`lanshare:dashboard-scope`会联动课堂、课表和事项，重组课程日程时必须拆清作用域。周视图学期不限定首页全部待办，完整课程集合搜索也不改变待办；学生自定义待办不得随课程零匹配消失。确需“仅看该课堂”时，在事项自身显示显式范围和清除按钮。验收覆盖“前20条都是课次，第21条才有待交作业”和同浏览器换学生账号。

“需要处理”标题右侧常显“＋自定义待办”，不再在问候区复制新增入口。复用`data-agenda-add-todo`、`data-agenda-todo-options`及`dashboard_agenda_widget.js:557-568,589-601,957-1043`的唯一新增/编辑弹窗与完成链；自定义项有编辑、完成/恢复未完成操作，创建后进入同一首页事项和日历，不造第二套待办模型。无截止日期允许，仍可保留在待办；标题、归属、截止、优先级、提醒能力及校验沿用原合同。

学生使用`learning.py:474-545`的`/api/classrooms/{id}/todos`，须选本人可访问课堂；仅一门授权课时可预选，已有内容不重填。教师账户级`/api/todos`仍为教师专属（`:115-117`），不能因新增按钮让学生越权。无可选课堂时保留入口但明确说明当前缺少可关联课堂，不假装创建成功；不把本次布局需求扩大成无课堂归属学生待办。

现有成功处理会`reloadSoon(650)`刷新整页（`dashboard_agenda_widget.js:979-983`）。实施复用现有CRUD和弹窗，成功后统一触发workspace/calendar局部刷新，保留课程日程的学期/周次、模式及焦点；请求失败保留表单和已输入内容供重试。新增、编辑、完成均防重复提交，计数只从服务返回的同一事实状态更新。新增成功可维持原优先级排序，但反馈必须提供“查看此待办”，打开/定位同一完整集合中的真实记录，不能因为首页仅展示3项而创建后找不到；无授权课堂的说明在表单内可读，入口不被隐藏。

成长工具用紧凑图标工具砖呈现，六个入口保留；帮助解释沿用共享说明组件。安全异常仍应在适当位置显式呈现，不能藏进工具说明。

### 6.3 作业、考试与历史入口

模块标题采用“作业与考试”，下方常显“整个课堂 · 共N项”。切换课次时该模块范围保持不变，避免标题带“第3课”的页面让学生误以为历史被过滤。

默认预览待处理4项；常显“待处理 / 已提交与结果 / 全部”分段筛选，并有独立描边按钮“历史作业与考试”。历史入口直接打开同一完整集合，默认显示全部记录、按任务创建时间倒序，可查标题与状态。“历史”是查找入口，**不等于closed过滤**。

历史排序沿用课堂查询已取得的`assignments.created_at`（`ui_parts/classroom.py:149-157`），同一时间按id倒序；无有效时间稳定排后。将该字段明确投影给任务集合排序，显示口径标为“创建时间”，不假称发布时间或提交时间。现有前端ClassroomTask尚未包含该日期，实施需补类型/服务投影；不能拿会随补交变化的`countdownAt`当历史顺序，也不需要新增数据库字段。

已提交、已批改、已关闭可能重叠，筛选数量不应相加作为总数。重交/补交中的已提交任务可能同时属于待处理，须保留服务状态与截止约束。成绩隐藏、考试未开放、小组结果未公布等依照原权限与呈现判断，不为统一卡片而强行补空值。

一条任务的稳定结构为：类型与状态 → 可点击标题 → 截止/提交时间与硬约束 → 明确动作。标题和“查看详情”进入同一合法详情；“开始作业 / 继续作业 / 进入考试 / 查看结果”根据真实可用操作显示。标题区可扩展命中面，但有批改、下载等子操作时不得嵌套链接或用全卡click抢走子操作。

完整集合继续复用单一任务DOM、现有普通/小组与角色分支。保存筛选、搜索、分页或滚动位置、打开入口和焦点；作业详情返回后恢复原集合。顶栏、首页课程日程中的课程入口、历史按钮、预览分段共享一套状态路由，不各建一份弹窗或列表。

零待处理也保留完整面板：“目前没有待处理任务”，旁边继续提供“已提交与结果”“历史作业与考试”。零历史与筛选无结果分别说明；不能显示“暂无作业”掩盖已经完成的任务。

### 6.4 材料、活动与教师端

- 删除主区所选课次材料面板，移除对`#cw-materials-preview`的portal与首层自动fetch；多份材料复用单一集合DOM/控制器。课次材料入口读取**当前用户在本课次完整可访问的材料集合**：0份在详情内显示准确空态并保留全部课堂材料入口；恰好1份直接进入其现有渲染阅读页，跳过列表和确认；多份才展示列表供选择。不能拿旧主材料ID、绑定总数或被截断的预览长度决定单份，也不能把读取失败当0份。顶栏“材料”仍明确进入全部课堂材料，教师管理/解绑链保留，学生不展示教师配置完成率。
- 导航复用已查证的学习材料链：`GET /api/classrooms/{id}/learning-materials?session_id=…&generate_blurbs=false` → `session_learning_materials_service.py:196-209`的`open_url` → `classroom_material_list.js:33-47`的`buildOpenUrl`归因规则。`materials_service.py:283-305`将HTML指向现有`/materials/render-view/{id}`渲染壳、Markdown指向`/materials/view/{id}`；保留服务解析的包路径和参数，不按后缀自行拼新URL，不调用文档导出/转换renderer冒充阅读入口。优先复用`classroom_material_list.js:152-159`现行阅读导航方式；沿用新标签时保留原详情/列表，回原标签即回实际来源。若采用同页导航则接已有返回上下文，不把单份直读扩大成全局阅读路由重构，组合键行为保留。
- 0/1/多份的计数来自同一鉴权投影，不新增逐项探测请求。现有清单路由先校验课堂访问（`materials_parts/learning.py:88-100`），实际Markdown/HTML阅读页继续用`ensure_user_material_access`复核，HTML入口文件亦校验（`materials_parts/exports.py:190-200,308-330`）；实施须保证集合排除不可访问项，不能把“有open_url”当成读权限证明。读取与跳转之间权限撤销时准确显示失败并允许返回，不绕过预览、下载或访问控制。阅读器继续接收`class_offering_id`和真实`session_id`，保留目录、README与原学习记录，不把绑定数当学习进度。
- 详情说明不能延续`classroom_page.js:1092-1094`只取前4行的截断；完整可滚动/展开。返回关系为单份“详情→阅读页→返回详情”，多份“详情→列表→阅读页→返回列表→详情”：新标签保留来源视图，同页方式恢复原上下文。单份不能返回未曾打开的列表或阅读确认层。保留所选课次、列表位置/查询及焦点，替换当前`:1927-1928`指向旧详情/预览节点的硬编码回焦，不指向已删除面板。
- 活动页签借鉴博客浅底轨道与实底选中态；未读、在线、断线重连与正在进行的互动持续可见。右栏需适配现有全宽CSS、五页签、nowrap工具条、私信联系人与附件；按容器宽度换行/紧凑排列，保留消息区`min-height:0`高度链和输入区。切换仅切已有内容容器，保持WebSocket、草稿、附件、引用、私信状态。
- 顶栏学生入口只显示“本课修为 2.9”这样的本课数值，可点击并有hover/focus反馈；不另显示“查看修为”、境界行或主区修为带。数据复用`classroom_page.learning_progress.score`（模板`:322,715-727,1616`），不是学生全局汇总。点击进入本课修为详情视图；现成承接是`#learning-progress-modal`详情弹层，可采用页式宽面板，**不是已经存在的独立修为HTML页面**，不虚构URL。沿用`data-learning-modal-open`与`learning_progress.js:6-8,60-94`的焦点/关闭链，完整境界、阶段、排名在详情保留；读取失败显式说明，不能用0冒充真实值。
- 教师共享表面、课次导航和动画规范，但主动作分别是发布任务、批改、备课材料与课堂管理。教师首页继续使用教师课表接口，不能切到学生只读接口；学生不得出现发布、同步、建课或其他教师权限入口。

## 7. 动效与状态规范

先让用户得到确定反馈，再完成内容更新。动画表达操作与结果的联系，不延迟按钮可用时间，不为每行列表逐个排队入场。

| 对象 | 起始预算 | 实施规则 |
|---|---|---|
| hover/focus/选中 | 180ms | 背景、边框、阴影平滑变化；可点击卡上浮最多1–2px；焦点轮廓立即可辨 |
| 按下 | 120ms | 位移/阴影收紧后恢复；链接导航不等动画结束 |
| 课次与筛选内容 | 180–240ms | 局部淡入/轻移最多4px；变化只作用相关区，焦点不被重建DOM吞掉 |
| 面板展开/收起 | 240–280ms | 同时设计进入、退出；隐藏须在退出结束后执行；连续操作取消前一动画 |
| 抽屉/Dialog | 约280ms开、180–240ms关 | 复用Radix状态生命周期，统一遮罩与层级；Escape、焦点约束及回到触发器完整 |
| 课表周次/放大 | 周卡约320–500ms，放大约280ms作为调校起点 | 普通画布滚轮直接切周并保留3D层叠位移、深度和透明度过渡；当前共享transform约500ms可按实测调校，不退化为仅换文字。保留锚点，快速切换合并意图 |
| 数据等待 | 立即显示busy状态 | 首次无数据才使用等尺寸骨架；后续请求保留范围清楚的旧内容，成功更新、失败就地重试 |

优先复用现有`--transition-fast/normal`与`--ux-motion-fast/base`，在相关基元中明确120/180/280ms映射；不用新的动画库，不增加整页第四套时长体系。`transition`显式列出属性，避免`transition: all`让尺寸和层级一起失控。大面积变换优先opacity/transform；高度动画仅作用小型折叠区，测量集中到一帧。

`prefers-reduced-motion`同时覆盖CSS与JS：关闭非必要位移、3D转动、惯性和平滑滚动；保留选中、loading、结果与全部操作。项目同时采用WCAG 2.3.3的减少交互动效能力作为增强目标，它是AAA项，不误写成AA统一要求。

博客本轮是设计参考。后续如要将共同动效规范同步回博客，应单独列出feed/detail、筛选加载、头部压缩和composer关闭的验收范围；本计划不把博客整页改造偷偷并入首页课堂施工。

## 8. 架构、数据与性能

### 8.1 复用链路

| 信息域 | 唯一来源/现有能力 | 第二版改动落点 |
|---|---|---|
| 首页事项 | dashboard路由 → `dashboard_service` / `dashboard_workspace_service` → dashboard-workspace island | 同一事实集合生成需行动分项与日程摘要，保留现有分页/过期游标处理 |
| 学生课表与课程全集 | `/api/dashboard/course-schedule/overview` → `student_course_schedule_service` → `course_schedule_deck.js`；全集复用SSR完整授权offerings或同一加载结果的轻量投影 | 单一课程日程、3D/日程切换、滚轮切周与完整集合；未排定和早return仍保留入口 |
| 教师课表 | 原教师overview与教务合同 → 同一deck | 保持角色数据源、未绑定课堂与建课能力 |
| 课次与材料 | teaching plan / `selectedOrder` → `classroom:session-selected` → session-detail → 可访问材料投影与既有open_url | 紧凑材料按钮按0/1/多份分流：空态/直读/列表；保留真实阅读来源和归因，删除首层材料预览 |
| 自定义待办 | 既有agenda新增/编辑/完成控制器 → `/api/classrooms/{id}/todos` → 同一事项/日历事实 | 标题右侧新增入口，复用归属与权限，成功局部刷新并可定位新记录 |
| 本课修为 | `classroom_page.learning_progress.score` → `data-learning-modal-open` → `#learning-progress-modal` | 数值移到顶栏，只读本课；进入既有全量详情视图，不新增虚构页面或计分规则 |
| 作业/考试 | 课堂路由授权投影 + assignmentWorkspaceItems + 原任务DOM/任务路由 | 卡片预览、显式筛选与历史直达；状态只归一化一次 |
| 活动与私信 | `chat.js`、classroom interactions、private messages等 | 表面与切换反馈；保持控制器、连接与草稿生命周期 |
| 通用控件与解释 | `frontend/src/components/ui`、`--ls-*`、LanShareExplanation | 统一按钮/面板/筛选语言，保留说明卡唯一实现 |
| 学生配色偏好 | 新增独立本人UI偏好合同及最小偏好表 → SSR配色上下文 → 共享语义令牌 | 一个显示当前名称的下拉选择，五组预设自动保存，选默认项恢复；不走完整资料覆盖API |

学生课表授权使用有效学生、主班与合班关系，只显示平台课程。不得把教师完整教务排课暴露给学生。复用现有实际日期、取消课次、学期归一化、缺时间说明与404/空态处理。

目前无作业到课次的可靠业务关系，教学布局调整无需新增业务表/列，不推断课次归属，不重构提交、评分、考试计时或修为算法。用户补充的跨设备配色仅增加4.3节个人UI偏好存储；本轮仍只规划、未运行迁移。未来确需课次作业，必须另做显式关联、历史迁移与教师配置需求。

### 8.2 状态与生命周期约束

- 课程日程统一宿主，3D与日程模式共用周/学期上下文和单个deck；完整授权课程集合常显可达，独立于有排课的周数据。切模式不销毁重建控制器，删除旧独立课堂容器的渲染入口和隐式范围广播。
- 课次浏览、选中、详情打开分状态；显式激活串联选中与开详情，自动定位不开窗。材料入口先解析完整可访问集合，再分0/1/多份；单份不挂载列表或插入列表历史，多份列表与详情受控交接。阅读返回按真实来源恢复详情或列表，保留同一课次；完整课次集合复用数据，不复制DOM ID、焦点锁或独立选中状态。
- 所有打开任务集合的入口共用一种可恢复的状态表示；扩展现有URL/历史状态解析，不建立并行路由系统。
- 保留AbortController、请求序列或等价迟到响应保护；课次、学期快速切换时仅最后一次结果可提交界面。
- SSR/静态资源延迟时不露出一堆已退役内容；课程链接仍可用，动态控件有明确就绪/失败状态，课表失败可切同范围列表重试。
- 不为动画重挂载讨论、私信、AI工具和完整任务DOM。广播与私信分别检查flex高度链、`min-height:0`与内部滚动，不能只看外层overflow。
- CSS在现有dashboard/classroom工作区文件内整理被替代规则，公共色彩和必要基元归共享系统；不把样式迁移变成全站重构，不在ui-system文件末尾无限堆覆盖。

### 8.3 并发与性能预算

- 常显课表会增加初访课表请求：每个有效学期一次，复用缓存/已有响应，切视图不重复取数；缓存按角色、用户、学期隔离，权限变化及时失效。
- 多模块读取同一workspace payload；不按每张课程卡重新聚合、不增加每卡轮询、不触发AI生成、教务同步或修为重算。
- 保留已存在的学生课表测试底线：21个授权课堂仍为4次批量SELECT、query_only可执行。该数字是既有测试合同，本轮尚未重跑。
- 快速拖动课次只改变浏览位置，网络请求数为0；激活先开现有详情，点击材料入口才按需读取可访问集合。一次响应完成数量分流，多份直接把同批数据交给列表，避免判完数量再重复取列表；重复进入只复用仍有效且按身份/课堂/课次隔离的结果。20次打开/关闭课次、材料和任务面板后DOM实例、document监听器和WebSocket不增长。滚轮切周只变已有overview的展示，不新增网络请求。
- 不对一整个学期逐课次预加载材料，不新加轮询。课表全学期DOM当前规模先测量，超大规模再局部窗口化，避免为动画一次渲染无限隐藏节点。
- 检查dashboard_service仍生成的旧cockpit/旧统计是否还有消费者，再决定是否按需跳过。不能在新布局上再加一套旧统计计算，也不能仅凭新模板未用就直接删除服务字段。
- 后续以同一fixture、同一网络/CPU配置对照当前版：LCP目标≤2.5s、CLS≤0.1，普通局部操作目标≤200ms；分别记录首次加载与缓存操作。既有报告已有慢设备交互超过200ms的偏差，不能把它写成当前已达标或本轮必然改善。
- 实验室EventTiming不冒充线上INP p75；生产并发容量不以单浏览器截图判定。新增请求的SQL数、p95和错误率需独立测量。

## 10. 验收：从发现入口到完成任务

### 10.2 布局、输入与业务矩阵

- 视口：2560×1187（对照用户截图）、1440×900、1366×768、1024宽、390宽、320宽；200%缩放；长课程名、8个合班名、1/多/零课堂、单/多/零任务。

- 任务：普通/考试/小组、未开放、可做、逾期可补交、已提交可重交、已截止未交、已批改、成绩隐藏、小组待公布；筛选重叠与总数一致。

## 12. 设计依据与适用方式

| 一手来源 | 本方案采用的原则 |
|---|---|
| [NN/g：共同区域](https://www.nngroup.com/articles/common-region/) | 用边界和共同背景表达功能归属，同时避免过量套框；对应模块与工具条 |
| [NN/g：可点击元素识别](https://www.nngroup.com/articles/clickable-elements/) | 静止状态给出可操作线索；对应标题链接、按钮、整卡命中一致性 |
| [Carbon：Motion](https://carbondesignsystem.com/elements/motion/overview/) | 日常任务采用轻、快、有意义的过渡；对应进入退出与局部状态变化；具体时长是项目预算 |
| [W3C APG：Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) | 真正内容页签需正确关联、键盘与选中语义；有加载延迟不应仅焦点移动就触发远程切换 |
| [W3C：拖动动作2.5.7](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html) | 自定义拖动必须提供点击替代；键盘等价不能单独替代触屏可点按钮 |
| [W3C：交互动效2.3.3](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html) | 支持关闭非必要交互动效；作为项目增强目标保留全部功能 |

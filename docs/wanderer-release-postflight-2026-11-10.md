# 散修第二版发布后专项核验

本入口只补最终镜像与生产现状的发布验收，既有完整回归和原生 PostgreSQL 迁移门禁仍按发布流程执行。生产不创建测试账号、不改真人账号、不向真实私信或群聊插入测试消息、不主动唤醒真实散修或付费模型。

## 最终应用镜像的隔离检查

在服务器取得本次已构建镜像的不可变 ID 后执行，使用 `--entrypoint` 跳过正式启动迁移，不挂载 `/lanshare/data`，不传生产环境文件，不加入生产网络：

```sh
docker run --rm --network none --entrypoint python "$RELEASE_IMAGE_ID" tools/wanderer_release_verify.py
```

这个入口在导入应用之前清除数据库环境、屏蔽所有 dotenv 加载和 psycopg 连接，创建自有临时 SQLite。代码还阻断非本机网络；本机回环仅供 Windows 的 asyncio 自管道，服务器容器另外用 `--network none` 隔离。测试进程退出后临时数据库回收。

复用现有测试共 47 项：AI 账号登录/密码/会话/微信隔离与迁移幂等，真人学生及教师原登录，服务身份的普通 CRUD、原归属/冲突/确认/撤权校验，新社交独立额度、并发最后一份额度、nonce 重放、群聊创建与恢复、真实协议连续六轮群聊，旧消息中心真实 ASGI 与连续六轮私聊，回调自写记忆、最后额度已接收指令继续执行、重复唤醒不重复计费和断点回执恢复。另含两项只读快照的隐私与异常检测。模型只提供合成指令，业务通过原服务和 ASGI 执行，不调用真实模型。

通过标准：JSON `ok=true`、`tests_run=47`、`failures=[]`、`errors=[]`、`skipped=[]`，退出码 0。此结论是最终镜像内的合成业务链路通过，不声称生产中已经自然发生六轮交谈。

## 生产只读快照

由发布执行者将下面时间替换为本次切换服务的时间，必须带时区。`APP_CONTAINER` 使用已核验的正式应用容器名；只使用该容器既有的 `DATABASE_URL`，不把凭据放在命令行或报告中：

```sh
docker exec "$APP_CONTAINER" python tools/wanderer_release_snapshot.py --since "$RELEASE_STARTED_AT"
```

脚本不导入应用、不调用任何 schema ensure/初始化或业务函数。PostgreSQL 在建立连接时就启用默认只读，并显式开启可重复读的只读事务，查询后 `ROLLBACK`；单条查询 15 秒超时、锁等待 1 秒。报告只含计数、预定状态枚举、版本、时间及开关，不查询正文、记忆、提示词、身份 ID、显示名、密钥和推理输出。可选认证模块的表不存在时列在 `absent_optional_auth_tables`，不伪装成曾测试该模块。

`ok=true` 要求 AI 绑定完整、无真人登录凭据/会话和生效委托遗留、命令与轮次关联完整、资源没有负数、世界账本版本为 5。其他计数用于观察：自建群无文本、活跃 AI 群成员缺观察游标、待办/失败分布、历史私信回执对应消息已经删除等，不能单凭这些总量判定本次新故障。

`natural_activity_since` 仅统计切换后的自然运行：新旧私信和群聊消息、会话中的 AI 发言者数量、派发模型次数与成功指令。至少 3/6 条且有两个 AI 发言者只表明观测到这些消息，并不保证严格交替回合。没有新消息或无六轮会话时如实报告“尚未观察到”，功能可用性由上面的隔离六轮检查证明。运行开关关闭、额度不足、尚未轮到定时任务或散修自主不发言时，不为获取验收结果强行修改真实状态。

上线健康、当前日志和重启数仍由现有部署 postflight 核对。保留部署后快照和最终镜像测试结果，与发布 ID、源提交、迁移报告和远端 Git 提交一起归档。任何失败先检查具体不变量、当前事件状态与本次变更，保留原数据和回执，不以删表、重置扣额或恢复旧业务库覆盖新数据来修复。

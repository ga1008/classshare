# 通知邮件降噪

邮件由具体业务事件决定，不再仅凭“重要通知 / 系统通知”标签发送。所有原有站内通知、消息权限、去重与跳转保持有效。

| 事件 | 邮件 |
| --- | --- |
| 学生提交作业、学习进度、课堂 @、日常协作 | 不发送 |
| AI 已完成但低置信度、证据不确定、需要教师复核 | 不发送 |
| AI / 系统批改失败、排队失败、批改超时、重批失败且保留原成绩 | 通知教师 |
| 学生成绩实际可见，包括零分和小组成绩揭晓 | 通知学生 |
| 成绩待公布、隐藏或已退回 | 不发送 |
| 教师发给学生的私信、教师在问题反馈中的回复 | 发送 |
| 学生 / AI 私信、普通反馈提交、关闭 / 重开反馈 | 不发送 |
| 普通作业发布、临期提醒 | 不发送 |
| 教师发布作业时主动勾选邮件通知 | 保留主动发送 |
| Agent 任务完成 | 不发送 |
| Agent 任务失败、账户找回、签名与申请审批、教务考试、公文关注 | 保留重要邮件 |

教师明确配置的独立定时邮件和待办邮件继续遵循其主动设置。

## 实现与兼容

- `email_notification_service.notification_email_required` 是入队和发信前共用的事件策略；畸形元数据按不发送处理，不中断邮件批次。
- 教师批改问题持久化 `grading_issue_type`；历史排队通知通过原有结构化 `ref_id` 区分复核与失败，不依赖标题或文案猜测。
- 学生成绩沿用统一成绩投影的可见分数与发布状态。小组最终成绩沿用原有揭晓通知和去重键，避免新增重复站内通知。
- 发信前重新检查历史排队通知；不再需要邮件的任务标为 `skipped`，站内通知的邮件状态设为 `not_required`，站内正文和已读状态保留。已发送邮件不改写，独立主动邮件不受此检查影响。
- 沿用 PostgreSQL `FOR UPDATE SKIP LOCKED` 领取和既有速率限制。新增检查按通知主键查询，不新增扫描、数据库结构或模型调用。
- 邮箱设置页面同步说明发送规则；提交动态和低置信度复核的新站内通知使用普通等级。

## 验证

本地 13 个测试模块共 164 项测试通过，其中新增通知策略专项 27 项。

覆盖策略矩阵、历史队列拦截、站内消息保留、孤立任务拦截、真实失败放行、独立主动邮件保留、隐藏小组成绩、可见零分、教师回复、作业主动邮件与既有任务终态通知。SMTP 和 AI 调用均隔离；测试不向用户发信。

另回归批改、成绩投影、小组结算、反馈会话、私信、签名审批、定时任务、SQL 方言与原生 PostgreSQL 发布门禁。上线结果单独记录在生产发布记录中。

# 全平台 UX 体检与「少即是多」改造计划（2026-08）

> 依据：2026-08-03 P03 收割机对教师端/学生端 24 个真实登录页面的全页截图审计
> （桌面 1440×980 + 移动 390×844）。本文承接并区别于
> `ui-copy-simplification-plan.md`（文案精简，已基本完成）：本轮针对的是
> **结构性重复、空态过重、装饰残留、交互生硬** 四类症结。

## 总诊断

平台不是「缺功能」，而是**每屏都想说完所有话**。同一个数字、同一个入口、
同一句解释在一屏内出现 2–4 次；零数据的统计卡、图表、图例长期占据首屏；
英文装饰眉题在上一轮清理后仍残留约 75 处；过渡动画缺失使状态变化「跳变」。

四条根因（按用户原话归类）：

1. **功能重复**——右栏快捷入口 ≈ 顶栏导航 ≈ 页内按钮；统计数字多处重复。
2. **交互生硬**——状态切换无过渡；hover/focus 反馈不统一；空态↔有数据切换突兀。
3. **说明啰嗦**——文案层面已治理，但「结构性说明」（图例、操作指引卡、
   零值统计）仍常驻。
4. **少即是多**——每屏一个焦点的原则未落实到组件级：零值就该隐身，
   重复就该合并。

## 症结清单（按证据）

### A. 结构性重复（最高优先级）

| # | 位置 | 证据 | 改法 |
|---|------|------|------|
| A1 | `profile.html` 通知中心分区 | 「总未读/当前分类/私信联系人」hero 统计 + 「通知工作台」卡再报一遍「当前列表/总未读/联系人/黑名单」+ 17 个分类 chip 各带 0 徽章 → 同屏 8 个「0」 | 三层头部合并为一行工具条；零值分类 chip 收进「更多分类」；徽章仅在 >0 时渲染 |
| A2 | `profile.html` 个人首页 | 待完成/已提交/平均分/修为 出现 3 次（hero chips、总览四卡、暗色修炼卡）；「各课堂修炼进度」再重复修为条 | 只保留总览四卡一处；暗色卡只留「修为段位 + 破境入口」这一独占信息 |
| A3 | `profile.html` 左栏 | SIGNAL 当前状态卡（今日心情/身份昵称/密码更新）与 QUICK 快捷入口卡（返回首页/编辑资料/账号安全）重复分区导航与顶栏 | 两卡整体删除；心情设置并入 hero chips |
| A4 | `dashboard.html` 右栏快捷入口 | 教师「开一间课堂/整理材料/看看题库/处理审核」≈ 顶栏「开设课堂/搜索/教学」；学生 9 张入口卡（直奔重点/错题本/成绩单/成就墙/商店/档案/消息/密码）≈ 顶栏「我的/消息」 | 每端保留 ≤4 个真正高频入口，其余合并进「我的」；「改个密码/去看消息」删除 |
| A5 | `manage/workflow.html` | 同屏三次「选择学期」：推荐处理卡、阶段卡、iframe 内完整学期管理页（自带 hero + 4 统计卡 + 列表 + 焦点卡 + 完整学期日历） | 向导态只保留阶段卡 + 精简 iframe（`embedded_mode` 再裁剪：隐藏 hero/统计/日历，只留列表与新建） |
| A6 | 学生课堂页任务区 | 「学习清单」迷你统计条 + 「任务列表/我的作业区域」双标题；卡片内「查看详情」链接与 chevron 重复 | 双标题合一；统计条并入分区头；卡片整卡可点击，去掉重复入口 |

### B. 空态过重（零数据不该占地）

| # | 位置 | 证据 | 改法 |
|---|------|------|------|
| B1 | 学期日历（`partials/semester_calendar_panel.html`，首页+管理端复用） | 无学期时仍渲染：4 个「--」统计格、5 个图例 chip、拖动操作说明段、「暂无学期」输入框、空态卡 | 无数据 → 整体降级为单行卡「暂无学期日历 + 创建学期」按钮；图例与拖动说明仅在有数据时出现，说明文字移入说明浮窗 |
| B2 | 教师首页 hero | 4 个统计卡全为 0（活跃课堂/覆盖学生/待批改/未读提醒）各带两行小字 | 全 0 时四卡折叠为一行摘要；单卡去掉解释小字（进浮窗） |
| B3 | `manage/materials.html` | 4 个图表统计卡全 0（含两个 0% 圆环）；8 个筛选 select 常驻展开；「材料库根目录/当前范围/0 项」三处重复 | 零数据隐藏图表板；筛选默认收纳为一行（搜索 + 「筛选」展开器）；范围信息只保留面包屑一处 |
| B4 | 学生课堂页课程材料 | 空态仍渲染 6 个零值统计格 + 3 个操作按钮 + 目录导航条 | 空态 → 单行「暂无课程材料」；统计与导航仅在有材料时渲染 |
| B5 | 优先处理/最近动态（两端首页右栏） | 空态各占一卡且带解释句（「可以趁现在补充材料或修订试卷」） | 空态单行；无内容时整卡淡化收窄 |

### C. 装饰性英文眉题残留（第二批清理）

上一轮只清了 manage 端 `academic-eyebrow`。本轮扫描仍有约 **75 处**：

- `profile.html` 29 处（Personal Hub / Overview / Cultivation / Signal / Quick /
  Distribution / Touchpoints / Snapshot / Security / Settings / Avatar / Mood /
  Identity / Contact / Password / Account / Email Delivery / Servers / Mailbox /
  SMTP / Rate Limit / Signatures / Recent Login / Notifications …）
- `dashboard.html` 6 处（DAILY COCKPIT / COURSE PULSE / CAREER GALAXY …）
- `classroom_main_v4.html` 4 处（LEARNING FLOW / COURSE LIBRARY …）
- `message_center.html`、`wrong_book.html`、`report_card.html`、
  `points_shop.html`、`achievements.html`、`learning_path.html`、
  `exam_take.html`、`resume/*` 等各 1–3 处
- JS/岛屿 15 个文件内的模板字符串同类眉题

规则：**纯装饰英文标签一律删除**；承载真实数据的动态眉题
（如 `course.sect_name`）保留但去掉英文回退词。CSS 类保留（避免布局抖动），
只删内容节点。

### D. 交互生硬（统一动效语言）

| # | 症结 | 改法 |
|---|------|------|
| D1 | 分区/卡片出现无过渡，筛选切换内容跳变 | 建立全局「微动效令牌」：进入 `opacity+4px 位移 180ms ease-out`；列表 stagger ≤60ms/项、总时长 ≤400ms；`prefers-reduced-motion` 全关 |
| D2 | hover/focus 反馈不一致（部分卡片无反馈，部分过度阴影） | 统一为 1px 位移 + 边框加深 + 轻阴影（沿用 premium 设计语言文档标准），落到 `.polish layer` 公共类 |
| D3 | 空态↔有数据、tab 切换直接替换 DOM | 内容区切换加 120ms 淡入；计数徽章变化加 scale 脉冲一次 |
| D4 | 学生课堂页讨论区右键菜单（引用/有用/复制）截图中默认可见 | 核查是否未收起的悬浮菜单缺省渲染，若是则修复初始 hidden |

### E. 移动端过长

学生首页移动端全页高 **5991px**：日历图例、9 张入口卡、登录安全等全部纵向堆叠。
改法：移动端把「学期日历、快捷入口、最近动态、登录安全」折叠为手风琴分区
（默认收起，记忆展开态）；B 类空态降级后长度自然减半。

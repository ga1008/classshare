# 材料库 Gitee 更新修复与线上验收

发布日期：2026-09-09。版本：`20260909-materials-refresh-dee5fe416009`。

## 现象与原因

Python 与计算机网络仓库的 Git 更新成功，但材料库缺少新文件或打开仍显示旧内容。

- 生产实际 Git 更新均返回成功、Already up to date。Python Gitee master 为 `a3dff8947c7b4caa5c244e1e3715e2eaf74affa9`，计算机网络为 `8480a2370953ba24fd633167b3add093634993ff`。服务器全部 28 + 18 个课程文件与本地版本匹配（文本比较统一 CRLF/LF）。
- Git 操作完成后仅刷新材料列表及部分详情，没有刷新已打开的目录树；即使服务端已有文件，浏览器仍保留旧节点。
- 课程、班级筛选仅使用节点直接分配，没有继承仓库根目录及祖先的分配。线上复现：进入仓库并保留课程或班级筛选时子列表为空。
- Git 导入子节点遗漏根目录的共享范围、所属组织及所有者字段，历史新文件因学院、系部筛选被隐藏。现有业务明确由最外层目录统一管理这些字段。
- 固定路径的课件 CSS/JS 缺少显式重新验证策略，可能继续使用缓存资源；HTML 已有 no-store 策略。

## 改动

1. `materials_manage.js`：更新后重新获取目录树和当前内容，恢复展开与选中状态，删除节点回退最近祖先；请求序号防止旧响应覆盖后续导航。
2. `materials_parts/common.py`：在原可见性检查之后，批量读取根组织信息和同仓库祖先分配，提供继承筛选标签。每批增加两次查询，不复制课堂分配。
3. `materials_git_service.py`：成功更新后，以根目录现有策略统一子节点元数据；单次条件 UPDATE，兼容 NULL；相同内容的元数据修复计入更新，不重复计算内容更新或 LessonDoc 保护路径。
4. `materials_parts/exports.py`：HTML 保留 no-store；资源使用内容哈希 ETag 与 private/no-cache/must-revalidate，匹配返回304，旧 ETag 返回最新200。始终先做材料访问检查。

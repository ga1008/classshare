# 本学期出勤日历与智慧课堂同步

教师进入课堂的「签到统计 → 学期出勤日历」，默认看到本课程全班的月历。「统计对象」可切换到某名学生。从「学生汇总 → 查看个人课次 → 个人出勤日历」也能进入同一份记录。从某一节课的学生名单进入个人课次时，会展开该生整个学期。

## 查出勤与改签

- 月历按实际日期、节次排列，保留周末、已有校历节假日和经过核对的调课信息。同一天上两次课时，打开日期后选择具体课次。
- 全班格中的到场人数包含正常出勤、迟到和早退，未到人数包含缺课、病假和事假。只有应考勤学生全部正常出勤才算满勤。待确认、免考勤和学校活动单列。研学、实践、志愿服务保留学校给出的具体状态。原课程出勤率继续使用「正常出勤人次 ÷ 已确认应考勤人次」。
- 点日期，勾选学生或选择全部应到学生，选状态，填理由。「保存到本地」记录本次决定。「保存并同步」先保存，再同步本课刚改动的学生。原点名面板可用「同步本课点名」处理整班。
- 已上课但没有本地点名时，可人工补记。系统建立课次名册、记录修改人和理由，其余学生保留待确认或免考勤。之前已收到的学校回读、已确认 PDF 和申诉更正仍有各自来源。一个人同一课次只计一次。
- 多人同时改动同一记录，或浮窗打开后该课改了日期、节次，保存时会提示冲突并保留草稿。刷新后可核对最新时间和名单，再决定是否保存。

## 选择同步范围

| 教师要处理的范围 | 操作 |
| --- | --- |
| 一人一课次 | 打开个人日历中的一个日期，在课次详情同步或保存并推送 |
| 一人多课次 | 从个人日历打开智慧课堂同步，选择课次 |
| 多人一课次 | 从全班日历进入课次详情，可选部分学生或全班 |
| 多人多课次 | 从全班日历打开智慧课堂同步，同时选定课次与学生，或选「每课全班名单」 |

每个课次使用自己的历史名册、学校课次和点名轮次。教师启动同步后，系统自动对齐可以确定的课次、登记学校结果、发送较新的本地结果并回读。课次或身份无法唯一对应、状态冲突且无法判定先后时，会在该课回执里列出需要教师核对的记录。

学校点名覆盖全班。全班同步遇到学校尚无点名时，会在学校允许创建且名单状态齐备的情况下自动申请浏览器定位、创建点名并逐人同步。学校会把新名单初始设成缺勤，若有应考勤学生待确认，面板会指出需要补齐的人数。单人和部分学生可直接同步已有的学校点名，需要新建时可选择「同步本课全班」。其他教师抢先开启学校点名时，系统停止本次创建，避免重复开轮。

## 两端怎样对齐

先确定学校学期、课程和授课班，再对齐日期、教学周与节次，最后按确切学号比对学生。审核过的调课关系会复用。候选有歧义或名单发生变化时，可打开「核对此课对齐」，比较候选并确认。班级人数相近、课程名称相似或同一天有课，均不足以证明属于同一次点名。

| 本地 | 智慧课堂 | 同步处理 |
| --- | --- | --- |
| 未点名 | 未点名 | 显示「未开始点名」，两端均不创建记录 |
| 未点名 | 已点名 | 自动建立可改签的本地点名轮次，把匹配到的学校状态写入本地。找不到对应学校记录的人保留待确认或免考勤 |
| 已点名 | 未点名 | 在全班范围使用本地已确认结果创建学校点名，逐人核对学校回执 |
| 已点名 | 已点名 | 对同一学生比较两端可核实的决定时间。学校较新就更新本地，本地较新就更新学校。同值保留，时间相同或缺失且无法判断时展示差异 |

优先采用学生这次改签的时间。学校只提供整轮更新时间时，系统会参照上次逐人核实的一致状态，避免别人的改签覆盖这名学生后来的本地更正。读取页面、重新同步的时间不参与新旧比较。学校点名进行中可导入已经明确的出勤，未签到暂不记缺勤。本地仍在记录或结算时等待发布。教师可在课次详情继续改签。推送中断时会按原回执回读，确认与学校一致后再显示成功。

## 双向同步核验

- 使用隔离的教师页面和正式构建复现了 42 人名册。同步后，学校已确认出勤的 41 人进入本地点名册，缺少学校记录的 1 人保留待确认。教师随后在同一页面将其中 1 人改为缺课，重新读取该生的本地记录后确认已保存。学校接口使用合成数据。
- 智慧课堂的 248 项后端用例通过，覆盖两端四种点名组合、同一课内不同学生分别以本地和学校为准、重复请求和中断回读。在隔离的 PostgreSQL 16 上重复升级旧库保留了原有 32 个课次，两次并发导入只生成一个本地点名轮次。
- 正式构建通过 129 项点名、统计和日历浏览器用例。另行核对了桌面与 390 像素手机布局。本次修订只推送 Git，下方发布号对应首版。

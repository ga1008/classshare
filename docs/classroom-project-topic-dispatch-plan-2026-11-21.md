# 课堂分组与项目题目派发设计

2026 年 11 月 21 日 · 设计与材料调查。已实现功能与实测结果见[使用及验收记录](classroom-project-topics-acceptance-2026-11-21.md)。

**建议在课堂「小组协作」增加「派发项目题目」。** 教师从本地导入已有题目，选定教学班的分组方案，再把题目派给组。学生沿「我的小组 → 本组题目」查看要求和附件。同一套题包可以在多个教学班使用，各班独立抽签；同一批学生也可以沿用一个分组方案，先后完成不同项目。

内容、名单和发布分别由三个对象负责。**题包版本**回答「这次可用哪些题和文件」，**分组方案**回答「这个学生属于哪组」，**派题活动**记录「这个班这次给每个组发了哪道题」。这三者分开后，换一门课程只需换文件和活动配置。授课周次、课题名称、组长职责、提交物和评分规则均由课程自己规定。

**题号存在真实冲突。** 三套材料的第 14 题对应三个项目；同为第 1 题，旧 HTML 是宿舍水电公摊，便携包是出游垫付与 AA 对账。即使两份 Word、PDF 和 HTML 的编号相同，也不能据此认定它们讲的是同一题。学生发布包与旧总则的评分细项也有差异。首次建包时应选定一套题目底稿；若要采用另一来源的某个文件，教师应预览内容后显式绑定。

**抽组和派题是两个决定。** 学生包原文规定组长报名，撞题时抽签。便携程序是开组时直接随机派题。本次平台设计支持「随机分组＋随机派题」和「随机分组＋教师按已有结果绑定」。若 Python 班正式改用前者，开课前需要让学生看到与实际操作一致的公共说明。志愿报名、冲突抽签、调剂属于另一种流程，可在确有课程使用时增加。

## 二、教师和学生怎样走完一次派发

| 环节 | 教师在课堂里的操作 | 学生能看到什么 |
| --- | --- | --- |
| 1. 准备题目 | 在「小组协作 → 派发项目题目」选本地 ZIP 或文件夹。导入成为教师草稿。逐题核对名称、编号、简介、入口、附件、备选标记和实际预览 | 草稿仅教师可见 |
| 2. 选择班级与分组 | 默认当前教学班，可选择已有方案或创建均衡随机分组。核对合班后的参与人数、豁免/单独加入、已有组、空组及尚未入组人数 | 若分组方案本身已开放，学生可照常查看小组；题目仍等待发布 |
| 3. 确定派题方式 | 选「随机派给各组」或「按已有结果绑定」。预检列出参与组数、可抽题数、备选数、失效资源及人数分布。人工绑定可当场发现漏组和撞题 | 可按教师设置提前阅读公共说明 |
| 4. 发布 | 确认后一次保存本次题包版本和全部组题对应。默认预览只显示规模与异常；若展示精确的抽签草案，必须保存该草案，并让发布按钮提交同一份结果 | 只有「活动已发布」和「本人已属于该方案中的组」两个条件都满足，才出现本组题名、要求、附件。未入组者获得入组或等待教师分配的指引 |
| 5. 执行与核对 | 教师总览显示每组人数、绑定题、资源状态、未分组学生。可补齐名单、纠错、导出，或关联已有的作业提交入口 | 组员共用同一题，刷新、重登及换设备结果一致。能从课堂分组卡或手机端同一活动重新打开；组长和普通成员都有阅读权 |
| 6. 收尾 | 按课程需要关闭学生抽组、继续教师补分，或归档活动保留名单与派题记录。导出包括班级、组号、题号、题名、学号、姓名及未分组状态，附活动与题包版本 | 正常归档后可回看本人已获配的资料。撤回发布则停止新的阅读和下载 |

本次 Python 班可一次随机分完全班。若课堂要保留便携程序的现场抽签体验，可先建好组和组题对应，再让学生逐个随机入席。学生点击时按各组剩余席位的数量抽取；抽中后写入同一套组员表，重复点击返回原组。迟到或后来纳入的学生进入已有小组即取得该组原题；教师补齐剩余学生不能改变已分名单或已派题目。关闭学生自行入组后如仍需教师补人，应使用独立的入组开关。现有分组「归档」会把方案转为只读，应保留其语义。

## 三、文件包怎样兼容其他课程

导入器提供两条路。有清单时按清单解析；已有教案只有文件夹、ZIP、HTML 总表或若干 PDF 时，向导列出候选文件，教师指定公共说明、各题入口和附件，也可选中总表里某段实际正文作为独立简介。支持中文路径、原文件顺序和教师填写的展示题号。确认后可导出规范清单供下学期复用。未识别的文件保持教师私有，教师可随时返回草稿继续整理。

建议清单只声明内容。例如以下是只有一道题的完整示例，文件路径均相对于包根。

```json
{
  "formatVersion": 1,
  "packageKey": "campus-projects",
  "version": "2026.1",
  "common": ["公共说明/项目要求.pdf"],
  "topics": [
    {
      "key": "dorm-ledger",
      "number": "01",
      "title": "宿舍账本",
      "brief": "为一个宿舍记录垫付、分摊和结算。",
      "entry": "宿舍账本/需求说明.html",
      "attachments": ["宿舍账本/示例数据.csv"],
      "pool": "regular"
    }
  ]
}
```

- **稳定标识与显示编号分开。** 组号来自分组方案，题号供人阅读，`packageKey + topic.key` 用于识别一套题中的同一题。重命名、调序可沿用稳定标识。旧包没有标识时由导入向导生成并保存；跨包合并及旧版映射需教师确认。
- **材料完备度与备选资格分开。** 每题区分「完整任务书」「仅简介」「待补材料」。有真实正文的简介，教师可明确选择「按简介派发」；只剩标题、零字节页或必需附件缺失的题不能作为完整题发布。备选另设开关，默认排除，仅教师显式启用后计入可抽题数。发现异常应定位到题和文件，允许先保存合格项及整个草稿。
- **共享资源与题内资源分开。** 图片、样式和必要脚本随使用它们的页面登记依赖。公共说明可供全班访问。含有所有题正文的首页或 JavaScript 数据文件不能直接设为公共资源，应拆成题内文件或保留教师预览。对于无法可靠拆分的单页，提示教师上传分题文件，支持预览后重新映射。
- **版本固定到文件内容。** 同一份内容重复导入可复用存储；版本应固定主文件、嵌入资源和附件的内容摘要。修改本地文件后再导入，生成可比较的新版本。已发布班级继续使用原版；教师可单独选择一个活动更新，预览变化并保留先前记录。删除或替换材料库里的普通文件不能让历史组题失效。

### 数据和事务

| 对象 | 必要字段与约束 |
| --- | --- |
| 题包、题包版本、题目、资源清单 | 所有者与复用权限、稳定标识、不可变版本、题名/编号/简介、材料状态、文件摘要、所属题或公共范围。同一版本内题目标识唯一 |
| 派题活动 | 教学班、分组方案、题包版本、参与组、勾选的题池、派发方式、状态、修订号、可选作业引用。同一方案可有多次活动；每次拥有独立的结果和查看入口 |
| 每组派题记录 | 活动 ID、分组 ID、该活动所用版本内的题目 ID。首版实行一组一题、同一题在同一活动最多派一次，分别约束「活动＋组」与「活动＋题」。写入时验证班、方案、组和题包版本一致 |
| 变更记录 | 操作者、时间、班级、活动版本、受影响组、动作和原因。覆盖发布、补人或换组、纠正绑定、修订资料、撤回和归档。复用既有成员变更记录，避免维护第二份实时名册 |

1. **预检。** 读取名册与方案版本，计算组数、容量、未分配人数和可派题数。复用已有方案时列出实际参与组；分批入席时可明确包含预留空组。默认要求每个参与组可以分得一道有效题。独占题不足时保留草稿、显示缺口，同时允许单独完成分组。
2. **发布。** 服务端对勾选且就绪的题均匀无放回抽取，再一一绑定参与组；教师指定模式校验同样的唯一性。先完成耗时的文件解析，发布时按现有课堂锁顺序复查方案、题包版本及预检条件。组题一次提交，失败整批回滚。若选择「新建组并发布」的一步操作，分组与派题同事务完成；已有方案保持原有名单。
3. **重试与并发。** 相同发布请求返回已保存的同一批结果。两位教师并发发布或预览后有人改了组名单，要求读回最新状态及差异。学生刷新、抢同一席位、教师补齐与学生入组同时发生，都应复用现有分组事务与容量约束。按班级和活动加锁，文件只存一份，学生读取按活动、组成员关系与资源索引查询。
4. **持续使用。** 组员变化后重新按当前成员关系计算读权。受已有提交、互评或成绩保护的组继续执行原有变更限制。发布后调换题目需显示受影响组、填写原因、原子交换并保留历史，可向受影响组显示变更提示。普通补人、改组名、推选组长、重新登录均不触发换题。已有学生成果时，默认禁止自动换题，需教师处理具体例外。
5. **状态与留档。** 活动从草稿进入已发布，可归档为只读或主动撤回。撤回保留教师审计并收回后续读权；更正后重新发布要生成明确修订。已归档的分组名单仍可用于读取既有活动，或由教师明确选作新活动的固定名单。归档保留活动内必要的最终组员记录，避免下学期复用、清理或重建课程后查错组。

### 可见性贯穿所有入口

后端对每次阅读同时检查活动状态、当前用户的课堂身份、活动对应方案的组员关系、该组绑定的题和所请求文件的范围。教师按教学班的管理权查看全组。学生响应只包含公共说明和本组题目的必要数据；活动列表、他组卡片、未入组状态、移动端通知及助手摘要均遵循同一条规则。

HTML 正文、相对路径图片、Word/PDF 预览、原文件下载和批量下载都走同一授权服务。题内跳转到总目录或下一题时，应在学生预览中发现并处理；教师确认的公共入口才可跨题使用。私有题目不能同时随普通课堂材料树、搜索、AI 检索或整包下载向全班公开。若选用的文件早已公开，导入预检应明确列出该份公开副本，由教师决定原发布如何处理。独立渲染授权要限定活动、题和资源范围，换组、撤回或改题后，旧链接和缓存不能继续发放内容。已经由学生下载的本地文件无法远程收回。

## 五、Python 班落地顺序

1. **选定本学期题库。** 在三套目录中选一套作为底稿，把题名、简介、HTML 和 Word/PDF 逐题对应，同版规则放入公共说明。教师机便携包可以作为候选；若只采用其中的分组办法，可继续使用教学班目录里的自编题。
2. **确定首日发到什么程度。** 如开题当天发完整任务书，先补足 13 道合格主选题；如果当天仅公布题目方向，允许明确以 13 份已核对的独立简介开题，界面标明「仅简介」，后续通过修订补任务书。第 14 题按本课程意图设为备选，启用前也需验收材料。
3. **设置这一次教学活动。** 在平台核对七班合班的当前有效参与者。若实到口径仍为 63 人，可设 13 组、每组 4～5 人，预计 11 组 5 人、2 组 4 人。实际人数变化时重新预检。若采用随机派题且有 13 道合格主选，13 组各获一题，备选题留存；若沿用教师线下确定的选题，可逐组绑定已有结果。
4. **学生和教师各核一次。** 教师查看 13 组和未分组数，用「以该组预览」逐题检查入口。学生端验证公共说明、本人组、任务材料、迟到补入和重新打开。导出留存人组题对照；组长登记、个人报告、组级文档、答辩和计分按该课程最终确认的规则处理。

## 六、实施分期与验收

| 阶段 | 交付 | 可判定的验收条件 |
| --- | --- | --- |

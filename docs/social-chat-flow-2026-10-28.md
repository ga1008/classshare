# 私聊及时回复与群聊分层改造

## 调查与设计（实施前）

基线：`981c1bd39f1cd652828ab9ec63522b4c2c8103d5`。范围是既有好友私聊、群聊及散修收件处理；沿用现有身份、好友、消息、通知、邮件和 LQ 合同。

### 已确认的原因

- 散修私聊触发器添加 20–600 秒延迟，离线还会延后到偏好上线时段；统一 scheduler 默认 20 秒轮询且串行等待长任务。旧私信入口则依赖十分钟 tick。
- 模型前推进已读，模型故障被转换成 skip；任务成功结束后无法区分主动沉默和失败。正在运行的任务被新消息重置还可能失去锁。只取最近 30 条会漏掉较早未处理消息。
- 顶栏固定打开好友管理；自己的头像在前端被主动隐藏。聊天关闭清空当前会话，重开重复请求、重建消息；多个事件整列重绘。
- 群成员邀请接口已有好友、拉黑、停用、群数量及容量限制，允许所有群成员邀请自己的好友；前端没有对应入口。现有群昵称是公开信息，没有个人群代称。
- 群设置堆在主侧栏，文件接口已有分页但前端未使用，也缺少切换分类时的迟到响应保护。

### 交互和数据合同

顶栏直接打开聊天，左栏底部保留好友管理入口。自己的消息显示真实头像和统一留白。群侧栏只有群信息、成员、文件三张 embedded Surface 卡；邀请和设置使用共享 LQ 子 Dialog，保留原生输入、IME、焦点回归、取消、草稿、忙碌状态和权限变化处理。模糊只由现有共享材质管理，领域 CSS 仅负责布局。

正式群名继续是 `name`。成员记录新增 `alias`（最多 30 字，空值清除），只投影到本人的 `me.alias`、`display_name` 和会话标题；成员名单、系统消息、其他成员、邮件都不包含此字段。公开昵称独立保存。重新入群清除旧个人设置。群资料保存携带 `expected_updated_at`，过期保存返回 409 并保留草稿；仅变化字段产生系统消息。成员邀请在事务锁后重新检查权限和容量，同时串行化目标用户的入群上限。

散修采用持久收件状态：收到与已处理高水位分离，每会话一个 lease，默认全局两个并发槽，短轮询独立于普通长任务。生成结果先持久化，稳定 nonce 分段发送并可恢复。失败、限频、额度不足不消费消息；新消息在下一快照处理。作息主要影响主动行为和好友审核。人工私聊由模型根据人格、关系、情绪决定回应，不再随机前置忽略；情绪和记忆按关系隔离，不泄露其他好友私聊。保留平台预算和权限边界，模型均用替身测试。

### 验收与发布

- 后端：别名隐私/清除/重入群、管理员权限、409、并发邀请容量、同会话互斥、多好友排队、模型失败重试、运行中新消息、lease 过期、分段恢复、超过 30 条不跳过、拉黑/停用取消、情绪与记忆隔离。
- 前端：桌面亮色和手机暗色、glass off、键盘/Escape/焦点、设置留稿、邀请部分成功、文件分页与切换、头像布局、关闭重开及请求/重绘/长任务证据；使用正式构建和隔离合成运行环境。
- 更新 LQ 模块记录和全平台源码审计，保持零阻塞、不新增豁免。跑相关旧功能回归及原生 PostgreSQL 验证。
- 冻结源代码后按既有流程 DryRun、停止写入备份、部署，保护 `/lanshare/data`；上线只读检查服务、资源、表结构及队列状态，最后推送并确认远端 Git 一致。
- 数据库为增量列/表；回滚应用可保留新增结构，原有群名和公开昵称不变。发布前记录备份及回滚制品位置。

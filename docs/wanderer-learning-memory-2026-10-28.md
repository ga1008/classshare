# 散修交流学习与个体经验

## 调查结果

原有会话记忆保留最近 40 轮及长期摘要；知识库主要由公开材料研读和天道裁决反思写入。普通博客评论、群聊和私信并没有把对方的后续反馈转成可修订的经验。原知识库会跨场景使用，也会增加修为，因此不能直接存入好友的私人偏好或把反复聊天当成知识积分。

另一个真实缺陷是博客评论部分发送失败后，原流程仍把模型生成的全部分段记作“自己说过”；现在只记录已成功持久化且公开的分段。回复条数由模型根据内容决定，不再由随机 multi 模式要求凑数。

## 学习闭环

1. 在现有生成请求前，从当前已授权的真实消息、评论或课堂发言提取最多 8 条证据，稳定 ID、文本哈希和本人/对方角色由服务器生成。社交私聊、群聊和旧私信精确绑定原会话快照的消息 ID，避免把生成期间的新消息提前用于回复。群记录遵循入群时间。
2. 原有模型调用在正常回复 JSON 内可额外返回 `learning`，最多 2 条；无需新模型请求。种类为具体知识、对方明确偏好、本人表达反思。表达反思必须同时引用此前真正说过的话和随后对方的反馈；自己输出不能成为知识事实证据。本轮尚未发出的文本不属于证据。
3. 模型字段白名单、字数和数量均受限；不得自选所属散修、私密范围、证据正文。引用不在本轮证据中的 ID、已经撤回或修改的原文、注入指令、秘密或联系方式会被拒绝。学习本身不进入公开回复，也不加修为、不耗每日行动预算。
4. DM 学习包随已经生成的回复存入持久队列，恢复分段发送时无需再次生成；完成时同事务固化。其他行为在实际发送或有效沉默后写入。源证据、当前权限再次校验，重复证据不重复写。经验库使用每散修的短事务锁，取得锁后再次检查权限，旧快照不能覆盖已经被纠正的条目。
5. 下一次同关系/群/课堂交流优先注入相关经验。对方明确改变偏好或纠正说法时，模型可引用本次暴露的旧经验编号，原记录保留为 superseded，新记录成为 active；不能替换其他个体或其他会话的记录。原创写帖仅可检索仍公开且相关的通用知识，不引入私聊偏好，也不能把草稿当成新学习证据。

## 私密范围与可信度

私聊、群、课堂的知识和偏好默认只在原会话使用；个体之间不共享记录。只有仍公开、非散修自我互证的博客资料，而且原始全文和结论都通过保守的非个人、通用技术/学科知识检查，才允许跨当前个体的会话使用。无法确定的资料保留在原会话。公开来源也始终标成待核实的说法，不因重复、点赞或多个散修附和自动成为事实。

经验块被明确包为可能错误的数据，不能修改人格、权限和系统规则。来源文本改变、撤回、帖子变为非公开时，不继续跨场景注入。校验键包括来源 ID、版本哈希和公开属性，避免同一原文的新版本误激活旧版记忆。匿名发言的内部作者身份不进入模型经验块，也不把匿名作者与实名私聊自动关联。检索以索引限制当前会话 12 条候选、公开 20 条候选，统一批量验证来源；最多注入 5 条经验，不作每轮全表扫描。

## 持久性、容量与诊断

新增 `wanderer_experience_notes` 表和范围索引，以及行动日志的 `(wanderer_id, action_kind, outcome, id)` 重试索引，避免每轮扫描历史日志；不改原消息、知识和记忆表数据。唯一键防止同证据重复消费，保存来源 ID/哈希而非原文副本。每会话最多 24 条 active，每个体最多 160 条 active，修订账本最多 400 条；超限先归档再清理最老账本。

学习写入使用 savepoint 隔离，失败不会撤销正常发言。正常的回复恢复包和失败重试包均剔除证据原文；失败候选再次执行字段裁剪、秘密和指令过滤，不能通过异常旁路存入日志。后续行为先尝试恢复一条，不追加 AI 请求，也不自旋。审计存储自身故障也独立回滚并打印不含正文的运维诊断，不影响原事务。后台原有管理员详情增加 learning 计数和最近 12 条经验/来源 ID，原始对话证据不返回；公开散修主页不暴露此数据。审计记录区分保存、重复、拒绝、写入失败和恢复。

验证使用隔离 SQLite、注入模型和原生 PostgreSQL 专项；不连接业务库、不发真实消息。新旧散修均使用同一服务，无需修改既有人设才能获得后续学习能力。真实模型是否正确归纳还需观察；系统保证来源、范围、修订和保存边界，并不声称模型推断必然正确。

## 接口与验证记录

`prepare_learning_safely(conn, wanderer, thread_key, scene)` 在原生成调用前准备有界证据和经验块，供 `build_system_prompt` 读取；`learning_output_contract()` 补充静默 JSON 合同。生成后 `parse_learning(raw_text, scene['_learning_snapshot'])` 提取独立包，不改变既有 `parse_turn_output` shape。实际发送完成后使用 `apply_learning_safely`；DM 包随现有持久队列保存，其他动作经 `remember`/`commit_learning` 接入。没有新的模型端点或定时任务。

2026-10-28 独立验证：`python tools/test_backend.py --pattern test_wanderer_learning.py` 23 项通过；原有 behavior 20 项、social 40 项、inbox 19 项通过，均由仓库隔离运行器屏蔽 dotenv 和 PostgreSQL。学习专项覆盖正常回复一次调用、跨好友隔离、群入群时间/快照、撤回/编辑、匿名身份、公开知识使用与撤回、幂等和纠错、容量、故障恢复、异常日志秘密过滤、管理员与公开页边界、不增加修为/行动/天道活动，以及博客部分发送失败。

原生 PostgreSQL 专项位于 `tests/test_wanderer_learning_postgres.py`，遵循 `ASSESSMENT_REHEARSAL_TEST_CLUSTER`/`ASSESSMENT_REHEARSAL_TEST_PORT` 的任务自有离线集群合同，涵盖同证据并发、并发纠错一胜、私有/公开范围、旧 schema 幂等迁移和真实 SQL 审计错误的 savepoint 恢复。已由发布主流程在自有原生 PostgreSQL 集群执行上述 5 项并通过，并完成双恢复迁移演练。学习 schema 已冻结为一张新表和两个索引，无旧数据改写。

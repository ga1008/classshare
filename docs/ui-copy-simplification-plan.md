# 全系统文案精简计划与验收标准

## 扫描范围与结论

本轮扫描覆盖 369 个 UI 源文件，包括：

- 101 个 Jinja/HTML 模板；
- 107 个非压缩传统 JavaScript 文件；
- 66 个 React/TypeScript/JavaScript 前端源文件；
- 页面路由和教师管理导航的文案来源。

自动审计得到 273 个需要人工判断的候选项：P1 18 项、P2 142 项、P3 113 项。完整逐行清单见 `docs/ui-copy-audit-candidates.md`；自动清单不是删除指令，必须按“简化、移入浮窗、保留关键提示”三类处理。

此外确认了 413 个标题节点、223 个原生 `title` 属性、60 个教师管理顶栏动作和 38 个教师管理导航功能。系统的主要问题不是单个长句，而是同一语义同时出现在页标题、英文眉题、副标题、卡片说明、按钮小字和原生 tooltip 中。

## 表单、模态框与状态文案

### 移入说明浮窗

- AI 生成/导入的能力范围、模型类型、预计过程和“完成后自动出现”。
- 公开范围继承机制、Git 命令说明、Markdown 能力列表。
- 多个“例如：……”组成的长占位符。
- 搜索会匹配哪些字段、排序方式、筛选范围。
- 指标、统计口径、数据来源、自动绑定和缓存策略。

### 必须持续可见

- 当前同步/保存/生成状态和明确失败原因。
- 文件格式、文件大小、截止时间、总分必须为 100 等提交硬约束。
- 成绩调整公式、出勤不被修改、公开范围变更、删除/覆盖等高风险说明。
- 权限不足、账号未配置、缺少前置材料等阻断信息。
- 用户输入后的校验错误及修复动作。

### 统一短文案格式

- 加载：`正在加载…`，不要同时描述内部实现步骤。
- 空状态：`暂无 ××`；有明确动作时只附一个按钮。
- 失败：`××失败` + 可执行原因，不使用宣传或安慰句。
- 后台任务：`后台处理中`；完成/失败通过状态更新和消息中心通知。
- 占位符：一个短例子，不超过 20 个汉字；复杂示例进入说明。

## 最终验收标准

### 文案

- 每个页面只有一个主标题；同一语义不在顶栏、Hero 和卡片标题重复出现。
- 主标题建议不超过 14 个汉字；分区标题不超过 10 个汉字。
- 常驻副标题最多一个短分句，建议不超过 28 个汉字；超出部分迁入说明浮窗。
- 顶栏操作常态只显示动作名；不再批量显示“内容资产、过程材料、真实数据”等分类小字。
- 英文眉题仅在确有产品分类意义时保留，不作为中文标题装饰性翻译。
- 空状态最多“一条状态 + 一个主操作”；不重复解释页面用途。
- P1/P2 候选全部标记为“简化、迁入说明、保留关键”之一，无未判断项。

### 说明浮窗

- 桌面悬停 2 秒打开；移动端长按打开；键盘聚焦可访问；`Escape`、关闭按钮和外部点击可关闭。
- 自动选择方向，任何常见分辨率下不越出视口，边距不少于 12px。
- 玻璃背景约 80% 不透明度，文字对比度清晰，不遮挡主任务超过必要范围。
- 最多 4 个快速链接；外链安全打开；PNG/JPG/WebP/GIF 有替代文字并只在首次打开时加载。
- 普通点击、滚动、拖动、链接导航不被长按识别误伤。
- 深色主题、减少动态效果、200% 缩放和窄屏均可用。

### 性能与架构

- 全页只存在一个懒创建浮窗 DOM；不为每个模块绑定监听器，不使用轮询和 DOM 观察器。
- 说明组件新增 JS+CSS 的 gzip 总量目标不超过 8KB；无说明媒体时不产生额外网络请求。
- 动态模块通过 `attach/register` 接口接入，不复制定位、定时器或浮窗样式。
- 教师导航使用 `help_text` 作为独立说明契约，避免再把搜索词、AI 提示和用户说明混为一体。

### 回归

- 桌面至少验证 1440×900、移动端至少验证 390×844，并覆盖边缘触发器、滚动容器和模态框。
- 验证鼠标、键盘、触摸长按、快速跳转链接、GIF 懒加载和 `prefers-reduced-motion`。
- 页面无控制台错误；路由、权限、提交、同步、生成、导出行为保持不变。
- 通过模板渲染、JavaScript 语法、CSS 构建、文案审计器和相关业务回归测试。
